## 2. 三条改变产品设计的结论

1. **"万能"必须分层且诚实**：R9 证明没有任何手段能保证未知程序可读；对外只能承诺"可访问文本能读、标准控件能读、OCR 尽力不完整、读不到会明确说"。
2. **RE 自动化是主地基，引擎适配器是快车道**（用户定调）：R14 的指纹库 + R13 的钩子栈 + R11 的保护检测 + R10 的 Ghidra 报告，构成"认引擎→选路线→出证据→跑验证"的闭环；R17 是闭环第一枪。
3. **合规与体验门槛是硬需求**：结构优先分发 + 首启告知 + 默认离线；启动必须播报语音后端状态（否则 P0）；日文 OCR/语音 v1 不承诺。

## 3. 对实现的直接影响（已写进 docs/11、docs/07）

- 启动播报后端状态与失败原因；可选按键提示音。
- 分析前门：加壳检测；只自动 UPX；先读归档再碰 exe。
- 生成器产物：只含代码/配置；不内嵌游戏文本；样例 ≤3 条 ≤50 字。
- 引擎识别层直接消费 R14 的 engine-fingerprints.json（W2-F 实现中）。
- Ren'Py 适配器按 W2-G 原型落 C#（W2-G2 实现中）。
