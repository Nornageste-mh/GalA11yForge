# 发布说明 v0.2.4.0

> 状态：**已发布**（2026-11-15 02:56）。发布目录 `releases/v0.2.4/`，校验和见 §3。

## 1. 一句话

0.2.4 是一个“**开箱即用 + 探索性内容**”版本：发布包自带 BepInEx 离线包（不用再自己找）、修好使用指南、补上 GUI 人工验收清单与打回演练，并把实验性能力（外部读屏器、KiriKiri 代理研究）和主产品明确分开。

版本纪律：继续 `0.2.x`，不设 1.0（用户 2026-11-14 邮件指示）。

## 2. 本版改动

### 2.1 开箱即用：BepInEx 离线包随发布包分发

- `tools/bepinex/` 放入官方原样 `BepInEx_win_x64_5.4.23.5.zip`（SHA256 `82F9878551030F54657792C0740D9D51A09500EEAE1FBA21106B0C441E6732C4`），附 LGPL-2.1 许可证全文与第三方声明（BepInEx / Harmony / Doorstop）。
- `BepInExLocator` 支持多搜索根：工作区缓存 + `forge.exe` 同目录的 `bepinex\`（单文件发布时用 `Environment.ProcessPath` 定位真实 exe 目录）；找不到时给明确指引，仍可用 `--bepinex` 指定。
- 构建暂存失败时不再硬着头皮编译：若游戏目录里也没有 BepInEx core，`forge build` 直接报 `E_DEPENDENCY_MISSING` 并给处理办法，不会吐一堆 `CS0246` 让用户误判。
- `tools/release.ps1` 发布时把离线包复制到 `app/bepinex/`，并写进 `SHA256SUMS.txt`。
- 真机冒烟：发布版 forge.exe 旁放 `bepinex/` 后，`forge build` 不传 `--bepinex` 成功（产物 Build.A11y.dll 45,568B，17.07s）。

### 2.2 使用指南重建

- `docs/18-使用指南-v0.md` 之前被误写成 0 字节，本版重写：两种用法（GUI/CLI）、每条命令读写什么、声音链路、安装/回滚、能力范围表、已知限制、FAQ、合规边界。GUI 人工验收清单见 `docs/32-GUI人工验收清单.md`。

### 2.3 实验性附加工具：外部读屏器（extras）

- `releases/extras/external-reader-0.1.0/`：自包含 `Forge.ExternalReader.exe`（162,876,605B，SHA256 `F334822235D25B92287066AC701147376EDCC8D5C90C65CCF0A2DCA626B33789`）+ 5 个 WPF 原生库 + README + SHA256SUMS。
- 明确边界：只保证标准控件/可访问文本；自绘窗口（如 LoveNest）读不到；OCR 仅实验（美术字体 CER 41.8%）；轮询 391–1439ms/轮；只 Windows x64；未做听感验收。

### 2.4 测试与文档

- 全解决方案测试：**612 通过 0 失败 0 跳过**（Core 80、Verify 64、Detection 30、Generators 55、Ren'Py 34、UnityMono 31、Build 77、Gui 138、Il2Cpp 48、Ghidra 55）。
- 新增 5 个 BepInEx 定位器测试；`docs/31-打回预案演练-v0.md`（12 类场景，8 类实测可扛/3 类部分/1 类范围外）；`docs/33-0.2.4-计划.md` 更新。
### 2.5 KiriKiri（旧版 KKZ）实验性代理：只发设计，不发成品

- R26 已完成：在《千恋＊万花》副本上用"插件 DLL 代理"拿到 **8 行真实日语台词**、外部 SAPI 合成 WAV、回滚后 plugin 59 文件 + 根 33 文件逐哈希复原。
- R28 交付 `docs/35-KKZ适配器设计-v0.md` 与参数化代理模板（状态机/去重/落盘/朗读均在原生侧，不向 TJS 注入对象——这是 R26 崩溃的根因）；安装/卸载脚本在沙箱假目录全流程通过。
- **本版不随包发行可执行代理，也不进主 CLI**：理由是"沙箱通过 ≠ 真实机器能装"——真实游戏目录一次没跑过（任务约束禁止），且 Steam 文件校验/游戏更新会让代理随时失效。等一台真实机器跑通"安装→取到台词→回滚→哈希复原"后再作为 extras 放出。
- 已确认的结论：旧版 1.2.0.3 不自动加载 `plugin/*.tpm`（R23 阳性对照证明 1.4.0.8 可以）；中文译文源仍缺（`.disp`/`.text` 为空，只有日文 `plaintext`）。
- R28 定稿：代理模板可复现构建（x86 三导出；link `/Brepro` 两次构建哈希一致，dist SHA256 `31C2661BB0112E35EEBBEE090CBD0213E1502942FE4904FF99CC828E91208225`）；沙箱安装/卸载全过。仍不随包发可执行资产（真实游戏目录零验证），源码作为开发者预览留在仓库 `src/experiments/kkz-adapter`。

## 4. 已验证 / 未验证

**已验证（本版或前版真机）**
- Unity Mono：生成→构建→安装→6 钩子挂载→`[Speech]` 真机朗读→回滚干净（《五天一夜》）。
- IL2CPP：安装 232 操作→19 行 `RevealableUIText::set_Text`→回滚 228 还原/4 删除→哈希不变（硅心）。
- Ren'Py：覆盖层安装→`a11y_speech.log` 文本→回滚后 1260/1260 哈希一致（DDLC）。
- GUI：UIA 树 44 元素无空名、Tab 21 停点、Alt 快捷键、loopback 录到 NVDA 输出（部分验证）。
- BepInEx 随包：`forge build` 免 `--bepinex` 冒烟通过。

**未验证（如实列出）**
- 人耳逐句验收（GUI/游戏朗读）；2 款以上 Unity Mono 的稳定复现（NEEDY 是失败样本，已如实记录）。
- KiriKiri 实验能力在真实商业游戏里的可用性（R26 只在《千恋》副本完成最小闭环；中文译文源未定位）。
- x86 老游戏、日文 TTS、非简体中文分支。
- 外部读屏器的人耳验收与 NVDA/争渡端到端。

## 5. 升级与兼容

- 从 0.2.3.0 升级：直接替换目录即可；工作区（`%LOCALAPPDATA%\GalA11yForge`）与账本兼容，无需迁移。
- 回滚旧安装：用本版 `verify --rollback` 读旧账本仍可用（schemaVersion=1 不变）。
- 发布包不再要求用户自备 BepInEx；已有自定义包时用 `--bepinex` 覆盖。

## 6. 合规边界

- 结构优先分发：只发工具与生成器，不直接分发针对具体游戏的成品补丁。
- 随包仅 MIT/Apache/BSD/未改 LGPL 组件；GPL/闭源工具（Textractor、LunaTranslator、eSpeak NG、争渡 DLL 等）不随包。
- 不修改 exe、不绕过 DRM、不对在线/反作弊游戏注入；不包含游戏资源/台词/图片/音频。
