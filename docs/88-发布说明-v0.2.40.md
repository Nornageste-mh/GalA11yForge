# GalA11y Forge 0.2.40.0 发布说明

- 发布：2026-11-16
- 版本：0.2.40.0
- 测试：全量 692 通过 / 0 失败 / 0 跳过
- 发布目录：`releases/v0.2.40/`

## 1. 这一版解决什么问题

0.2.39 把“高级分析超时后该调到多少”算出来了，但那只在**跑完之后**。读屏用户点「分析文本」
之前仍然不知道这枚 exe 会跑多久，只能干等。0.2.40 把同一套粗估提前到界面就绪提示里：
勾选「高级分析」、填了「分析程序」（且文件存在）时，按钮下方那行会先说「大约需要多久」。

## 2. 改动

### 2.1 GUI 就绪提示带耗时粗估

- `src/Forge.Gui.Core/AnalysisDurationHint.cs`（新增）：30 秒启动 + 约 85 秒/MB，夹 30–3600 秒；
  `EstimateRoundedSeconds`、`Describe`（≥600 秒读成“约 N 分钟”）。
  注释里写明：公式与 `src/Forge.Analyzers.Ghidra/GhidraDurationEstimator.cs` 保持一致，
  GUI 核心库刻意不引用 Forge.Core，所以保留一份最小实现，两边都有同组样例的单测。
- `src/Forge.Gui.Core/GuiStateMachine.cs`：
  - `GuiInputs` 新增 `long? GhidraExecutableSizeBytes`（可空，仅用于提示）；
  - `GuiInputs.Create(...)` 末尾新增可选参数 `long? ghidraExecutableSizeBytes = null`；
  - `HintText` 在「将分析你指定的程序：X.exe。」之后追加
    `按文件大小粗估，分析这个程序大约需要约 N 秒/分钟。`（只有大小 > 0 时才加）。
- `src/Forge.Gui/MainForm.Commands.cs`：
  - `SnapshotInputs()` 传入 `_advancedCheck.Checked ? TryGetFileSize(_ghidraExeBox.Text) : null`；
  - 新增 `private static long? TryGetFileSize(string? path)`（文件不存在/读不到返回 null，不抛异常）。

## 3. 测试

全量 692 通过（Core 98、Verify 69、Detection 30、Generators 59、Ren'Py 37、
UnityMono 31、Build 80、Gui 161、Il2Cpp 55、Ghidra 72）。

新增/修改：

- `tests/Forge.Gui.Tests/AnalysisDurationHintTests.cs`（4 条）：
  - 4,583,168B → 402 秒（与 Ghidra 侧同一样例）；
  - 8MB → 710 秒 → “约 11 分钟”；
  - 100MB → 夹到 3600 秒 → “约 60 分钟”；
  - 未知大小 → “无法粗估（不知道可执行文件大小）”。
- `tests/Forge.Gui.Tests/ButtonStateTests.cs`：
  - `HintText_EstimatesRoughDuration_WhenExecutableSizeKnown`（断言程序名 + 「按文件大小粗估」+「约 402 秒」）；
  - `HintText_OmitsEstimate_WhenSizeUnknown`（没大小就不出现这句话）。
