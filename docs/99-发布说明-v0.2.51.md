# 0.2.51 发布说明：Unity 游戏加一层「文本兜底轮询」

## 1. 一句话

当静态分析选出来的钩子没命中真正的正文时，生成的插件现在会自己**定时扫一遍屏幕上可见的 UGUI / TMP 文本**，只把新出现或变化的文本交给朗读；默认开，可在 BepInEx 配置里关掉。

## 2. 为什么做

- 用户反馈《Mystery Lover 2》装完「没有剧情朗读」，查下来是插件只钩到系统对话框，正文入口没进去（0.2.48 已修该类识别）；
- 但未知 Unity 游戏总有「钩子选不准」的情况，读屏用户不该因此一句都听不到；
- 兜底轮询只读文本、不改游戏，失败也只写日志，不影响游戏运行。

## 3. 改了什么

| 文件 | 改动 |
|---|---|
| `src/Forge.Generators/Templates/SpeechGateTemplate.cs` | 新增 `ConfigureWatcher` / `TickWatcher` / `ScanWatchType`：按间隔（默认 0.3 秒，0.1–2 可调）用 `Resources.FindObjectsOfTypeAll` 扫 `UnityEngine.UI.Text` 与 `TMPro.TMP_Text`，只对可见组件、非空文本、`InstanceID` 变化过的文本朗读；日志前缀 `[Speech:watch]` |
| `src/Forge.Generators/Templates/PluginTemplate.cs` | 启动时调用 `SpeechGate.ConfigureWatcher(Config)`（新占位 `{{WATCHER_INIT}}`） |
| `src/Forge.Generators/UnityMonoGenerator.cs` | `GATE_UPDATE` 里追加 `SpeechGate.TickWatcher();`，并生成 `WATCHER_INIT` |
| `tests/Forge.Generators.Tests/FieldWiringTests.cs` | 断言生成物含 `ConfigureWatcher`、`TickWatcher`、`FindObjectsOfTypeAll`、`[Speech:watch]`、`文本兜底轮询` |

## 4. 配置项（游戏里 `BepInEx/config/*.cfg`）

```ini
[朗读]
文本兜底轮询 = true      ; 关掉就完全走钩子，不扫屏
兜底轮询间隔秒 = 0.3     ; 0.1–2，越小越及时越费电
```

## 7. 已验证 / 未验证

**已验证**：生成物含兜底轮询代码；真实 Unity 程序集下编译通过；全量测试 712 绿。

**未验证（诚实边界）**：
- **没有在真实游戏里跑过运行期**——`[Speech:watch]` 是否真的读到台词、会不会重复读界面文字，需要装到游戏里看日志；
- 兜底轮询会读到菜单/按钮等界面文本（可能有点吵），目前只做了「同一段文本不重复读」，没有做 UI 元素过滤；
- 与旧钩子并存时可能同一句被读两次（钩子先读、轮询再读同一个文本组件）——按需在配置里关掉兜底。

## 8. 升级

直接换用 `releases/v0.2.51` 的 `forge.exe` 与 GUI；已装旧插件的游戏请先 `forge verify --rollback` 再重装，才会用上新模板。
