# 0.2.5 事故通报与恢复记录（SenrenBanka / KKZ 适配器）

日期：2026-11-15
涉及：task-51（KKZ 适配器 v1 真机闭环，实验性子代理）
状态：已恢复（90/93 逐文件一致；2 个 `.sig` 缺失、`data.xp3` 被 Steam 回退为原版，游戏可正常启动）

## 1. 一句话

测试 KKZ 代理适配器的自动卸载脚本有 bug，误删了《千恋＊万花》（Steam appid 1144400）的 `plugin\` 全部 59 个文件和根目录 18 个小文件；已用 Steam 内容校验 + 本地工作区备份恢复到与原快照 90/93 一致，游戏本人验证可正常启动。

## 2. 经过

- 04:0x，task-51 子代理在**真实游戏目录**安装实验性 KKZ 代理（`plugin\getSample.dll`）做真机闭环。
- 04:07，子代理失败退出；检查发现其 `uninstall.ps1` 已执行回滚，但回滚逻辑把“安装前快照里没有的文件”当成“本次安装产生的多余文件”批量删除。
- 根因（已定位到行）：
  - `install.ps1:219` 写快照表头 `scope,relpath,bytes,sha256,mtime_utc`，但行值写的是相对路径（列名与值语义不一致）；
  - `uninstall.ps1:132` 旧代码读 `$r.rel` → 该属性不存在（实际是 `relpath`）→ 所有快照键退化成 `plugin|`（rel 为空）；
  - 随后“快照外文件”判定把所有文件都判成多余 → 删除；`.xp3` 和 >5MB 文件因两条保护规则幸存。

## 3. 损害范围

- 被删除：`SenrenBanka\plugin\` 59 个文件（含 `a11y.dll`、`menu.dll`、`*.sig`、`nvdaControllerClient.dll` 等）；游戏根目录 18 个小文件（含 `SenrenBanka.exe`、`steam_api.dll`、`*.sig` 等）。
- 未被删除：全部 `.xp3`（10GB 级）与大文件。
- 后续：Steam 内容校验把 `data.xp3` 回退为原版（1,007,286,279B），此前注入的 a11y 补丁内容（约 1,033,432,485B 版本）丢失；`data.xp3.back` 现与 `data.xp3` 同为原版。

## 4. 恢复过程

1. `steam://validate/1144400` 触发 Steam 内容校验；校验后 `appmanifest_1144400.acf` StateFlags=4、BytesToDownload=0。
2. 从本地工作区恢复 mod 文件（均与快照哈希一致）：
   - `plugin\a11y.dll` 219,136B SHA256 `30A259AB2D877985996CC521513322767061A7BA1A7B014E4DE568545BF0F70C`
   - `plugin\a11y_labels*.ini`（4 个）、`plugin\a11y_speech.ini`
   - `plugin\nvdaControllerClient.dll` 215,192B SHA256 `96295979A25AB1C8DDC9B6AAFFDD81ED72C9504880850D49E99F1DB96055A7D0`
   - 来源：`D:\DSHWorkSpace\SenrenBanka-For-Accessibility\`、其 `release_stage\0.2.0.1` installer 内容、以及本机同名 mod 目录的缓存副本。
3. 用 `research/45-kkz-adapter-e2e/evidence/snapshot-before.csv`（94 条：plugin 59 + root 35，含逐文件 SHA256/大小）逐条比对：
   - `OK=90`、`MISSING=2`（`adult.xp3.sig`、`adult2.xp3.sig`，各 212B）、`MISMATCH=1`（`data.xp3` = 原版）。
4. 启动验证：`steam://rungameid/1144400` → 进程 SenrenBanka（PID 34720）、窗口「千戀＊萬花」、Responding=True；窗口截图 `_kkz-recovery\senren-after-restore.png`。

## 5. 缺失项与影响

- `adult.xp3.sig` / `adult2.xp3.sig`：全盘无副本；Steam 校验不恢复；游戏启动不依赖它们（已验证可启动到主菜单）。暂记为已知差异，后续如需可重装/再验证 DLC，或等游戏首次运行时生成（未确认）。
- `data.xp3`：已是原版（补丁注入被 Steam 校验移除）。如用户需要继续用 a11y 补丁，可用 0.2.4 工具链重新生成安装；0.2.0.1 的发布物仍完整保存在工作区（installer SHA256 `C33B97…`）。

## 6. 修复（已完成并测过）

1. `src/experiments/kkz-adapter/uninstall.ps1`
   - 快照解析与校验提前到**所有动作之前**：解析失败/行 rel 为空 → 直接退出码 23，不杀进程、不还原、不删任何文件（fail fast）。
   - 兼容两种表头：`relpath` 与 `rel` 都读。
   - 默认**不删除**任何“快照外文件”；必须显式 `-RemoveExtras` 才删除。
   - 额外白名单：只删 `.dll/.ini/.log/.txt/.json/.tmp` 且 <5MB；`.sig/.exe/.xp3/.cf` 永不删。
   - 日志新增 `snapshot_rows_loaded`、`extras_kept`、`remove_extras`。
2. `src/experiments/kkz-adapter/install.ps1`：快照表头统一为 `scope,rel,...`。
3. 新增回归测试 `src/experiments/kkz-adapter/tests/uninstall-sandbox.ps1`（只碰 `%TEMP%` 沙箱）：
   - T1 默认：退出码 22（有差异→安全失败），所有快照外文件保留；
   - T2 `-RemoveExtras`：只删白名单，`.sig/.exe/.xp3` 保留；
   - T3 快照损坏：退出码 23，一个动作都不做。
   - 实测输出：`SANDBOX=PASS`。

## 7. 纪律（写进流程）

- 任何“自动清理/自动删除”脚本：先验证快照/账本解析成功，再做动作；默认不删未知文件；危险动作必须显式开关。
- 真实游戏目录操作前：先沙箱演练 + 逐文件快照 + 备份；脚本要能在失败前停手。
- KKZ 适配器在真实机闭环（安装→取台词→回滚→哈希复原）通过前，**不进发布包、不随包**，只发设计文档。
