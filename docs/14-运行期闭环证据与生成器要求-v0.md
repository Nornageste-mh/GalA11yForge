# 14 运行期闭环证据与生成器要求（v0）

- 日期：2026-11-14
- 依据：`research/19-re-runtime-confirm/REPORT.md`（R17，309 行，单游戏实机闭环）＋ `research/20-il2cpp-re/REPORT.md`（R18）
- 用途：把实机证据固化成 W2-B（分析器）/W2-C（生成器）/W2-D（构建部署）/W2-E（自检）的验收要求。**不是覆盖率结论**：单游戏、单次运行、40 条台词、3 个选项、5 条消息框。

## 1. 一句话结论

《五天一夜》（Unity Mono）上，「静态候选 → 自动生成 Harmony Hook → 实机命中 → 卸载还原」闭环成立（5/5 Hook 命中，40 句台词，还原 211 文件逐哈希一致）。瓶颈不在 Harmony，而在**候选发现规则**与**运行期输入自动化**。

## 2. 实机事实（生成器设计的硬约束）

### 2.1 主通道不是 set_text

- 真正整句在 `UIText::AnimateText(string text, ..., int Num, TextMeshProUGUI targetText, ...)` 的 `text` 参数里；40/40 条非空。
- `UIText::DOText` 是每句入口，持有 `Ja/En/Sc/Tc` 四种语言的长度与 hash、说话人、`Voice`。
- `TMP_Text::set_text` 运行期被调 1,273 次（102 空串、1,171 非空、79 次整句回填），但它没有通道/说话人/配音/Num，且同句重复 1–2 次——只适合做计数旁证，不能当主 Hook。
- 教训：静态只按 `set_text` 调用者排序会漏主通道。分析器必须加 sink：`DG.Tweening.ShortcutExtensionsTMPText::DOText` 等打字机 API，以及「参数含 string + 方法体调用打字机 sink + 类型持有 TMP 字段」的方法（建议新增 S9 规则，+20 分）。

### 2.2 语言层：hash 用错语言 = 0% 配对

- 实测顺序：`DOText`（日文原稿 `speak`）→ `HandleMessageText`（日文 hash）→ `AnimateText`（本地化简中）。
- C1↔C2 用 **sc（简中）hash** 40/40 配对；C4↔C2 用 ja hash 5/5。不能默认 `speak` 就是当前语言。
- 生成器必须把 `language=sc|tc|ja|en` 做成显式配置，并写入报告；本作 `lang=1` 对应简中（枚举定义未确认）。

### 2.3 去重与事件模型

- 主键 `(num, hash)`，短窗 2 秒；C1 自身 40/40 唯一，短窗足够。
- 选项会二次进入台词管线：3 个选项资产中 2 个选中项以 `AnimateText num=0` 回显，延迟 67.7 秒与 416.2 秒——**不能用短时间窗去重**。建议事件类型：`dialogue` / `choice` / `choice_echo` / `message` / `heartbeat` / `quit`；`choice_echo` 默认不朗读。
- 同一日文原稿可能对应不同简中文本（ja hash 相同、sc hash 不同），按 ja 去重会误合并。

### 2.4 安装/回滚四件套（W2-D 直接复用）

- 安装前 `before-tree.json` + `manifest.json`；运行后 `after-run-tree.json`；卸载后 `after-restore-tree.json` + `restore-verification.json`（逐文件哈希）。
- 实测：安装 22 文件/3 目录/1.8MB；运行期 BepInEx 又生成 6 文件/4 目录（cache/config/日志/插件数据）。卸载只允许删「安装清单 + BepInEx 白名单」，未知新增文件必须失败并保留现场。
- 还原结果：211 文件/21 目录/587,992,325 B，`missing=0 changed=0 sizeChanged=0 extra=0`，`ok=true`。

### 2.5 Harmony 模板细节

- Prefix 参数名/类型/顺序必须与原方法一致；嵌套 struct 要按值声明（如 `UIText.CharaStatus`），用 `object`/`ValueType` 会静默不命中。
- 需要实例用 `__instance`；取栈只取 3 帧，并过滤 Harmony 的 `DMD<...>` 包装帧。
- 每个 Hook 独立 try/catch，异常只写一次日志，不能影响游戏主循环。
- 日志最低字段：`ts,event,method,hash,len,num,target,name_len/hash,voice,lang,sample?`；正文默认前 12 条、每条 ≤60 字，其余只落 hash/长度。

## 3. 输入自动化：不要为了全自动牺牲可解释性

- 本作 Space 完全不能推进，单击有效；首次点击被吞；选项必须双击/三击且对坐标极敏感。
- 结论：v0.1 运行期确认默认 `run.mode=manual`（启动→人工点 Start/推进/选项→插件记录→退出），可选 `auto_click` 仅做固定坐标盲点，选项一律留人工。
- 运行前应清场（其它游戏/BepInEx console 会抢焦点）；窗口置顶可用 `SetWindowPos(HWND_TOPMOST)` + `SetForegroundWindow`，仅用于采样规避。

## 4. 对 v0.1 产品的要求（可验收）

1. 分析器（W2-B 扩展）：能对《五天一夜》输出 `UIText::AnimateText`、`UIText::DOText`、`UIText::Choice`、`UIText::HandleMessageText` 四个候选（含精确签名、IL 偏移、字段类型），并解释每条打分。
2. 生成器（W2-C）：输入候选 JSON + `language` 配置，产出一个可编译的 netstandard2.1 BepInEx5 插件工程，包含对应 Prefix、事件日志、正文采样策略、去重/回显标记。
3. 构建部署（W2-D）：安装前快照/清单、白名单卸载、哈希验证；卸载失败要保留现场。
4. 自检（W2-E）：安装后/回滚后账本与磁盘一致；`pass_with_skips` 不算通过（已实现）。
5. 报告：结论先行，含命中/唯一/配对率/重复/还原 ok/未验证项；正文引用 ≤3 条、每条 ≤50 字；不得把 40 条当覆盖率。

## 5. 待办与风险

- W2-B 需补 sink 与 S9 规则并重跑回归（用 `research/19-re-runtime-confirm/evidence/candidates.json` 做样本）。
- 第二个 Mono 游戏复验（GalMaster/NEEDY）确认「DOTween sink + 四语言 hash + 选项回显」是否通例。
- 未做无插件 A/B，不能量化 Hook 开销；FPS 均值 21.2（软件渲染），最低 4.6。
- `lang=1` 对应简中为实测现象，枚举定义未确认。
- 未走 Steam 启动，SteamAPI_Init 失败属环境噪声，报告需区分「游戏自身错误」与「Hook 异常」。
- IL2CPP 侧见 R18：以 token/类型级为主，方法级 Hook 需 Il2CppDumper/interop 进一步验证（未进 v0.1 主链）。
