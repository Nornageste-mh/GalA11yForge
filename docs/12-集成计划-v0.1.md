## 2. 接线顺序（Lead 执行，避免与子代理写盘冲突）

1. **sln 集成**：把 Forge.Detection/Generators/Build/Verify 与各自测试项目加入 `src/GalA11yForge.sln`（子代理被要求不碰 sln，这步必须 Lead 做）。
2. **CLI 真调用**：
   - `forge detect`：先 `EngineDetector`（Forge.Detection）出 detect.json；有适配器时再走适配器覆盖。
   - `forge analyze`：Unity Mono → 把 `src/experiments/unity-mono-analyzer` 迁为 `src/Forge.Analyzers.UnityMono`（或临时 ProjectReference），输出 docs/09 约定的 analysis.json。
   - `forge plan`：由分析结果生成 PatchPlan（route/automatic 或 automatic_with_confirmation；候选不足→semi_automatic+manualTodo）。
   - `forge generate`：Forge.Generators 输出插件工程到 `work/<id>/generated/`。
   - `forge build`：Forge.Build 调 dotnet build（离线引用本地 DLL，避免 restore 联网失败）。
   - `forge install`：Forge.Build 部署到游戏目录（先备份+manifest，写 BepInEx 骨架）。
   - `forge verify`：Forge.Verify 离线检查 + 语音后端探测；运行期验证（启动游戏抓日志）单独一步。
   - `forge report`：合成 report.md（固定 7 节）+ human-todos.md。
3. **E2E 脚本**：`tools/e2e-v01.ps1`（Lead 写）串起全链，把每步退出码/产物路径/耗时记到 `reports/e2e-v01.log`；失败即停并保留现场。
4. **回滚验证**：install 后立刻 rollback，对比关键文件 sha256；再 install 一次留给人工验证。

## 5. 风险与预案

1. **静态候选不足**（五天一夜只有 1 个 A）：R17 运行时确认后按实测补 hook 规则；仍不行则 v0.1 降级为 semi_automatic（生成骨架 + 人工指定 hook 点），并在报告里如实写。
2. **BepInEx 安装污染游戏目录**：全部走备份+manifest；先 install→rollback 验证再留给用户。
3. **dotnet build 联网**：用本地 BepInEx DLL 引用 + `--no-restore` 场景；生成工程带 offline 引用路径。
4. **子代理产出接口不一致**：集成时以 docs/06 为准，必要时 Lead 写适配层；不允许改 Core 契约去迁就零件。
5. **Unity 版本识别失败**：不影响 patch，但报告必须写"未识别"并在 verify 里降置信度。
