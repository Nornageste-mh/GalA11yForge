# 真机复核操作手册 v0（Ren'Py 确认框 / 选项题目 / GUI 读屏）

> 用途：把“需要占用户电脑窗口”的验证压缩成 10 分钟以内的固定流程，避免每次重新摸索。
> 前提：用户明确说“电脑空闲”；任何一步发现前台不是游戏窗口，立即停止，不要盲点。

## A. 通用注意（血泪教训）

1. 截图必须用 `CopyFromScreen` 抓**游戏窗口区域**；先确认前台窗口标题是游戏，不是 DSH/Steam。
2. 合成点击分两类：
   - 老 Input（DDLC/Ren'Py、GalMaster）：`SetCursorPos + mouse_event` 可用；
   - 新 Input（manosaba Unity6）：必须同一 pwsh 进程内先 `SetForegroundWindow` 再点，且坐标要准（New Game y=905 而不是 985）。
3. `PostMessage` 键盘/鼠标对多数游戏无效，仅作最后手段。
4. 每次验证后：杀进程 → `forge verify --rollback` → 核对游戏目录文件数/关键哈希 → 删测试副本。

## B. Ren'Py：确认框（退出确认）

1. 复制测试副本（DDLC 约 286MB）：
   ```
   Copy-Item 'D:\Steam\steamapps\common\Doki Doki Literature Club\*' D:\DSHWorkSpace\_renpy-confirm3\game -Recurse
   ```
2. 安装覆盖层：
   ```
   releases\v0.2.24\app\forge.exe install --game D:\DSHWorkSpace\_renpy-confirm3\game --workspace D:\DSHWorkSpace\_renpy-confirm3 --json
   ```
3. 启动（必须重定向输出，否则 pwsh 挂起）：
   ```
   Start-Process -FilePath D:\DSHWorkSpace\_renpy-confirm3\game\DDLC.exe -WorkingDirectory D:\DSHWorkSpace\_renpy-confirm3\game -RedirectStandardOutput out.txt -RedirectStandardError err.txt
   ```
4. 窗口恢复：`_galmaster-e2e\tools\topmost.ps1 -TargetPid <DDLC pid> -On`（hwnd/rect 会打印）。
5. 点击顺序（client 坐标 → 屏幕坐标 = client + 窗口 client 原点；DDLC 常见原点约 (315,175)）；
   **注意：DDLC 主菜单 Quit 实测是直接退出、没有确认屏**；确认框要从游戏内「标题」触发，见 F 节。
   - 存档提示：选 **2 No, continue where I left off.**（不要选 1，会删用户存档）；
   - 主菜单：`Quit` client ≈ (163,615)，点两次（第一击聚焦、第二击激活）；
   - 出现 `Are you sure you want to quit?` 即成功触发。
6. 判据：游戏目录下 `a11y_speech.log` 出现
   ```
   [A11y屏幕] … 确认：Are you sure you want to quit?…
   ```
   且无零宽字符/重复句。
7. 收尾：杀进程 → `releases\v0.2.24\app\forge.exe verify --game … --workspace … --rollback --json` → 删副本。

## C. Ren'Py：选项上方题目

- DDLC 的选项屏大多没有题目文本；要验证 `_a11y_choice_prompt()`，用自带样本或自造一个带 `screen choice` 上方文本的最小 Ren'Py 工程。
- 判据：`a11y_speech.log` 出现 `提示：<题目>。选项 N 个：…`；无题目时退回旧格式。
- 若来不及造样本：如实写“仅单测覆盖，真机未取证”。

## D. GUI 读屏（NVDA 人工）

1. 启动 `releases\v0.2.24\gui\Forge.Gui.exe`，NVDA 保持开启，打开 NVDA 语音查看器。
2. 依次 Tab 一遍：输入区 4 行 → 浏览按钮 → 11 个操作按钮 → 结果区；记录每个控件是否播报名称。
3. 点“一键安装”（可用测试目录 dry-run）→ 听忙碌态/结果播报 → 点“停止”。
4. 判据：全部控件有名且不念“按钮”空名；结果区文本可读；失败时有“建议/详情”朗读。
5. 记录：`research/58-gui-nvda-verify/` 下放截图 + 观察记录。


## F. 已实测成功路径（2026-11-15 22:04，《永恒与星辰与日常》，Ren'Py 8.6）

1. 游戏目录 `D:\Steam\steamapps\common\永恒与星辰与日常`，复制到 `_renpy-confirm7\game`；
   把游戏自带的旧补丁目录 `game/a11y_game`、`game/a11y_platform` 移出（否则 0.2.24 闸门会拒绝安装，这是对的）。

5. 点击路径（client 坐标）：点「开始游戏」START `(1167,86)` → 进入对白 → 点 quick menu「SYSTEM」`(1207,702)`
   → 点右下「标题 TITLE」`(930,660)` → 弹出确认框。

   截图应同时看到中文确认框（「您确定要返回到标题界面吗？」+ 确认/取消）。
7. 收尾：杀进程 → `releases\v0.2.24\app\forge.exe verify --game … --workspace … --rollback --json`
   → overall=pass_with_skips（还原 0/删除 9/清理 1/哈希不一致 0）→ 删副本。

## E. 判定与文档

- 真机通过 → 更新 `docs/50`（IL2CPP/字段）或 `docs/18`（使用指南）对应条目，写清“已验证/未验证”。
- 未通过 → 记 `[A11y屏幕]` 缺失、屏幕名不对、异常栈，作为下一版修复输入；不要写成“已支持”。

## G. 播报语言：必须取翻译后文本（0.2.26 真机教训）

- 症状：界面显示中文，日志却是英文原文。
- 根因：`_a11y_displayable_text` 用了 `_tts_all(raw=True)`（= `text_parameter`，翻译前 source text）。
- 正确做法：`_tts_all(raw=False)`（= `self.text`，与屏幕显示一致）；Ren'Py 自己的 TTS 也用 `raw=False`（`renpy/display/tts.py:428`）。
- 兜底：`_a11y_translate_text()` 用 `renpy.translate_string` 再查一次翻译表；注意键可能含 `\n`，查不到就原样播报。
- 证据：`research/67-renpy-i18n-confirm/`（日志 + 截图）。

## H. 确认框按钮播报（0.2.27 实测）

- 现象：确认框用 imagebutton，按钮上没有文字，旧版只播报提示句。
- 现在：屏幕播报「确认：<提示>；有 N 个按钮。按 Tab 切换，回车确认」；焦点到按钮上播报「按钮 （没有可读文字，按 Tab 换一个，回车执行）」。
- 判据：`a11y_speech.log` 里 `[A11y屏幕]` 行包含「有 N 个按钮」，`[A11y焦点]` 行包含「没有可读文字」。
- 证据：`research/68-renpy-confirm-buttons/`。

## J. GUI 未知引擎报告入口（0.2.31 实测）

- 前置：本机 Ghidra（`GALA11Y_GHIDRA_HOME` 或 `D:\ghidra_*`）。
- 步骤：启动 `gui/Forge.Gui.exe` → Alt+1 游戏目录、Alt+2 工作区 → Alt+7 勾「高级分析」→ Alt+A「分析文本」→ 等日志/工作区出现 `analysis.json` → Alt+P「分析报告」。
- 判据：工作区 `reports/<slug>/report.md` 与 `human-todos.md` 出现；`human-todos.md` 含 `[阻断] M-A01 该引擎没有内置适配器`；`report.md` 的覆盖声明含 Ghidra 函数数与候选数。
- 自动化替代：`tools/gui-advanced-e2e.ps1`（WMI 启动 + WM_SETTEXT 填框 + BM_CLICK 点按钮 + 轮询产物；PASS 条件 = Ghidra available 且有 report.md）。
- 实测：开发版 122.2 秒、发布包 101.1 秒；样本 SenrenBanka（KiriKiri）；证据 `research/73-gui-report/`。
- 注意：`TextBox` 的 `WM_SETTEXT` 回读为空是正常现象，判断以产物为准。
