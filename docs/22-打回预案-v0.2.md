# 打回预案 v0.2（GalA11y Forge）

> 目的：用户明确要求「把猜测可能被驳回当成常态来设计」。本文把最可能被拍回的 12 类意见列出来，
> 每类写清：触发场景 → 我们已经提前做的准备 → 如果被打回，1 天内能交的修补 → 成本/代价。
>
> 原则：**能配置的不要写死，能插拔的不要焊死，能诚实标注的不要假装成功。**

---

## 0. 可插拔点总清单（被打回时先看这里）

| 层 | 插拔点 | 文件/机制 | 换掉要多久 |
|---|---|---|---|
| 引擎识别 | 指纹规则 | `src/Forge.Detection/Fingerprints`（7 原语+5 消歧，JSON 内嵌） | 加 1 个引擎 0.5–1 天 |
| 引擎适配 | 适配器 | `BuiltInAdapter` 注册表 + 每引擎独立项目（UnityMono/Il2Cpp/Renpy） | 新适配器 2–5 天 |
| 分析后端 | `IAnalyzerBackend` | Ghidra 后端（task-39）、外部捕获（task-40） | 1–3 天 |
| 生成物 | 模板 | `src/Forge.Generators/Templates/*` + golden 测试 | 改样式 2 小时 |
| 安装 | 部署器策略 | `PluginDeployer`（BepInEx）/ `OverlayDeployer`（Ren'Py 覆盖层） | 新策略 1–2 天 |
| 自检 | 检查项 | `src/Forge.Verify/Internal/*Checks.cs`（可加检查，不影响旧项） | 加检查 2 小时 |
| 语音 | 后端链 | Tolk→NVDA→ZDSR→SAPI→静默；`Speech` 层 | 加后端 0.5–1 天 |
| 界面 | 壳 | CLI（`forge.exe`）+ WinForms GUI（调用 CLI） | 换壳 3–5 天 |
| 读屏兜底 | 外部读屏器 | `src/Forge.ExternalReader`（原型，task-40） | 视矩阵结论 |
| 运行选项 | `--option key=value` | 覆盖 `profile.options`，不落盘 | 立即生效 |

**快速修正流程**：用户/测试反馈 → 判断属于哪层 → 改配置（profile/overrides/--option）能解就当天发；
需要改代码的，走 `改模板/加检查/加适配器` 三条最短路径，不动其它层。

## 1. 「支持的游戏/引擎太少，还是只能玩你们测过的那几个」

- 触发：用户拿一款新 Gal 来试，识别出来但提示"该引擎适配器尚未接线"。
- 已准备：22 款本机游戏 22/22 识别；5 个引擎适配器（Unity Mono / IL2CPP / Ren'Py / 待接 KiriKiri、RM）；
  未知引擎不再"假装成功"，而是给出人工待办 + 外部读屏/OCR/Ghidra 兜底路线（见 9）。
- 打回后 1 天可交：
  1. 用 `forge detect` 的扫描统计 + 用户游戏截图，快速判断引擎族，给出"最接近适配器"建议；
  2. 若是 Ren'Py，已有覆盖层生成，当天可出可用补丁；
  3. 若是 KiriKiri，按 task-41 方案研究结果给 TPM 路线或明确"暂不支持+外部方案"。
- 成本：新引擎适配器 2–5 人日/个；不做假承诺。

## 2. 「日文 Gal 读不了/没日语语音」

- 触发：拿日文原版游戏测试，中文 TTS 读日文变乱码或音不对。
- 已准备：语音后端自动检测；无 ja-JP 语音时**明确提示**"当前会读成中文音，不可懂"；
  NVDA 自带 eSpeak NG 可读日文（GPL，不随包，靠用户环境）；OCR 日文 v1 不承诺。
- 打回后 1 天可交：
  1. 文档+提示引导用户安装日语语音（Windows 设置→语音）；
  2. 可选：接入本地 VOICEVOX（用户自装，HTTP 本地接口）作为"日语语音"选项；
  3. 可选：Tesseract jpn fast（2.36MB，Apache-2.0）作为日文 OCR 可选下载件。
- 成本：1（文档/提示）～3 人日（VOICEVOX）～2 人日（Tesseract）。

## 3. 「安装有风险/被杀软误报/游戏更新后失效」

- 触发：用户装完打不开游戏、杀软报毒、Steam 更新后补丁失效。
- 已准备：逐文件备份 + 哈希校验 + install-manifest + 一键回滚 + 基线核对；
  安装前加载器兼容性预检（mscorlib/Input 裁剪直接拒绝）；默认离线；结构优先分发（不随包成品）；
  发布物带 SHA256SUMS。
- 打回后 1 天可交：
  1. 独立"一键卸载器"（exe，不依赖工作区）；
  2. 安装前自检报告（把 detect+兼容性+备份路径一次性写给用户）；
  3. 游戏更新后的"重生成补丁"引导（profile 版本 pin + 重新 generate/build/install）。
- 成本：1–2 人日。

## 4. 「GUI 不好用/读屏不友好」

- 触发：用 NVDA/争渡实际走一遍，发现焦点顺序乱、按钮读不出、结果区难读。
- 已准备：WinForms 三区布局、全中文可读名、显式 TabIndex、Alt 助记符、忙碌禁按钮、
  安装/回滚二次确认默认"否"、失败自动聚焦结果区；task-38 正在做真实 NVDA 验收。
- 打回后 1 天可交：
  1. 按验收报告修 P0（名称/焦点/播报）；
  2. 加"朗读结果区"按钮 + Ctrl+Shift+R 重读；
  3. 提供纯 CLI 路径文档（读屏用户可完全不用 GUI）。
- 成本：0.5–2 人日。

## 5. 「只支持 Windows，Mac/Linux 用不了」

- 触发：跨平台用户。
- 已准备：明确声明 v1 仅 Windows（BepInEx/Unity 注入、Windows TTS 栈都是 Windows 绑定）。
- 打回后 1 天可交：无低成本方案；只能给"Ren'Py 覆盖层"的跨平台研究结论（Ren'Py 本身跨平台，
  覆盖层文件可复制，但语音桥 a11y_say.vbs 是 Windows 脚本，需要重写 Python/平台层）。
- 成本：跨平台语音桥 5–10 人日，不承诺。

## 6. 「依赖太多/要装 Python/要装 Ghidra/要管理员」

- 触发：干净机器上跑不起来。
- 已准备：核心 CLI 是自包含单文件 exe（发布版 65MB，无 Python 依赖）；Ghidra/OCR 是可选后端（BYO）；
  BepInEx 从本地缓存或按需下载（sha256 固定）；不需要管理员权限（写用户目录）。
- 打回后 1 天可交：把"需要什么、不需要什么"写成安装前检查清单；doctor 输出逐项列依赖状态。

## 7. 「版本号/发布不规范」

- 触发：版本跳跃、发布物没有校验和/说明。
- 已准备：版本号纪律 0.2.x（用户邮件指示）；每版附 SHA256SUMS + README + 发布说明 + 未验证清单。
- 打回后：当天改文档/重新打包，不跳版本。

## 8. 「未知程序/新引擎还是处理不了」

- 触发：拿一款没见过的游戏，工具只报"失败"。
- 已准备：`forge detect` 全库 22/22、未知引擎明确 unknown；加载器兼容性预检；
  未知/非 Unity 路线已落地：Ghidra 高级分析已接 CLI（task-39，`--advanced`，BYO 不随包）；外部读屏器原型已完成（task-40，结论见 docs/26）——**只承诺标准控件/可访问 DOM**，自绘窗口（如 LoveNest NW.js）实测读不到、OCR 美术字体 CER 41.8% 不可用，故不承诺"万能"，只作实验性附加工具。
- 打回后 1 天可交：对具体游戏用 `detect`+兼容性报告给"为什么不行/还能怎么读"的书面结论，
  这本身就是产品能力（说明"不假装成功"）；如可行，接 Ghidra/外部读屏出实验性结果（R22 已给出可行边界与 14–20 人日估算）。
- 字段兜底边界（R31 全库只读扫描，research/48-field-scan）：9 款可分析 Unity Mono 中 8 款有“类型文本字段”证据（317/410 候选），IL2CPP 0/120；字段是类型级声明、只扫 `Assembly-CSharp` 等有限程序集，故**不承诺“任何 Unity 都能读”**，只承诺“有文本组件字段时尝试读，读不到会静默并写诊断”。
- 成本：视引擎 1–5 人日。

## 9. 「补丁读不出来/漏读/重复读」

- 触发：真机试玩发现漏句、重复、选项不读。

  必要时加"详细日志"一键开关。

## 13. 「游戏本来装过旧无障碍补丁，装完启动就崩」

- **现象**：安装成功，但启动游戏直接弹 Ren'Py 异常屏（如 `A11yHost.validate()` 报 AttributeError）。
- **根因**：游戏自带旧版 `game/a11y_game/` + `game/a11y_platform/`（用户 A11yFramework 体系），与本工具覆盖层共用目录，契约不一致。
- **0.2.24 起的行为**：`install` 检测到旧覆盖层即返回 `E_ENGINE_UNSUPPORTED`，提示先运行旧补丁 `uninstall.ps1`（或删除旧目录）再装；确认叠加需 `--force`。契约层另有兼容桥，强制叠加也不崩、不双读。
- **答辩要点**：这不是“装不上”，而是“故意不装出一个必崩的组合”；证据：research/65-renpy-legacy-conflict/。
- **若被要求支持共存**：需要把旧补丁的调用面（validate/rpy/keys/log/repeat/said/choice 等）一项项接管，并处理双播报冲突；这是新需求，不是 hotfix 范围。

## 14. 游戏界面是中文，播报却是英文原文

- 症状：屏幕显示中文，读屏念英文 source text。
- 原因：取文本时用了 Ren'Py `_tts_all(raw=True)`（翻译前文本）。
- 处理：改用 `raw=False`；另有 `_a11y_translate_text()` 兜底查翻译表；查不到就原样播报，不崩。
- 已验证：0.2.26 真机《永恒与星辰与日常》确认框（证据 research/67-renpy-i18n-confirm）。
- 若用户追问“别的游戏也会这样吗”：诚实回答“Ren'Py 已修，Unity Mono/IL2CPP 走字符串参数不受影响；未在所有引擎上复测”。

2. 是"这一款游戏"问题，还是"这一类引擎"问题？（前者走适配器修补，后者走新适配器/兜底路线）
3. 用户愿不愿意参与 30 分钟验收？愿意就按可用性测试 Gate A 跑一轮，拿真实证据再改。


## 15. 装了补丁却一点声音都没有（Ren'Py 引擎把 `os` 删了）

- 现象：日志里后端显示「SAPI」，但每句都有一条 `[A11y错误] sapi.speak: NameError: global name 'os' is not defined`，
  `wscript.exe` 从不启动；用户什么都听不到。
- 原因：Ren'Py 6.99 的 `renpy/common/00keymap.rpy` 在 `init -1600 python:` 里 `import os` 取 `config.screenshot_pattern`，
  随后 **`del os`**。覆盖层在 `init -1850/-1800` 更早运行，后来的引擎块把脚本命名空间里的 `os` 删掉，
  运行期任何 `os.xxx` 都变成 NameError；同块 import 的 `codecs`/`sys`/`ctypes`/`subprocess`/`tempfile` 不受影响。
- 处理（0.2.45 起）：覆盖层统一 `import os as _a11y_os`，所有模板引用别名；生成物测试里有回归守卫（不允许裸 `os.`）。
- 预防：给覆盖层加「运行期别名」约定：凡是被引擎可能清理的模块，一律用 `_a11y_xxx` 别名导入。

## 16. 装完启动就弹「Parsing the script failed」（生成的 .rpy 语法错误）

- 现象：Ren'Py 启动即显示 `File "game/a11y_platform/03_menu.rpy", line N: invalid syntax`。
- 原因：生成器模板里的三引号文档字符串正文夹了 ASCII 双引号（中文引号没问题，ASCII 引号会提前结束字符串）。
- 处理（0.2.45 起）：模板里不用夹 ASCII 双引号的文档字符串，改用 `#` 注释。
- 预防：模板改动后先在自造最小样本（research/84）上跑一次启动，比在真实游戏上试错便宜得多。

## 17. 回滚成功后再装一次，却要求加 `--force`

- 现象：`verify --rollback` 成功、游戏目录干净，再 `install` 报 `E_ARTIFACT_INVALID 工作区已有部署账本`，提示加 `--force`。
- 原因：回滚后账本故意保留（追溯用），但没标记「已回滚」，安装前检查只看账本文件是否存在。
- 处理：0.2.47 起回滚会写 `rolledBack: true` + `rolledBackAt`，安装前检查放行并给一句「上一批部署已回滚…」提示；旧账本归档到新批次备份目录。
- 证据与复现：`research/86-rollback-reinstall/`（含 0.2.46 失败 / 0.2.47 成功的 A/B 产物）。
- 若仍被挡：说明账本不是由回滚写入的状态（例如手工删了补丁文件却没跑 `verify --rollback`），按提示加 `--force` 即可，属保守行为。

## 18. 游戏是 Utage（宴）引擎，装完只有对话框按钮被读，剧情不读

- 现象：补丁安装成功、`verify` 也正常，但进剧情一句都不念；日志里只有系统对话框/按钮的 Hook 命中。
- 原因：Utage 的正文入口 `Utage.AdvMessageWindow::PageTextChange(AdvPage)` 没有 string 形参，
  文字在 `page.TextData.OriginalText` / `window.Text.OriginalText` 属性链上；0.2.47 及之前分析器的候选条件不认这种入口，
  只挑到有 string 形参的 `Utage.SystemUiDialog*Button::Open`。
- 处理：0.2.48 起识别 Utage 正文类型与方法，评分加 S10（+55），计划里写「文本属性链：…」，
  生成器产出 `Postfix(object __instance)` + `SpeechGate.SayPropertyChain(__instance, new[] { "Text", "OriginalText" })`
  （只读反射、不写死偏移）。
- 若仍不读：先看 `BepInEx\LogOutput.log` 里有没有 `[Hook:hook-001] 命中 …`；有 Hook 无 `[Speech]` 说明属性链读不到
  （该游戏字段/属性名不同，需人工确认）；连 Hook 都没有说明正文走另一条链。
- 预防：计划里没有已识别正文入口时会报高风险 `R-106`，别把“安装完成”当成“能读”。
- 证据：`research/87-utage-support/`、`docs/96-发布说明-v0.2.48.md`。

## 20. GUI 里被「没有正文入口」挡住，没有 `--force` 出路
- 现象：0.2.49 起没有正文入口时 `install` 会被闸门挡住（`E_PARTIAL`），命令行能加 `--force`，但 GUI 没有这个开关。
- 处理：0.2.50 起 GUI 输入区有「允许强制(&9)」复选框，勾选后安装带 `--force`，提示行会说明风险；
  不勾选时保持安全默认（不装）。
- 另外：0.2.50 修掉 GUI 结果区里子进程 stderr 乱码（CLI 输出被重定向时强制 UTF-8），
  否则读屏只能听到乱码，等于没有错误信息。
- 证据：`research/90-gui-force/`、`docs/98-发布说明-v0.2.50.md`。

## 19. 装完“安装成功”，进游戏却一句剧情都不读
- 现象：`install` 报安装完成、`verify` 也正常，但游戏里没有任何剧情朗读；日志里可能只有系统对话框/提示按钮的 Hook 命中。
- 原因：计划里没有选中任何正文入口（台词管线），只有 UI 对话框/工具提示这类“有 string 形参”的方法被选中。
  旧版仍会安装成功，用户装完才发现没用（《Mystery Lover 2》0.2.46 的教训）。
- 处理：0.2.49 起计划带 R-106 时 `plan` 会打 `[注意]` 并在 JSON 输出 `noDialogueEntry=true`；
  `install` 直接返回 `E_PARTIAL`（退出码 5）不再部署；确认要冒险时加 `--force`，装完核对 `BepInEx\LogOutput.log` 里的 `[Speech]` 行。
  如果 R-106 误报（正文入口命名很怪），先看 `plan.json` 的人工待办，必要时人工补入口。

## 21. Unity 游戏钩子选点没命中正文，一句台词都不读

- 症状：安装成功，进游戏没朗读；日志里 `[Hook:...]` 从不出现或只出现在对话框弹出时。
- 兜底（0.2.51）：生成的插件默认开「文本兜底轮询」——每 0.3 秒扫可见的 `UnityEngine.UI.Text` / `TMPro.TMP_Text`，只读新变化的文本；日志看 `[Speech:watch] 兜底读到：…`。
- 觉得菜单文字太吵：`BepInEx/config/*.cfg` 里 `[朗读] 文本兜底轮询 = false`。
- 注意：兜底与钩子可能重复读同一句；先确认钩子是否真的没命中。

## 22. 兜底轮询把富文本标签和数字也念出来

- 症状：日志 `[Speech:watch] 兜底读到：<u><size=50>…` 或 `兜底读到：9` / `1/4`。
- 修法（0.2.52）：`CleanWatchText` 先剥 `<[^>]*>`、trim，纯数字/页码正则命中则跳过。
- 若还有别的噪声（例如菜单项），先在配置里关掉文本兜底轮询，或等 UI 过滤版本。

## 23. 兜底轮询把分辨率等设置项念出来

- 症状：`[Speech:watch] 兜底读到：1920x1080`、`1440x810`。
- 修法（0.2.53）：`CleanWatchText` 用 `^\d{3,4}x\d{3,4}$` 跳过。
- 若还念别的设置项（音量/按钮名），先在配置里关掉「文本兜底轮询」，或用后续 UI 元素过滤版本。

## 24. 兜底轮询把设置界面的取值也念出来

- 症状：日志 `[Speech:watch] 兜底读到：Off` / `On` / `Windowed` / `FullScreen`。
- 修法（0.2.54）：`WatchIgnoreExact` 精确忽略表直接跳过这些取值。
- 仍未覆盖：`Very Fast`、`Normal`、`Slow` 这类“长得像普通单词”的设置值——需要 UI 元素级过滤，或让用户先在设置界面关掉兜底轮询。

## 25. 自定义管理器游戏被判“没有正文入口”，被闸门挡住

- 症状：plan 报 noDialogueEntry=True、R-106、install 拒绝；但候选证据里有“类型文本字段：…”。
- 修法（0.2.55）：有实例文本字段的入口算可读，不再拦安装；装上后靠字段兜底或文本兜底轮询朗读。
- 若仍读不到：把 BepInEx\LogOutput.log 发我们，看是否 [Speech:watch] 兜底读到。

## 26. 兜底轮询念出 Unity 默认占位 `New Text`

- 症状：日志 `[Speech:watch] 兜底读到：New Text`，用户听到“乱读”。
- 修法（0.2.56）：`WatchIgnoreExact` 精确过滤 `new text`、`text`、`???` 等占位；仍剩下 `【 ? ? 】` 这类角色占位，遇到可把日志发我们。

## 27. 兜底轮询念出未命名角色占位 `【 ? ? 】`

- 症状：日志 `兜底读到：【 ?  ? 】`，用户听到噪声。
- 修法（0.2.57）：`WatchPlaceholderRx` 只过滤“括号内全是问号/空白”的占位，正常名字不受影响；仍有异常把日志发我们。

## 28. 脚本解析 `--json` 失败（stdout 混人类行）

- 症状：`forge analyze --json | json.loads` 报错，或错误分支拿不到 JSON。
- 修法（0.2.58）：stdout 只留 JSON 信封，人类可读行走 stderr；解析期错误也遵守 `--json`。老脚本如果一直在解析「最后一行 JSON」，可继续用；如果解析整段 stdout，现在更稳。

## 29. verify 说「有朗读」，其实全是兜底轮询

- 症状：日志有朗读行、钩子 0 命中，verify 仍 pass。
- 修法（0.2.59）：s-04 区分通道；全兜底 → Skip + 未验证「可能只读到 UI/菜单文字，剧情正文未验证」。

## 30. 计划里只剩“位置/音乐时长”参数，却当正文入口放行

- 症状：`noDialogueEntry=false`，装完读不到剧情；钩子读的是 locationText/musicDuration 一类。
- 修法（0.2.60）：参数名整名匹配 dialogue/message/line/… 才算正文入口；否则照常报 R-106 并拦安装（可用 `--force` 越过）。

## 31. 游戏目录里有启动器，钩子全打在启动器上

- 症状：根目录是 `*Launcher.exe` + `*Launcher_Data`，真游戏在 `game/`；候选全是 PPIViewer/Tooltip 一类。
- 修法（0.2.61）：去掉“顶层找到就返回”，按同 exe/UnityPlayer/程序集大小/层级给 `*_Data` 打分；仍不对时可把 `--game` 指到 `game/` 子目录。

## 32. IL2CPP 装完“安装成功”，但游戏没有声音

- 症状：日志有 `[a11y] 朗读运行时就绪；speech=True，tolk=False`，CLI 只说“安装完成”。
- 修法（0.2.62）：安装结果会提示 `--speech-runtime`；显式传入含 Tolk.dll 的目录后重装。

## 33. 钩子全打在不运行的旧代码上，装完一句不读

- 症状：install/verify 正常，游戏里没有任何朗读。
- 对策：0.2.64 起计划阶段做死代码弱判定（本程序集内调用者 0 个 → 排后 + R-107）；仍误判时人工换入口，或 analyze --advanced 看原生调用。

## 34. IL2CPP 装完只读菜单/标签，剧情不读

- 症状：install 成功、日志有 len=/sha= 但游戏没声音。
- 对策：0.2.65 起计划给出 R-306；同时确认是否传了 `--speech-runtime`（0.2.62 起安装结果会明示）。

## 35. 日语游戏读出来却是中文腔/或干脆没声

- 症状：台词文本对、但发音是中文/英文，或没有声音。
- 对策：0.2.66 起 `forge doctor` 会报 `japanese-voice`；没有就在 Windows 设置→时间和语言→语音里装日语语音，或后续用 `--speech-runtime` 指定语音运行时。

## 36. 自动化回归第二次跑就失败（前台被抢）

- 症状：脚本第一遍 PASS、第二遍 FAIL；日志里有“跳过本次点击”。
- 对策：0.2.67 后脚本已加固（Enter-Foreground 12 次重试 + 点击失败返回 false 并重试）；仍失败时看日志里最后的前台 hwnd 是哪个程序。

## 37. 脚本想知道语音哪项没过，JSON 只给一行

- 现象：0.2.69 及以前 `data.speech` 只回显 s-02，`data.checks` 是数字，脚本无法判断 s-04（钩子通道）是否通过。
- 现行为：0.2.70 起 `data.speech.allChecks` 给出全部 s-01..s-04；`metrics` 合并（当前各项不填，保持空）。
- 复测：`forge verify --speech-log <日志> --json`，看 `data.speech.allChecks`。

## 38. 空文件也能识别成 Unity 游戏

- 现象：0 字节 `UnityPlayer.dll` + `Assembly-CSharp.dll` 命中 R01 得 0.95；《透明的她 Demo》只有模组载荷也报 unity_mono。
- 现行为：0.2.71 起 `PlaceholderBinaryCheck` 对 unity_mono 做大小校验（UnityPlayer < 64KB 或 Assembly-CSharp < 4KB），置信度压到 0.6 并追加 `measured:PE 大小校验降级…`。
- 复测：造一个 2 字节假文件的目录跑 `forge detect --json`，看 `confidence` 与证据。

## 39. 语音指标的 metrics 永远是空对象

- 现象：0.2.70/0.2.71 的 `data.speech.metrics` 是 `{}`；脚本只能读文字结论。
- 根因：指标记在报告层 `Report.Metrics`，CLI 只合并了「检查项自己的指标」。
- 现行为：0.2.72 起合并报告层所有 `speech*` 指标（`speechValidLines` 等）。
- 复测：`forge verify --speech-log <日志> --json`，看 `data.speech.metrics`。

## 40. 语音指标自相矛盾（通道数大于有效行）

- 现象：0.2.72 同一份日志给出「有效 6 行、Ren'Py 通道 8 行」。
- 根因：`RenpyBackendRx` 命中时未标记 Ren'Py 通道；`renpyLines++` 在回声过滤之前自增。
- 现行为：0.2.73 起带 backend 行也算 Ren'Py 通道，且通道只统计有效行（回声重复行不计）。
- 复测：`forge verify --speech-log <日志> --json`，看 `speechValidLines` 与 `speechRenpyLines` 是否一致。

## 41. 装完只有弹对话框才念（台词入口被菜单挤掉）

- 现象：计划 6 个钩子全是 SystemUiDialog/菜单类，真台词 SetText 落在名额之外。
- 根因：评分 + `MaxHookPoints=6` 硬截断，台词候选分数略低就被挤掉。
- 现行为：0.2.74 起，若计划里没有 Dialogue 类候选，会用最高分台词候选替换最后一个名额（保底一个）。
- 复测：`forge plan` 后看补丁点里是否至少有一个 `PageTextChange`/`SetText` 类入口。
