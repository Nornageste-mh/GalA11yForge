# 0.2.35 发布说明：未知引擎高级分析可以指定可执行文件

发布日期：2026-11-16
版本：0.2.35.0
类型：小版本（未知程序能力增强）
测试基线：676 通过 / 0 失败 / 0 跳过

## 1. 这版解决什么问题

很多游戏不是一个 exe 在根目录，而是「合集」结构：

```text
To the Moon\
  To the Moon\To the Moon.exe
  To the Moon (SerenityForge)\To the Moon.exe
  Minisode_1\Sigmund Holiday Special 1\Siggy - Holiday Special.exe
  ...
```

0.2.34 已经能往子目录找 exe，但只能自动挑一个。用户如果知道“该分析哪个”，
旧版没办法指定；自动挑错时，也只能自己猜。

本版补两件事：

1. **可以指定**：`--option "ghidra.executablePath=<完整路径>"`。
2. **自动挑时告知候选**：结果里列出其它候选 exe，并提示怎么切过去。

## 2. 改动

### 2.1 新增选项 `ghidra.executablePath`

- 路径存在：用这个文件做 Ghidra 分析（`Path.GetFullPath` 规范化）。
- 路径不存在/非法：给一条警告「已忽略，将自动选择可执行文件」，然后走自动选择。
- 显式指定时，产物里的 `executableCandidates` 为空（不干扰使用者）。

### 2.2 候选可执行文件列表

- `GhidraTargetSelector.FindCandidates(gameDirectory, max = 8)`：
  根层 + 两层子目录，去重；排序规则与自动选择一致（名字匹配祖先目录 > 层级浅 > 体积大 > 名字）。
- 产物新增 `executableCandidates`；JSON 信封 `data.ghidra.executableCandidates`。
- 候选多于 1 个时，`unverified` 会写一条中文说明：当前自动选的是哪个、怎么指定另一个。
- 人类输出追加一行：「另有 N 个候选可执行文件，可用 --option ghidra.executablePath=<路径> 指定。」

### 2.3 默认超时统一

`GhidraBackendOptions` 的类属性默认值（600/900 秒）与 `FromProfile` 回退值（原 240）不一致，
本版统一为常量，避免“没配置时到底等多久”说不清。

### 2.4 语义修正

Ghidra 硬失败（超时/崩溃）且没有适配器分析结果时，CLI 首行原为
`[完成] 分析完成：0 个文本候选`，容易被误读为成功。本版改为：

```text
[部分完成] 分析未完成：0 个文本候选（Ghidra 高级分析失败，结果不完整）。
```

## 3. 真机证据（To the Moon，只读）

环境：Ghidra 12.1.4；命令均带 `--advanced`。

| 场景 | 命令要点 | 结果 |
|---|---|---|
| 显式指定小 exe | `ghidra.executablePath=…\Siggy - Holiday Special.exe`、`timeoutSeconds=150` | `completed`、50.8 秒、`executableSizeBytes=61440`、`executableCandidates` 空 |
| 自动选择 + 短超时 | `timeoutSeconds=45` | `timeout`、45.1 秒、选中 `To the Moon\To the Moon.exe`、候选 7 个、提示如何指定 |

- `run-a-explicit-analysis-ghidra.json`、`run-a-cli-output.txt`
- `run-b-auto-candidates-analysis-ghidra.json`、`run-b-cli-output.txt`

## 5. 已验证 / 未验证

已验证：

- 676 个自动化测试全绿（Core 98、Verify 69、Detection 30、Generators 59、Ren'Py 37、UnityMono 31、Build 80、Gui 152、Il2Cpp 55、Ghidra 65）。

## 6. 升级

直接替换 `app/forge.exe` 与 `gui/Forge.Gui.exe` 即可；工作区、已装补丁、账本格式未变。
旧工作区里 0.2.34 的分析产物仍可被 0.2.35 的 `report` 读取。
