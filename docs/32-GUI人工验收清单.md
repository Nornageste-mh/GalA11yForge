# GUI 人工验收清单（10 分钟版）

## 0. 自动化已覆盖（0.2.23）

以下项目已经用 UI Automation 自动跑过，`research/64-gui-uia-check/` 有证据，人工清单里不用重复：

- 控件都有中文名：41 个节点无“空名字控件”。
- Alt+1..6 焦点落点正确（游戏目录/工作区/BepInEx 包/forge.exe 路径/语音日志/演练模式）。
- 操作按钮的助记符存在（Alt+D/A/G/B/O/I/Y/V/R/X/L）；没填游戏目录时按钮禁用、助记符不生效，符合预期。
- Alt+V 能触发环境自检，状态行与结果区文本都能被 UIA 读到（7 项检查逐条）。

**仍需人工**：NVDA/争渡实际念出来是否流利、结果区更新时会不会自动朗读、安装/回滚二次确认的播报是否清楚。


给用户用：打开 `releases/v0.2.3/gui/Forge.Gui.exe` 后，按下面 10 步走一遍，把"过/不过/听不清"记在最后一列。
目的不是测功能全，而是确认**读屏用户能不能独立完成一次"识别引擎"和一次"环境自检"**，以及关键按钮念得对不对。

前置：NVDA 或争渡已启动，耳机/扬声器可用。GUI 与游戏都关掉，避免抢焦点。

| # | 操作 | 应该听到/看到 | 结果（过/不过/备注） |
|---|---|---|---|
| 1 | 双击打开 GUI | 窗口标题「GalA11y Forge — 无障碍补丁工坊」；焦点落在「游戏目录」输入框 | |
| 2 | 按 `Alt+1` | 焦点跳到游戏目录输入框，读屏念出标签与当前内容 | |
| 3 | Tab 走一圈（约 21 个停点） | 每个控件都有名字；顺序：输入区 → 操作按钮 → 结果区 → 执行记录；不会卡在某处 | |
| 4 | 按 `Alt+V`（环境自检） | 结果区出现"环境检查通过"等文字；读屏能读到结果；按钮有忙碌状态 | |
| 5 | 在游戏目录填一个真实游戏（可先用 `D:\Steam\steamapps\common\Build`） | 填错路径时结果区给中文错误和下一步建议，不是英文堆栈 | |
| 6 | 按 `Alt+D`（识别引擎） | 结果区念出「识别为 unity_mono（置信度 95%，高）」与加载器兼容性；焦点在结果区 | |
| 7 | 按 `Alt+O`（一键：识别→分析→生成→构建） | 依次出现步骤结果；中途可按停止；失败时给 code/message/suggestion | |
| 8 | 按 `Alt+I`（安装补丁） | 先弹二次确认，默认「否」；选「否」不会写游戏目录 | |
| 9 | 选一次「否」后再按 `Alt+R`（回滚） | 没有安装记录时给中文提示，不崩溃 | |
| 10 | 关掉窗口重开 | 上次的输入还在（或明确清空），不会丢配置 | |

补充检查（有余力再做）：

## 已知限制（不用当 bug 报）

- 窗口截图（PrintWindow）会卡住，这是工具限制，不是 GUI 问题。
- 结果区文字很长时，NVDA 可能需要用方向键逐行读；这是文本框，不是文档模式。
- "一键"里如果有步骤未实现（例如某引擎的构建），会明确显示"未实现"，不是 bug。

- **Ren'Py 确认框**：已真机取证（0.2.24，research/66-renpy-confirm-screen，播报英文原文、按钮名未单独播报，属已知缺口）。
