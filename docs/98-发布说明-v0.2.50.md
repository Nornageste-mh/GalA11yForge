# 0.2.50 发布说明（2026-11-16）

## 1. 一句话

GUI 里加了「允许强制」复选框（Alt+9），被「没有正文入口」挡住或要覆盖已有补丁时不用回命令行；
同时修掉 GUI 结果区里子进程错误输出乱码（读屏会念乱码的问题）。

## 2. 为什么做这两件事

- 0.2.49 引入了「没有正文入口就不让装」的安全闸门（R-106），命令行能加 `--force` 越过，但 GUI 没有这个开关
  ——读屏用户被挡住后没有出路，只能去命令行。
- 0.2.50 之前，GUI 执行 `install` 失败时结果区的「标准错误」段显示为乱码（`[ע��] …`），
  同一次输出的 stdout 中文正常。读屏用户会听到一串乱码，等于没有错误信息。

## 3. 改了什么

| 文件 | 改动 |
|---|---|
| `src/Forge.Gui/MainForm.cs` | 输入区第 9 行新增「允许强制：跳过安全拦阻（&9）」复选框；根布局输入区高度 300→332；输入表 9 行 |
| `src/Forge.Gui.Core/GuiStateMachine.cs` | `GuiInputs` 新增 `Force`；就绪提示行在勾选时说明「安装会加 --force，可能覆盖已有补丁或越过安全拦阻」 |
| `src/Forge.Gui/MainForm.Commands.cs` | 把勾选状态带进 `ForgeRequest.Force`（CLI 参数由现有 `ForgeArgumentBuilder` 生成） |
| `src/Forge.Gui.Core/ForgeShortcuts.cs` | 输入框助记符扩到 Alt+1..9（Alt+8 分析程序、Alt+9 允许强制） |
| `src/Forge.Cli/Program.cs` | 启动时若输出被重定向，显式把 `Console.OutputEncoding` 设为 UTF-8（无 BOM）；修 GUI stderr 乱码 |
| `tools/gui-force-e2e.ps1` | 真机验证脚本：勾选后读提示行确认状态、点安装并处理二次确认框、断言命令行带 `--force` 且 stderr 中文可读 |
| 测试 | GUI 助记符/输入/提示行新断言；共 **712 通过 0 失败**（Gui 168） |

## 4. 验证（真机）

## 5. 诚实边界

- 自动化只能证明「提示行反映了勾选状态、发出的命令行带 `--force`、结果区文本是中文」；
  NVDA 真人听辨（尤其复选框勾选反馈）仍需人工复验（docs/32 清单）。
- 只在一个 DPI / 一套主题下验证了 9 行输入区排版；换 DPI 是否裁切未复核。
- `--force` 会越过 R-106 安全闸门，装上仍可能读不到剧情；GUI 提示已写明“大概率读不到剧情”。

## 6. 升级提示

- 本版 GUI 有改动：升级时请同时替换 `gui/Forge.Gui.exe`。
- 已装过旧版补丁的游戏：先 `verify --rollback`，再装新版（0.2.47 起回滚后重装不再需要 `--force`）。
