# GalA11y Forge 产品方案 v1（2026-11-14，待甲方确认）

> 依据：`docs/03-研究汇总-v1.md` 的 8 份研究报告 + 本机实测。
> 一句话：输入"游戏文件夹"，输出"能读屏玩的补丁 + 安装说明 + 自检报告 + 人工待办"。

## 0. 先给结论

推荐 **形态 C（混合）**：内置"通用保底插件"保证装了就有点用，再按游戏自动生成"专属补丁"把效果做深。
首期只承诺 3 类引擎（Unity Mono、Ren'Py、Unity IL2CPP），其余引擎做"识别 + 人工待办"，不硬吹。
软件成本 0 元；测试游戏建议 0 元起步，如需扩样本首期预算上限 ￥300（用户已拍板，实际未支出）。完整拆分见 `docs/75-成本分析-v0.md`。

## 1. 三种形态与代价（A/B/C）

### A. 纯命令行生成器

- 是什么：一个 exe，命令 `forge patch --game "D:\Steam\...\Game"`，生成补丁工程和安装包。
- 优点：开发最快、最稳、最容易测试；生成物透明可审。
- 代价：盲人用户几乎无法独立使用（要开命令行、看路径）；每次换游戏都要人喂参数。
- 适用：先做内部工具、给会电脑的人用。

### B. 通用运行时插件（不分析，装上就"尽量读"）

- 是什么：一个通用 BepInEx 插件，监听 Unity 的文本变化/UI 变化，尽量把新出现的文字读出来。
- 优点：一键安装、覆盖广；不依赖对每个游戏的分析。
- 代价：效果天花板低——漏读、重复读、把菜单/调试文字也读出来；可选菜单、回放、别名都做不好；用户口碑会差（R7 六类负面反馈里占四类）。
- 适用：作为"保底模式"和"暂不支持引擎"的兜底。

### C. 混合（推荐）

- 是什么：一个 WinForms 向导 + 同一个核心 CLI。向导负责选游戏、跑分析、给你看"能做什么/不能做什么"，然后一键生成/安装/卸载/自检；核心还是确定性流水线。
- 优点：盲人可独立操作（向导全程键盘可达、读屏友好）；效果接近手工补丁；失败时降级到通用保底并产出人工待办。
- 代价：工作量最大（约比 A 多 30–40%），GUI 与语音桥要额外测试。
- 适用：我们要交付"产品"，不是"脚本合集"。

**推荐 C 的理由**：用户就是盲人读屏用户，产品必须自己能操作；同时 C 里的核心 A 可以先做、先测，GUI 后包一层，风险可控。

## 2. 用户流程（甲方视角，5 步）

1. 打开 GalA11y Forge → "选择游戏文件夹"（自动列出 Steam 库里的游戏，也可手动选目录）。
2. 点"分析"：10–60 秒后给一页人话报告——
   - 识别到的引擎/版本/位数；
   - 找到几处文本写入点、几个候选菜单、预计覆盖率；
   - 哪些能做、哪些要人工确认、哪些不支持。
3. 点"生成并安装"：自动生成补丁工程 → 构建 → 备份 → 安装 → 写回滚清单。
4. 点"自检"：检查文件、版本、补丁加载日志、语音后端；输出"通过/失败原因/下一步"。
5. 按"首次试玩清单"玩 10 分钟，遇到漏读/重复读点"记录问题"，生成反馈包。
   卸载：一键还原备份；游戏更新后：点"重新生成"。

## 3. 产品组成

| 模块 | 职责 | 技术 |
|---|---|---|
| `GalA11yForge.Core` | 流水线编排、工作区、profile、报告、日志 | .NET 8 类库 |
| `GalA11yForge.Cli` | 命令行：scan/analyze/plan/build/deploy/verify/uninstall | .NET 8 控制台 |
| `GalA11yForge.Gui` | 向导、报告页、自检页、日志页（读屏友好） | WinForms（R6 实测 UIA 可读） |
| `Adapters.*` | 每引擎一个适配器，实现 detect/analyze/plan/generate | 独立项目，可插拔 |
| `SpeechBridge` | 统一语音出口：NVDA/争渡/Tolk/SAPI/eSpeak 选路与打断 | 复用 Framework L1（MIT） |
| `Verify` | 静态检查 + 日志解析 + 自检报告 | 核心库 |
| `Payload` | 内置：BepInEx 5/6 缓存、L1 平台层（pin 版本）、许可证清单 | 随包资源 |

## 4. 七步流水线（机器模块）

1. **discover**：枚举 Steam 库/目录，识别引擎、位数、Unity 版本、已装补丁；（R1 已证明要修入口误判）
2. **analyze**：Cecil/Il2CppDumper/UnityPy/文本扫描 → 证据（文本写入点、文本持有者、框架痕迹、CJK 字面量、候选菜单）；
3. **plan**：打分（R4 的 S1–S8/N1–N4，阈值 70/50/30）→ 选 hook 策略、按键方案、语音后端 → 产出 `profile.json` + `plan.md`；
4. **generate**：渲染补丁工程（Unity 插件 / Ren'Py .rpy / KiriKiri 配置）→ 生成缺口清单；
5. **build**：dotnet build / 复制脚本 / zip 打包（可复现，pin 版本）；
6. **deploy**：备份 → 安装 → 写 manifest（可卸载/回滚）；
7. **verify**：静态校验 + 首次启动日志自检 + 人工试玩清单。

## 5. 引擎支持分级与首期范围

| 级别 | 引擎 | 首期承诺 | 本机样本 |
|---|---|---|---|
| A | Unity Mono | 全自动：识别→分析→生成→构建→部署→自检 | 9 款（含 P0 3030980） |
| A | Ren'Py | 全自动，零归档改动（.rpy 叠加） | 3 款（DDLC 6.99 / mei 8.5.2 / 永恒 8.6 已装补丁） |
| A（暂标未验证） | RPG Maker MV/MZ | 生成 JS 插件；本机无样本，先"识别+待办" | 0（To the Moon 的 mkxp 是 XP，不算） |
| B | Unity IL2CPP | 自动 + 一次人工确认（首次启动生成 interop） | 5 款（P0 3012630 硅心/Naninovel） |
| B | KiriKiri Z | 版本分流：新作启用内建 a11y；老作注入（tpm 优先/归档兜底） | 1 款（千恋，无干净基线） |
| B+ | WebGAL | 识别 + 生成建议，后续版本 | 0 |
| C | 其余 13 类 | 只识别 + 人工待办 + 通用保底建议 | 视情况 |

首期明确**不做**：UiNav 大改（R1 明确新作不得接）、自动翻译（只留接口）、在线 TTS、盗版/解密支持。

## 6. 生成物与安装形态

- Unity Mono：`BepInEx 5.4.23.5` + `netstandard2.1` 插件工程；随包 L1 平台层（Framework pin 到具体 commit，MIT，NOTICE 里署名）。
- Unity IL2CPP：`BepInEx 6.0.0-be.788` + `net6.0`；首次启动生成 interop，再注入。
- Ren'Py：`game/a11y_*.rpy` + `nvdaControllerClient64.dll` 可选；不改 rpa/归档。
- KiriKiri Z：老作 `plugin/*.tpm` 优先（未实测），归档补丁需备份 + manifest 回滚；新作直接启用引擎内建 a11y。
- 每次安装都产出：`install-manifest.json`（文件清单+哈希+备份路径）、`uninstall.ps1`、`README-安装说明.txt`（人话版）、`verify-report.json/md`、`manual-todo.md`（人工待办）。

## 7. 语音与界面方案（R6 实测结论）

- 语音后端默认顺序：**Tolk（自动检测任意读屏器）→ NVDA 直连 → 争渡 ZDSR → SAPI5 → 静默+诊断日志**。每级失败记录原因、10 秒重试；切换后端时把跳过的后端念给用户听。
- SAPI 只做兜底，且**永远异步**：实测同步读 68 字会阻塞主线程 17.67 秒；打断用 PURGE（实测有效），长文本按句切（每句 60–80 字）。
- 日语：本机无 ja-JP 语音（SAPI/OneCore 注册表与目录都只有中/英）。首选用户自装 ja 音色；次选 NVDA 自带 eSpeak NG（GPL-3.0，不随包）；都没有时**明确播报"当前无日语语音，中文音色读日文不可懂"**，不静默降级。
- 界面：**WinForms 主界面**（UIA 树完整、焦点扫描 12 项可读、开发成本最低）；WPF 备选（AutomationId 更规整但标题栏菜单会抢焦点）；Avalonia 11 本次未取得可靠 UIA 树 → 不做主界面；TUI 只做诊断/无 GUI 兜底。
- 补丁内嵌：L1 源码（MIT）+ Tolk.dll（LGPL-3.0）+ nvdaControllerClient64.dll（LGPL-2.1）+ SAPI 纯 P/Invoke；**ZDSR DLL 不随包**（运行时从用户安装目录加载）；**eSpeak NG 不随包**（GPL-3.0）；安装器附 `licenses/` 与第三方组件说明。
- 交互纪律：单一语音出口、事件驱动（不轮询刷屏）、可打断可重播、不抢焦点、菜单循环读；选项也进重读缓冲；有配音的行整句进缓冲但只报角色名；快进/自动模式丢弃中间句而不是排队。

## 8. 质量保证

- 单元测试：核心（discover/plan/render/verify）+ 适配器（fixture 假游戏目录，不含游戏资源）。
- 集成测试：本机 P0 `3030980`（Mono）与 `3012630`（IL2CPP+Naninovel）端到端；Ren'Py 用 DDLC/mei 基线。
- 回归测试：13 款已装补丁游戏，验证"装了补丁的游戏不被误判、不重复安装、可识别版本"。
- 验收矩阵：R8 的 30 条（P0 12）+ R7 的 15 条风险 + R3 的安装/卸载/回滚场景。
- 交付前：自动化测试全绿 + 至少 2 款真实游戏人工跑通 + 1 款"故意异常操作"（中途关游戏、重复安装、游戏更新后重生成）。

## 9. 版本、成本、命名

- 命名：GalA11y Forge（中文：无障碍补丁工坊）。
- 版本：统一 `0.2.x` 叠加（用户 2026-11-14 指示）：`0.2.0.0` 核心 CLI/Unity Mono → `0.2.1` 硬化 → `0.2.2` Ren'Py/选项 → `0.2.3` IL2CPP/GUI …；不跳 0.3+，验收通过后再谈 `1.0`。不夸大。
- 软件成本：0 元（开源依赖；随包只放 MIT/Apache/BSD/未改 LGPL）。
- 测试游戏：建议先 0 元（现有 21 款 + 免费 Demo 4169180）；可选买《钟塔》¥18（验证补丁随游戏更新失效）、Riddle Joker ¥88（补第二部 KiriKiri 干净基线）。
- TTS/翻译：默认全免费离线；在线翻译默认关闭（有 API 费用，不默认开）。

## 11. 被打回预案（按用户要求提前准备）

- **可插拔**：每个引擎适配器独立项目、独立版本；某一个被否掉不影响其它。
- **可快速修正**：`profile.json` 存盘，`overrides.json` 允许人工改 hook 点/别名/文本规则/按键；改完 `forge rebuild` 一条命令重生成。
- **可降级**：引擎不支持 → 输出"通用保底 + 人工待办"，不报错卡死。
- **可回滚**：安装前备份、manifest 记录；一键卸载。
- **多输出形态**：CLI 与 GUI 共用核心；通用保底插件可单独发；生成物可当模板被人手改。
- **版本 pin**：Framework、BepInEx、L1 全部 pin 版本 + sha256，避免"上次能跑这次不能"。
- **提前留接口**：多语言（日/英文本朗读）、盲文输出、在线翻译、更多引擎，都留扩展点，不写死。

## 12. 需要甲方确认的 4 件事

1. **形态**：A 纯 CLI / B 通用插件 / **C 混合（推荐）**。
2. **首期引擎顺序**：推荐 Unity Mono → Ren'Py → IL2CPP → KiriKiri（可调整）。
3. **预算**：0 元 / ¥18（钟塔）/ ¥106（钟塔 + Riddle Joker）。推荐先 0 元，跑通后再决定。
4. **实验授权**：是否允许我们在**备份后**对指定游戏安装/卸载我们的补丁并启动游戏做运行期验证（只限工作区已记录的测试游戏，结束后恢复；不碰千恋的 0.2.0.1 现场）。

确认后我们按阶段 2 开工；未确认前不写产品代码。
