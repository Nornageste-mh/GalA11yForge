# 可用性测试 Round A 方案（草案）

> 状态：待用户拍板（是否做、预算、时间）。本文件只出方案，不执行。
> 目的不是“证明产品好”，而是找出**真人第一次用会卡在哪**——尤其是安装、进游戏、朗读、选项、回滚这五步。

## 1. 要找谁

- 3–5 人，满足其一即可：
  - 平时用 NVDA / 争渡 / 手机读屏的视障玩家；
  - 没玩过 Galgame、但愿意按步骤试的读屏用户（更接近“第一次用”）。
- 不要求会命令行；不要求懂游戏引擎。
- 每人一次，约 30–40 分钟，远程（腾讯会议/微信语音）或线下均可。

## 2. 预算与补偿

- 按此前口头标准：**¥50/人**；3 人 ¥150，5 人 ¥250。
- 不含：打车/设备等额外费用（如需另算请用户定）。
- 我方出：一台能跑游戏的 Windows 电脑 + NVDA（或让参与者用自己的读屏环境）。

## 3. 测试任务（按顺序，允许卡住并记录）

1. **安装**：从 `releases/v0.2.x` 解压，运行 GUI，选中游戏目录，点“一键安装”。观察：能否独立完成？在哪一步犹豫？
2. **启动与朗读**：启动游戏，进到第一句对白。观察：多久听到第一句？读的是不是当前句？有没有重复/漏读/念界面字？
3. **推进对话**：连续推进 5 句。观察：是否知道怎么推进？是否重复朗读？
4. **选项**：走到有选项的地方（若测试游戏没有，则人工构造或换 Ren'Py 样本）。观察：能否听到选项、能否用数字键选中、选完是否有确认。
5. **回滚**：在 GUI 里点“回滚”，确认游戏目录恢复。观察：是否敢点？点完是否相信已恢复？

## 4. 记录什么（只记行为，不记台词）

- 每步：完成 / 需要提示 / 卡住；卡住时原话（简短）。
- 主观 1–5 分：安装难度、朗读可懂度、整体信心。
- 可选：屏幕录制（只录操作区域，避免录到游戏台词）；不强制。
- **不记录**：游戏原始文本、账号信息、参与者真实姓名（用 P1/P2 代号）。

## 5. 我方需要提前准备

- 一个干净的测试机 + 一款已装补丁能跑通的游戏（优先 DDLC 或 GalMaster，体积小、流程短）。
- GUI 的“一键安装/回滚”路径提前自测一遍（0.2.18 已具备）。
- 一份 1 页纸的“参与者说明”（这是什么、不会收集什么、卡住没关系）。
- 记录表模板（Excel/CSV），测试时只填代号与行为。

## 6. 结果怎么用

- 输出 `research/59-usability-round-a/REPORT.md`：按五步列通过率、最常见卡点、原话摘录（脱敏）、改法建议。
- 卡点按“产品问题 / 文档问题 / 用户环境问题”分类；只有前两类进待办。
- 若 3 人里 2 人卡在同一步，该步优先修；不追求一次改完。

## 7. 需要用户决定的事

1. 做不做？（建议做：这是目前唯一能验证“真人能不能用”的手段）
2. 人数与预算：3 人 ¥150 还是 5 人 ¥250？
3. 时间：本周内 / 下周 / 等版本更稳再做？
4. 参与者来源：用户自己找，还是我方出招募文案？（我方不接触个人信息）
