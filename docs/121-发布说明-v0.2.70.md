# 0.2.70 发布说明：初检的语音块不再只给一行

- 日期：2026-11-17
- 版本：0.2.70.0
- 上一版：0.2.69.0（verify 能统计 Ren'Py 播报行）

## 1. 一句话

`forge verify --speech-log` 的 JSON 里，`speech` 从「只回显 s-02 一条」变成「s-01…s-04 全给 + 合并指标」，脚本和 GUI 不用再猜哪项检查没跑。

## 2. 为什么做

0.2.69 真机对照时发现：`data.speech` 只有 s-02，`data.checks` 只是个数字，`metrics` 是空的。脚本想知道「钩子命中通道」有没有过（s-04）、`[朗读]` 回声有没有被去重，只能去翻 Markdown 报告。

## 3. 改了什么

- `src/Forge.Cli/PipelineCommands.cs`：`verify` 的 `data.speech` 扩成
  - 兼容字段：`check`/`name`/`status`/`detail`（仍指 s-02）；
  - 新增 `allChecks`：所有 `s-*` 检查的 `check`/`name`/`status`/`detail`；
  - `metrics`：合并所有 `s-*` 检查的指标（目前各项不填，保持空对象，不编数）。
- 人类可读输出不变。

## 4. 验证

真机（自造 Ren'Py 6.99 最小样本 + 0.2.69 归档日志 `research/84-minimal-renpy-e2e/evidence/a11y_speech-0.2.44.log`）：

```
install --force → verify --speech-log → verify --rollback
```

`data.speech`：

```json
{"check":"s-02","name":"日志里有有效朗读输出","status":"pass",
 "detail":"有效朗读 8 行，去重后 6 行，占位噪声 0 行。","metrics":{},
 "allChecks":[{"check":"s-01","status":"pass"},{"check":"s-02","status":"pass"},{"check":"s-03","status":"pass"}]}
```

（该日志没有 hook 命中/兜底行，所以 s-04 不出现，符合预期。）

- 全量测试：735 通过 0 失败 0 跳过（Core 117、Verify 72、Detection 30、Generators 60、Ren'Py 37、UnityMono 41、Build 82、Gui 168、Il2Cpp 56、Ghidra 72）
- 证据：`research/122-verify-speech-block/`（install.json / verify.json / rollback.json）
