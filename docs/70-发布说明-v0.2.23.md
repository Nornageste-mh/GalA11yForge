# 0.2.23.0 发布说明（2026-11-15）

## 1. 本版做了什么

### 1.1 修：发布包里的 GUI 找不到 forge.exe

之前的发布包布局是 `releases/v0.2.x/{app, gui}`：`forge.exe` 在 `app\`，`Forge.Gui.exe` 在 `gui\`。
旧 GUI 的查找顺序是「同目录 → 向上找仓库的 `src\Forge.Cli\bin\{Release,Debug}\net8.0\forge.exe` → 当前目录 → PATH」，
真实用户解压发布包后双击 `gui\Forge.Gui.exe`，会提示「没找到 forge.exe，请用 Alt+4 指定路径」。

0.2.23 起 `ForgeExeLocator` 增加两个候选（顺序在“同目录”之后）：

1. `..\app\forge.exe` —— 发布包布局（来源显示“发布包 app 目录”）
2. `..\forge.exe` —— 扁平布局兜底（来源显示“上一级目录”）

同时把输入框占位提示改成「留空 = 自动查找（GUI 同目录 / 上一级 app\ / 仓库产物 / PATH）」。
结果区的“来源”和“尝试过的路径”仍会保留，找不到时用户能看到差在哪一步。

新增 2 条单测：`ReleasePackage_SiblingAppFolder_IsFound`、`FlattenedLayout_ParentFolderForgeExe_IsFound`。

### 1.2 GUI 可访问性自动点检（不改产品代码，补证据）

用 UI Automation 对 0.2.22 发布版 GUI 做了一次自动点检，证据在 `research/64-gui-uia-check/`：

- 41 个控件全部有中文名，无“空名字控件”。
- Alt+1..6 的真实焦点落点正确（游戏目录/工作区/BepInEx 包/forge.exe 路径/语音日志/演练模式）。
- 操作按钮助记符存在（Alt+D/A/G/B/O/I/Y/V/R/X/L）；没填游戏目录时按钮禁用、助记符不生效，符合预期。
- Alt+V 能触发环境自检；状态行与结果区文本都能被 UIA 逐字读到（7 项检查逐条），结果区可用 ValuePattern 取全文。

结论：GUI 的“机器可读性”达标；**读屏实际念出来是否流利、结果更新是否自动朗读，仍需人工确认**（docs/32 有 10 分钟清单）。
