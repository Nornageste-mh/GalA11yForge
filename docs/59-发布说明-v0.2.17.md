# 0.2.17.0 发布说明：自动 dump 结果会被复用，不再重复跑

- 发布日期：2026-11-15
- 版本号：`0.2.17.0`（按用户 2026-11-14 邮件：统一在 0.2.x 上叠加）
- 发布目录：`releases/v0.2.17/`
- 上一版：`0.2.16.0`（Ren'Py 选项上方题目朗读）

## 1. 这个版本解决什么问题

IL2CPP 游戏如果没有 BepInEx interop，工具会自动调用 Il2CppDumper 生成 `dump.cs`（约 20 秒，
产物 ~17–18MB）。此前有个体验问题：

- 第一次 `forge analyze` 生成了 dump.cs，但第二次 `forge plan` / 再跑一次 `analyze` 会**重新 dump**；
- 如果第二次没带 `--option re.il2cppdumper.path=...`，就会直接报
  `E_DEPENDENCY_MISSING 没有可用的静态输入，自动 dump 也没成功`，让人以为环境坏了。

这个版本之后：**工作区里已有新鲜的 dump.cs 就直接复用**，不再起 dumper 进程；
只有 dump 比 `GameAssembly.dll` / `global-metadata.dat` 旧（游戏更新过）时才重新 dump。

## 2. 改了哪里

- `src/Forge.Adapters.Il2Cpp/Internal/Il2CppAutoDumper.cs`
  - `Produce()` 在校验输入文件后先 `FindDumpFile(ResolveOutputDirectory(context))`；
  - 新增 `IsDumpFresh(dumpPath, layout)`：产物 ≥100KB，且 dump 的写入时间不早于
    `GameAssembly.dll` 与 `global-metadata.dat` 的写入时间；
  - 复用成功时 Note 写「复用工作区已有 dump.cs（N B，未重新运行 dumper）」，
    该 Note 会进 analysis.json 的 unverified 首条，用户能看到本次没有重新 dump。
- 测试：`AutoDumper_ReusesExistingFreshDump_WithoutDumperExecutable`
  （刻意不放 dumper，只放新鲜 dump.cs，断言成功复用且 Note 含「复用」）。

## 4. 真机工作区验证（SiliconHeart）

- 游戏：`D:\Steam\steamapps\common\SiliconHeart`（Unity 2021.3.15f1，IL2CPP，无 interop）。
- 首次 analyze（0.2.16 + 显式 dumper）→ 40 候选，工作区生成 dump.cs（18,195,590 B）。
- 第二次 plan（0.2.17，不再传 dumper 路径）→ 成功，不再报依赖缺失；plan 显示
  `route=semi_automatic、0 个补丁点、9 条人工待办`，首条是「先让 BepInEx 6 生成 interop」。
- 第二次 analyze（0.2.17，不传 dumper 路径）→ 成功，40 候选，unverified 首条为
  「复用工作区已有 dump.cs（18195590 B，未重新运行 dumper）」。
- 说明：SiliconHeart 的 0 钩子是缺少 interop 的设计结果（dump 路线只给骨架，不给强类型钩子），
  **不是本版引入的回归**。
- 证据：`research/50-il2cpp-field-fallback/evidence/il2cpp-dump-reuse-0.2.17.txt`。
