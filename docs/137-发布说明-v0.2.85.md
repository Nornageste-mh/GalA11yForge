# 发布说明 · v0.2.85.0（2026-11-18）

## 1. 一句话

`verify --speech-log` 的 `s-06` 现在会拿**计划里的钩子数**和**日志里实际挂载的钩子数**对账：钩子静默少挂（没有任何异常行）也会判失败，整体标记 `partial`。

## 2. 为什么做

0.2.84 的 `s-06` 只检查「日志里有没有解析失败行」（`Ambiguous match` / `解析目标时出错`）。这只覆盖了「出错并且写进日志」的情况；真实世界里更常见的是**一句异常都没有**：

- 补丁点目标方法在这版游戏里不存在（被裁剪/改名）；
- Harmony 补丁签名与目标参数不匹配（`Patch` 阶段直接抛异常但被插件吞掉或只在详细日志里）；
- 插件加载顺序/依赖问题导致某个 Hook 类没被扫描到。

这些情况下日志里既没有 `Ambiguous match`、也没有别的错误行，`s-06` 会给出「通过」，和「一切都好」无法区分。0.2.55 的《Mystery Lover》真机事故（6 个钩子只挂 5 个）本质就是这个问题的显性版本；这一版把「对账」补上：**装了不等于挂上了，挂上了几个必须能对上计划**。

## 3. 改了什么

| 文件 | 改动 |
|---|---|
| `src/Forge.Verify/Internal/SpeechLogChecks.cs` | 新增 `TryCountPlannedHooks(PreparedContext)`：从工作区 `02-decide/plan.json` 读 `PatchPlan`，数 `Kind == PatchPointKind.Hook`；文件不存在/解析失败返回 null |
| 同上 | `s-06` 改为四分支：①日志无钩子行且计划为 0/null → Skip（不适用）；②日志无钩子行但计划 N>0 → Skip 并提示「日志可能来自旧的一次运行」；③有解析失败行 → Fail（文案追加计划数）；④**挂载数 < 计划数 → Fail（P1）**「计划 N 个钩子，日志只挂载 M 个（少 D 个）」；数量对得上 → Pass，写明「（计划 N 个）」 |
| 同上 | 新增 metrics：`speechPlannedHooks` |
| `tests/Forge.Verify.Tests/InstallVerificationTests.cs` | 新增 3 条：少挂 → s-06 Fail 且 `overall=partial`；数量一致 → Pass；计划有钩子但日志无钩子行 → Skip 并带计划提示；helper `WritePlan(...)` 写工作区 `plan.json` |
| `tests/Forge.Verify.Tests/SpeechLogInspectorTests.cs` | `Counts_hook_mounted_and_resolve_error_lines`（0.2.84 已有，本版沿用） |

`TryCountPlannedHooks` 读不到 plan.json 时返回 null（s-06 退化为 0.2.84 行为），不会因为工作区不完整就误报失败。

## 4. 验证

### 4.1 真实归档日志（计划 6 个 / 日志挂载 6 个）

日志：`research/91-watcher-live/LogOutput.log`（10,922 B、180 行，6 条 `[Hook] 已挂载`、钩子命中 0、兜底轮询 53 行）。在《Build》副本上安装后用 0.2.85 开发版 CLI：

```
overall = pass_with_skips
s-01 pass   10,922 B，180 行，完整读取
s-02 pass   有效朗读 49 行，去重后 44 行，占位噪声 0 行
s-04 skip   钩子命中 0 行、兜底轮询读到 53 行：可能全部来自兜底轮询
s-05 pass   没有发现 [A11y错误] 或 Exception 行
s-06 pass   钩子已挂载 6 个（计划 6 个），没有解析失败行
s-03 pass   有效朗读 49 行，去重后 44 行（同一句最多重复 3 次）

metrics: speechHookMountedLines=6, speechHookResolveErrorLines=0, speechPlannedHooks=6, speechWatchLines=53 …
```

0.2.84 下同一份输出只写「钩子已挂载 6 个」，无法知道计划里有几个。

### 4.2 合成「静默少挂」日志（计划 6 个 / 日志挂载 2 个）

`research/147-plan-hook-count/evidence/synthetic-fewer-hooks.log`：2 条 `[Hook] 已挂载` + 3 行 `[Speech]` 朗读，**没有任何异常行**。

```
overall = partial  failed=1
s-06 fail   计划 6 个钩子，日志只挂载 2 个（少 4 个），而且没有解析失败行：
            可能有钩子静默没挂上、对应文本读不到；若日志不是本次安装后产生的，请重跑一次验证。
```

### 4.3 真机级链路（副本，Steam 目录只读）

复制 `D:\Steam\steamapps\common\Build`（560.75 MB / 211 文件）到 `_hm85\game`，工作区 `_hm85-ws`：

```
detect → analyze → plan（6 个 Hook）→ generate（27 文件）→ build → install（23 文件）
install 输出：安装完成。 本补丁有 6 个钩子；另外「文本兜底轮询」也开着…
verify --speech-log <归档日志>  →  s-06 pass（计划 6 个）
verify --speech-log <合成日志>  →  s-06 fail（少 4 个），overall=partial
verify --rollback --force       →  ok=true、overall=pass_with_skips、game/a11y_platform 已删除
```

> 踩坑（已写进 research/147）：第一次跑出来的还是旧文案，因为没有重建 `src\Forge.Cli`——开发版 `forge.exe` 是单文件发布，只构建 `Forge.Verify` 不会更新它。教训：改被 CLI 引用的项目后必须重建 CLI 再验证。

## 8. 升级提示

- 已装旧版补丁的游戏：先 `forge verify --game <游戏目录> --workspace <工作区> --rollback --json`，再装本版。
- 本版不改安装格式、不改 BepInEx 离线包；重装只需替换 `app/forge.exe`。
- 旧工作区（只有 `02-decide/plan.json` 而没有改动的）可直接被本版读取，不需要重新跑 plan。
