日期：2026-11-15

## 一句话

装了补丁但还没启动游戏就点「安装后自检」，不会再被 `b-05/b-06` 的红色失败吓到——只要你在「语音日志」里指了运行日志，自检会如实说“日志改用外部文件核对”，结论是 `pass_with_skips`，不是 `fail`。

## 改了什么

### 1. `verify --speech-log` 时 BepInEx 日志缺失不再算失败

场景：用户装完补丁没启动游戏，或者把游戏日志移走/改名/清理了，但手上有运行日志（比如从别处归档的 `LogOutput.log`）。旧行为：`b-05 BepInEx 日志存在`、`b-06 BepInEx 日志关键行` 直接失败，整体 `fail`，看起来像补丁坏了。

新行为（仅当显式传了 `--speech-log`）：

| 检查 | 旧 | 新 |
|---|---|---|
| b-05 日志存在 | 失败 | **跳过**，注明“游戏自身日志不存在/为空；已指定外部语音日志，不作为失败” |
| b-06 日志关键行 | 失败 | **跳过**，注明“改由 s-01..s-03 核对外部语音日志” |
| 整体 | fail | pass_with_skips（并写一条“插件是否被游戏加载未直接核对”的未验证项） |

不传 `--speech-log` 时保持旧行为：日志缺失 = 失败，避免把“加载器崩溃/静默失败”报成通过。

### 2. 回归测试

新增 `tests/Forge.Verify.Tests/InstallVerificationTests.cs::Missing_game_log_with_external_speech_log_skips_bepinex_log_checks`：
故意删掉游戏日志、给一个外部语音日志，断言 b-05/b-06 为 Skip、s-02 为 Pass、整体 PassWithSkips。

### 3. 附带工具（仓库内，不随 GUI 打包）

`tools/ai-usability-l2.ps1`：AI/CI 一键跑「安装 → 自检/语音证据 → 回滚 → 现场检查」，输出 PASS/FAIL 与 JSON。

实测：
- Ren'Py（DDLC 副本）：7 步全 PASS；
- Unity Mono（Build 副本，561MB）：7 步全 PASS（本次修复正是由这条回归暴露的）；
- 证据：`research/63-l2-regression/`。

**未验证 / 已知边界**
- GUI 新输入框仍未用 NVDA 真人点一遍。
- 语音证据只统计日志行数，不等于用户真的听见；Tolk 缺失时补丁降级为日志输出。

- 没传 `--speech-log` 时，BepInEx 日志缺失仍会失败，这是有意的（宁可让人启动一次游戏）。
