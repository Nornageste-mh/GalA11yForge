# Gal 无障碍辅助 Demo 快速生成工具（GalA11y Demo）使用指南（v0.2.86.0）

> 这份文档写给“要玩游戏的人”，不是写给编译器。每一步都写清楚：做什么、会改哪里、出问题怎么退回来。

## 0. 一句话

Gal 无障碍辅助 Demo 快速生成工具（GalA11y Demo；Vibe Coding 产物，代码不保证稳定和可用）是一个 Windows 工具：你给它一个 Galgame 的游戏目录，它自动识别引擎、找文本出口、生成补丁、编译、安装、自检，并留下可回滚的账本。搞不定的游戏会明确告诉你“哪里需要人工”，不会假装成功。

当前可执行版本：**0.2.86.0**（BepInEx 5 与 BepInEx 6 离线包都随发布包分发，无需再自备）。
已发布目录：`releases/v0.2.86/`（只保留最新一版）（`app\forge.exe` 命令行、`gui\Forge.Gui.exe` 图形界面、`SHA256SUMS.txt`）。

## 1. 两种用法，选一个就行

### A. 图形界面（大多数人用这个）

打开 `gui\Forge.Gui.exe`，标题是「Gal 无障碍辅助 Demo 快速生成工具」。整个窗口只有三块，读屏用户全部可用 Tab 和 Alt 快捷键操作：

1. **输入区**（Alt+1/2/3/4/5、Alt+6 演练模式、Alt+7 高级分析）：游戏目录、工作区、BepInEx 包（现在可以不填，发布包自带）、forge.exe 路径、语音日志（可选，只给「安装后自检」用）、演练模式、高级分析。
2. **操作区**（Alt+字母）：识别引擎(D)、分析文本(A)、生成工程 Demo(G)、构建补丁(B)、分析报告(P)、一键(O)、安装补丁(I)、安装后自检(Y)、环境自检(V)、回滚补丁(R)、停止(X)、清空结果(L)。未知引擎：勾「高级分析」(Alt+7) → 分析文本 → **分析报告(P)**，看工作区 reports/<slug>/human-todos.md 的人工待办。
3. **结果区**：只读文本框，显示每一步的中文结果；下面是执行记录。

第一次使用建议顺序：
1. 点「浏览」选游戏目录（例如 `D:\Steam\steamapps\common\Build`）。
2. 点「环境自检(V)」——看到 ok 再继续。
3. 点「一键(O)」——识别→分析→生成→构建一次跑完。
4. 点「安装补丁(I)」——弹出确认框，默认「否」，看清楚了再点「是」。
5. 启动游戏，听声音；日志里出现 `[Speech]` 就说明朗读接上了。
   > 0.2.21 起：在「语音日志(&5)」里填游戏运行日志（BepInEx 的 `LogOutput.log`，或 Ren'Py 的 `a11y_speech.log`），再点「安装后自检(Y)」，结果区会直接给「语音证据：有效朗读 N 行…」；不填也可以，自检会找默认日志。
   > 「演练模式：只检查、不写盘」的快捷键是 Alt+6（输入区占了 Alt+1..5）。
> 0.2.29 起：勾选「高级分析」复选框（Alt+7）后，「分析文本」会自动加 `--advanced`，调用 Ghidra 做原生静态分析——只读，但会明显更慢；其它命令不会带这个参数。
6. 玩完后点「回滚补丁(R)」并按提示确认，游戏目录恢复原样。

完整人工验收步骤见 `docs/32-GUI人工验收清单.md`。

### B. 命令行（脚本/进阶用）

发布包解压后，在 `app` 目录执行（Windows 合并了“当前目录”和可执行文件目录的搜索，下面的 `forge` 就是 `app\forge.exe`）：

```powershell
# 1) 只识别（不改任何东西）
.\forge.exe detect --game "D:\Steam\steamapps\common\Build" --json

# 2) 一条龙：分析→计划→生成→构建（不写游戏目录）
.\forge.exe build --game "D:\Steam\steamapps\common\Build" --workspace "$env:LOCALAPPDATA\GalA11yForge"

# 3) 安装（会改游戏目录，自动备份）
.\forge.exe install --game "D:\Steam\steamapps\common\Build" --workspace "$env:LOCALAPPDATA\GalA11yForge"

# 4) 自检（读日志、查文件、查账本）
.\forge.exe verify --game "D:\Steam\steamapps\common\Build" --workspace "$env:LOCALAPPDATA\GalA11yForge"

# 5) 回滚 + 回滚后自检
.\forge.exe verify --game "D:\Steam\steamapps\common\Build" --workspace "$env:LOCALAPPDATA\GalA11yForge" --rollback --force
.\forge.exe verify --game "D:\Steam\steamapps\common\Build" --workspace "$env:LOCALAPPDATA\GalA11yForge" --rollback
```

`--json` 会先打印人类可读行，最后一行是 JSON 信封；脚本解析取最后一行 `{` 开头的即可。

> 想确认“补丁到底有没有读出来”：安装后启动游戏、推进几句对白，然后加 `--speech-log`：

> 提示：`--speech-log` 的相对路径按**游戏目录**解析；拿不准就传绝对路径。
> 0.2.22 起：如果游戏自身日志缺失但传了 `--speech-log`，`b-05/b-06` 会改为“跳过”而不是失败，整体是 `pass_with_skips`。
>
> 0.2.23 起：GUI 的「forge.exe 路径」留空会先找发布包布局（`gui\` 同级的 `app\forge.exe`），再找同目录、上一级、仓库产物和 PATH；发布包解压后直接打开 GUI 即可。
> `.\forge.exe verify --game "<游戏目录>" --speech-log "<游戏目录>\BepInEx\LogOutput.log"`
> 0.2.20 起会输出 `s-01 语音日志可读`、`s-02 日志里有有效朗读输出`、`s-03 朗读文本没有明显重复` 三项检查；
> 只统计条数与重复情况，不会把台词写进报告。日志里还没有朗读行时只记“未验证”，不判失败。
发布包里现在自带 `app\bepinex\BepInEx_win_x64_5.4.23.5.zip`（官方原样包，LGPL-2.1，附许可证与声明），所以 `--bepinex` 一般不用填；如果用自己的版本，加 `--bepinex <zip 路径>`。

## 2. 每个命令到底做什么

| 命令 | 会读什么 | 会写什么 | 改游戏目录吗 |
|---|---|---|---|
| `doctor` | 运行环境、适配器、可选 Ghidra、可选 BepInEx 离线包 | 无 | 否 |
| `tools` | 本机 RE 工具（Il2CppDumper / pyghidra / Frida / dnSpyEx）是否就位 | 无 | 否 |
| `detect` | 游戏目录（只读扫描） | `00-detect/detect.json` | 否 |
| `analyze` | 程序集/脚本/资源清单（只读） | `01-analyze/analysis.json` | 否 |
| `plan` | 分析结果 | `02-decide/plan.json` | 否 |
| `generate` | 计划 | `03-generate/`（可编译工程） | 否 |
| `build` | 生成工程 Demo + BepInEx 包 | `04-build/`（插件 DLL） | 否 |
| `install` | 构建产物 + BepInEx 包 | 游戏目录 + `05-deploy/`（备份、账本） | **是（有备份）** |
| `verify` | 账本、日志、备份、基线；可选 `--speech-log` 朗读日志 | `06-verify/verify.json/md` | 否（除非 `--rollback`） |
| `report` | 分析与计划 | `reports/<slug>/`（汇报给用户） | 否 |

工作区默认 `%LOCALAPPDATA%\GalA11yForge`，每个游戏一个子目录 `games/<slug>/`。
`--dry-run` 只看不做；`--force` 允许覆盖已有安装账本/强制回滚；`--rollback` 走回滚路径。

## 3. 声音是怎么来的

补丁里包含了经过验证的最小语音平台层，链路是：

```
游戏文本事件 → 生成的 Harmony 钩子 → Platform/SpeechGate（去重、空白归一、超长截断）
           → Repeat（历史缓冲/重读键） → Speech（Tolk / NVDA 直连 / 争渡 / SAPI5）
```

- 启动时自动检测读屏器：Tolk → NVDA → 争渡 ZDSR → SAPI5 → 静默（并写诊断）。
- 日志里 `[Speech] xxx` 表示这句话被送去朗读；`[Hook:...] 命中` 表示钩子触发但可能没有文本参数。
- 生成的插件配置里「详细日志」默认关闭；**要看朗读日志，把它改成 true 再重启游戏**（配置在 `BepInEx\config\<GUID>.cfg`）。
- 0.2.8 起配置里多了 `[朗读] 字段补读最长等待秒`（默认 4，0=关闭）：首句比对话框晚出现时最多再等几秒补读；怕补读到旧句就调小或设 0。
- 选项界面：会播报“有 N 个选项…按数字键选择”，按 1/2/3 选择；这是补丁自带的选择通道（有的游戏会禁用鼠标）。

## 4. 安装、卸载与回滚

- 安装前会把将被覆盖/新增的每个文件写进账本 `install-manifest.json`，并把原件备份到工作区 `backup/`。
- 回滚严格按账本逆序：先还原替换/删除的文件，再删掉新增的文件，最后清理空目录；完成后自检会核对哈希。
- 想彻底卸载：先 `verify --rollback --force`，再确认游戏目录里只剩原版文件（自检报告会列残留）。
- 游戏更新后：旧补丁可能失效，重新跑一遍 `build → install` 即可（先 `--rollback` 再装更干净）。

## 5. 当前支持范围（如实说）

| 引擎 | 识别 | 自动生成补丁 | 真机验证 |
|---|---|---|---|
| Unity Mono（BepInEx 5） | ✅ | ✅ | 2 款游戏（《五天一夜》《NEEDY 失败样本》） |
| Unity IL2CPP（BepInEx 6 + interop） | ✅ | ✅ | 1 款（硅心）：安装/19 行台词/回滚 |
| Ren'Py 6.99/8.x（覆盖层） | ✅ | ✅ | 1 款（DDLC）：主菜单/台词/回滚 |
| KiriKiri Z（吉里吉里） | ✅ | 实验性（旧版 1.2.0.3 靠 DLL 代理，研究中） | 部分（最小朗读闭环已通） |
| RPG Maker MV/MZ、WebGAL | ✅ | 预留适配器 | 未验证 |
| 其它未知程序 | 兼容模式（标准控件/可访问文本） | 不走补丁 | 部分（自绘窗口读不到，OCR 仅实验） |

**重要**：`detect` 认出来 ≠ 一定能生成朗读补丁。若计划里“没有任何带字符串参数的补丁点”，工具会明确警告“只能记录调用次数，不会朗读”，请按报告的人工待办处理。

### 5.1 IL2CPP 游戏的前置条件（很重要）

IL2CPP 游戏没有托管 DLL 可读，`analyze` 需要一份“静态类型原料”，有两条路：

1. **自动生成 dump.cs（0.2.11 起默认）**：如果游戏目录既没有 interop、也没有 dump.cs，
   `analyze` 会自动找 `Il2CppDumper.exe` 生成 dump.cs（输出到工作区，不写游戏目录），再继续分析。
   - 工具放哪：工作区 `tools/re/il2cppdumper/`、或 `forge.exe` 旁边 `tools/re/il2cppdumper/`；
   - 也可以手动指定：`--option re.il2cppdumper.path=<Il2CppDumper.exe 或目录>`；
   - 找不到工具或 dump 失败时，会明确报 `E_DEPENDENCY_MISSING`，并给三条路（装 interop / 人工 dump / 指定 dumper）。
   - 注意：该工具需要 .NET 运行时；本产品会自动设 `DOTNET_ROLL_FORWARD=LatestMajor`。它结尾的退出码不可靠，本产品按产物判定成功。
2. **interop 路线（更完整）**：在游戏里安装 BepInEx 6（IL2CPP）并成功启动一次，
   让 BepInEx 生成 `BepInEx/interop/` 程序集；之后 `analyze/plan/generate/build` 都会用它们。
   注意：换游戏版本后 interop 方法名可能失效，需要重新生成。
3. **人工 dump.cs 路线（降级）**：自己用 Il2CppDumper 生成 dump.cs，然后
   `forge analyze --game <目录> --option il2cpp.dumpPath=<dump.cs 的绝对路径>`。
   只有 dump.cs 时，计划只能做静态推断，生成的工程**只能验骨架、不保证能编译**。

> 0.2.19 起，发布包自带 `app\bepinex6\BepInEx_win_x64_6.0.0-be.788.zip`，`forge install` 不给 `--bepinex` 也会自动发现；`forge doctor` 的 `bepinex6-bundle` 项可确认它在不在。

想先检查工具在不在：`forge tools --json`（不会自动下载任何工具）。

### 5.2 IL2CPP「字段兜底」（0.2.12 起）

有些 IL2CPP 游戏的台词入口方法**没有字符串参数**（文本放在实例字段里），过去只能报“人工待办”。
0.2.12 起，`analyze` 会记录类型上的文本字段，`plan` 会为这类入口生成补丁点，`generate` 会产出
`A11y/A11yFieldReader.cs`，运行期按字段名沿继承链原生读取（不写死偏移）。

- 生成物里会多一个 `A11y/A11yFieldReader.cs`，补丁点描述会带「字段兜底」字样。
- 字段名带 `_diag/_debug/_log/status/path/key/hash/url/version/prefab` 的会被跳过，避免念调试字符串。
- 已知边界：界面装饰文本仍可能被读出（例：饰品名、文件夹页脚），因为当前只按字段名过滤、不看调用时机。
- 真机验证记录见 `docs/54`（Lilith：`[Speech:fields]` 命中 16 条、台词「周末快乐」、噪声 0 条）。


## 6. 已知限制（不是 bug，是还没做）

- 默认不打开详细日志；看不到 `[Speech]` 先检查配置。
- 三选项以上、hideMask 组合的选项界面未真机验证。
- 日文语音：本机没有日语 TTS 音色时，日语台词会退化为中文音色读或只进缓冲；不承诺“能听懂”。
- OCR 兜底仅实验性（自绘窗口、美术字体识别率很低），默认关闭。
- GUI 的 NVDA 播报已用 loopback 录音证明“有输出”，但未做“人耳逐句验收”，需要你按清单试一遍。
- Steam 游戏修改客户端可能违反 Steam 协议；默认离线单机使用，在线/反作弊游戏会被拒绝。
- 每次只支持 x64 为主；x86 老游戏（DDLC、千恋）走 Ren'Py 覆盖层或专门适配。

## 7. 常见问题

**Q：游戏更新后补丁失效？**
A：重新 `build` 再 `install`（先回滚更干净）。补丁不修改存档，但存档格式由游戏决定。

**Q：杀毒软件报毒？**
A：生成的 DLL 没有签名，可能被误报。确认来源与 SHA256，加白名单；这不是“我们藏了东西”。

**Q：听不到声音？**
A：按顺序查：①游戏是否加载了 BepInEx（`BepInEx\LogOutput.log` 有 `Loading` 行）；②配置里详细日志 true；③日志有无 `[Speech]`；④读屏器是否运行（NVDA/争渡）；⑤SAPI 是否有中文音色。

**Q：会不会改坏游戏？**
A：安装前备份+账本，回滚后逐文件核对哈希。极少数游戏更新/杀软占用会导致个别文件失败，重试或回滚即可。真出问题用 Steam「验证文件完整性」。

**Q：BepInEx 包在哪？**
A：发布包 `app\bepinex\` 自带官方 5.4.23.5 包（LGPL-2.1，见 NOTICE）；也可用自己的或用 `--bepinex` 指定。

## 8. 合规与安全边界

- 只分析本机合法安装的游戏与免费 Demo；不下载、不传播盗版资源。
- 发布物只包含代码/配置/模板，**不含游戏原始资源、台词、图片、音频**。
- 不改 exe 本体、不破解 DRM、不对在线/反作弊游戏注入。
- 生成的补丁由你本机编译、本机使用；分发成品补丁前请自行确认游戏许可与当地法律。
