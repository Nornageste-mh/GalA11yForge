# 0.2.71 发布说明：占位空文件不再骗过引擎识别

- 日期：2026-11-17
- 版本：0.2.71.0
- 上一版：0.2.70.0（初检 JSON 语音块给全 s-01..s-04）

## 1. 一句话

Unity 游戏目录里如果放着 0 字节 / 占位大小的 `UnityPlayer.dll` 或 `Assembly-CSharp.dll`，识别仍会命中 R01 拿到 0.95；现在会降级到 0.6 并写明「可能是占位/空文件，结果不可信」。

## 2. 为什么做

32 个子代理体检（research/134）复现过：两个空文件就能让 detect 报 `unity_mono 0.95`；《透明的她 Demo》正是这种目录（只有第三方模组载荷）。下游 analyze 会以 exit 4 拦住，但用户先看到的「识别成功」是误导。

## 3. 改了什么

- 新增 `src/Forge.Detection/PlaceholderBinaryCheck.cs`：`Apply(gameDirectory, detection)`，只在 `family == "unity_mono"` 时生效；`UnityPlayer.dll < 64KB` 或 `*_Data/Managed/Assembly-CSharp.dll < 4KB` 即判为占位，`Confidence = min(Confidence, 0.6)` 并追加证据行 `measured:PE 大小校验降级（… 字节）：可能是占位/空文件，识别结果不可信。`；幂等（重复调用不重复加证据）。
- `src/Forge.Detection/EngineDetector.cs`：选出 Primary 后调用该检查（所以 `forge detect` 直接受益）。
- `src/Forge.Adapters.UnityMono/Internal/UnityMonoDetector.cs`：适配器路径也调用同一个检查，不再重复实现。
- 测试：新增 `tests/Forge.Adapters.UnityMono.Tests/DetectorPlaceholderTests.cs` 两条（占位 → 0.6 且带证据；正常大小 → 保持 0.95）；`tests/Forge.Detection.Tests` 的 Unity 夹具改为真实大小（200KB / 50KB），避免夹具自己被降级。

## 4. 验证

- CLI 实测（2 字节的 `FakeGame.exe` + `UnityPlayer.dll` + `Assembly-CSharp.dll`）：
  - `family=unity_mono`、`confidence=0.6`；
  - 证据：`measured:PE 大小校验降级（UnityPlayer.dll=2 字节，Assembly-CSharp.dll=2 字节）：可能是占位/空文件，识别结果不可信。`
  - 证据文件：`research/123-detect-placeholder/detect.json`
- 全量测试：**737 通过 0 失败 0 跳过**（Core 117、Verify 72、Ghidra 72、Generators 60、Detection 30、Ren'Py 37、UnityMono 43、Build 82、Gui 168、Il2Cpp 56）
