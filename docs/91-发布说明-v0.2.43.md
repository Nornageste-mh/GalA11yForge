## 1. 这一版修了什么

**问题**：对“已识别但没有内置适配器”的引擎（如 KiriKiri），如果用户**只跑 `report`**、而且工作区里还没有缓存的分析结果，旧版会直接失败：

```
E_NOT_IMPLEMENTED：引擎 kirikiriz 的分析器尚未接线。
建议：当前可用：Ren'Py；没有适配器时请加 --advanced 用 Ghidra 做原生兜底。
```

用户按建议也做不下去——`report` 并不会自动跑高级分析，等于“让你先分析，但没告诉你 report 自己不会分析”。

**修复**：`report` 在没有缓存分析结果时，自动改走 Ghidra 高级分析（只读），再导出报告；并在 stderr 明确说明改道。

## 2. 改动清单

- `src/Forge.Cli/PipelineCommands.cs`
  - 适配器解析：`autoAdvanced` 现在对 `analyze` 与 `report` 都生效（未显式 `--advanced`、游戏根目录有 exe 时自动启用 Ghidra 兜底）。
  - 新增公共方法 `AnalyzeWithOptionalGhidraAsync(...)`，统一“先分析、需要时再跑 Ghidra、写回 analysis.json”的流程。
  - `RunReportAsync`：缓存分析缺失时走上面的公共方法，并打 stderr 说明。
- `tests/Forge.Core.Tests/AdapterlessAnalyzeAutoAdvancedTests.cs`
  - 新增 `Report_WithoutCachedAnalysis_AutoRunsGhidraAnalysis`：空工作区 + `report --dry-run --json` 断言 exit 0、dry-run 输出、stderr 含改道说明。

## 7. 升级方法

1. 解压覆盖 `app\forge.exe` 即可（GUI 未改动，可沿用）。
2. 跑一次 `forge version` 确认是 `0.2.43.0`。
3. 旧工作区的 `analysis.json` 仍可复用；想强制重跑就换一个新工作区。

## 8. 已知问题

- `releases/v0.2.23` 的空 `gui` 目录被某进程占用，删不掉（不影响使用，后续再清）。
- Ghidra 高级分析对大 exe 可能超时；用 `--option ghidra.timeoutSeconds=<更大值>` 或指定更小的 exe。
