## 1. 本版做了什么

### 1.1 IL2CPP 自动生成 dump.cs（主线）

**问题**：0.2.10 的 IL2CPP 分析要求用户先具备两样之一——BepInEx 6 生成的 `BepInEx/interop`，或手工准备好的 `dump.cs`。前者要装 BepInEx 并启动一次（约 229 秒），后者要用户自己去跑第三方工具。对“甲方+测试”来说这两步都太重。

**做法**：
- `Il2CppOptions` 新增 `autoDump`（默认开）、`dumperPath`。
- 新增 `src/Forge.Adapters.Il2Cpp/Internal/Il2CppAutoDumper.cs`：
  校验 `GameAssembly.dll` + `global-metadata.dat` → 按 `re.il2cppdumper.path` / 工作区 / 程序旁找 `Il2CppDumper.exe` → 输出到 `<工作区>/games/<slug>/il2cpp-dump/`（不写游戏目录）→ 10 分钟超时 → 按 `dump.cs` 存在且 ≥100KB 判成功。
- `Il2CppAdapter.AnalyzeAsync`：无 interop、无 dump.cs 时先自动 dump；成功则继续分析，并在 `unverified` 里注明“自动产物未人工核对”；失败返回带 details 的 `E_DEPENDENCY_MISSING`，给三条路（interop / 人工 dump / 指定 dumper）。
- 实测坑已处理：Il2CppDumper 6.7.46 目标 .NET 6 → 自动设 `DOTNET_ROLL_FORWARD=LatestMajor`；结尾 `Console.ReadKey` 退出码异常 → 以产物判定成功。

**真机验证**：SiliconHeart 只读目录 → 20.0 秒生成 17.4MB `dump.cs` → 40 个候选，`ok=true`；游戏目录 0 改动。

### 1.2 `forge tools`

- 检查 5 件 RE 工具：Il2CppDumper（MIT）、pyghidra（Apache-2.0）、Frida（wxWindows 3.1）、frida-il2cpp-bridge（MIT）、dnSpyEx（GPLv3）。
- 输出：是否找到、路径、版本、许可证、下载地址、放置提示；不自动下载、不安装。
- 支持 `--option re.<id>.path=<exe 或目录>` 指定；与自动 dump 共用同一套工具发现顺序。

### 1.3 三路研究结论（docs/52）

- `research/49-re-toolchain`：Il2CppDumper 本机可用（SiliconHeart dump.cs 18,195,590 B / 530,195 行 / 9,301 类）；pyghidra 与 Ghidra 12.1.4 兼容；Frida/dnSpyEx 版本与许可证实测。
- `research/50-il2cpp-field-fallback`：IL2CPP 字段兜底——反射路线不可行（interop 只有 `static NativeFieldInfoPtr_*`），原生字段 API 路线可编译但未真机读数；只验 2/5 样本，故本版不发。
- `research/51-frida-dynamic`：Frida attach 成功、枚举 64 程序集/13,595 类、读静态字符串；适合研究，不随包。
