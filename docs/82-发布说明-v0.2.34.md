## 1. 本版做了什么

### 1.1 未知程序：主程序不在根目录也能跑高级分析

Ghidra 高级分析以前只在「游戏目录根层」找 `.exe`。很多游戏（尤其带 `bin\`、引擎子目录、合集型安装）根层没有 exe，会直接报 `E_ARTIFACT_MISSING`「游戏目录下没有找到可分析的可执行文件」。

现在：
- 根层没有 exe 时，**向下搜 2 层子目录**（常见 `bin\game.exe`、`Game\Game.exe` 布局）；
- 过滤安装器/卸载器/崩溃报告器（unins/setup/install/vcredist/dxsetup/crash/report/helper/update/launcher/config）与无关目录（_CommonRedist/redist/dotnet/directx/crash/install/tools）；
- 候选排序：**exe 名与所在目录/游戏目录同名优先** → 层级浅优先 → 体积大优先 → 名字序。

这一改的直接动机：本机《To the Moon》的 exe 在 `To the Moon\To the Moon.exe`，根层只有子目录，旧版连分析入口都找不到。

### 1.2 修一个默认超时不一致

`GhidraBackendOptions` 类默认 `TimeoutSeconds=600`，但 `FromProfile()`（CLI 实际走的路径）回退值是 **240**。结果：配置里不写超时，实际只给 240 秒，大 exe 更容易被误判超时。现统一为常量 `DefaultTimeoutSeconds=600` / `DefaultAnalysisTimeoutSeconds=900`，并补单测锁住。

## 2. 测试

全解决方案 **671 通过 / 0 失败 / 0 跳过**：
Core 98、Verify 69、Detection 30、Generators 59、Ren'Py 37、UnityMono 31、Build 80、Gui 152、Il2Cpp 55、Ghidra 60。

本版新增 5 个 Ghidra 测试：
- 根层无 exe → 子目录找到；
- 根层有 exe → 优先根层；
- exe 名与目录同名 → 压过更大的兄弟 exe；
- 超过 2 层 → 不选（诚实失败）；
- 默认超时 = 600/900。

| 游戏 | 引擎 | 修复前 | 修复后 | 结果 |

## 6. 升级建议

直接覆盖解压。高级分析入口在 CLI `analyze --advanced` 与 GUI「高级分析」勾选；本版不改补丁生成/安装链路。
