> 状态：开发中（2026-11-15 17:3x）。上一版 0.2.18.0 已发布，643 测试全绿。
> 17:27 更新：Ren'Py 确认框真机尝试因用户正在用电脑而中止（记录见 `research/57-renpy-confirm-verify/README.md`），改日空闲再补；GUI 读屏复验同样需要用户在场。
> 17:45 更新：用户 17:29 排队消息已执行——SiliconHeart interop 复验完成（见 `docs/50` §11）、ntre-recover 8GB 已清（D 盘 14.23GB）、Round A 按“自动化测试优先”排队；真机复核流程已固化为 `docs/64-真机复核操作手册-v0.md`。KKZ 真机闭环仍未明确授权。
> 原则：先做能验证的、不打扰用户的操作；需要占用用户电脑/游戏窗口的验证，等用户不用电脑时再排。

## 1. 本版目标（按优先级）

1. **补上 Ren'Py 两处真机验证缺口**（确认框 / 退出确认；选项上方的题目）。
   - 现状：代码与单测已完成（0.2.16），真机只在 DDLC 存档提示屏上看到「选项 2 个…」，没有走到确认框。
   - 验收：DDLC 副本上触发 Quit 确认框，日志出现「确认：…」播报；选项题目在真实选项屏出现「提示：…。选项 N 个」。
   - 前提：游戏窗口在最前、用户不用电脑。

2. **GUI 人工读屏复验**（NVDA 实测）。
   - 现状：GUI 有 141 条自动测试；自动读屏探测只在后台验证过控件名，没做真人听读。
   - 验收：用 NVDA 开 GUI，逐按钮 Tab 一遍，确认名称可读、顺序合理、忙碌态/结果区可读；截图 + 读屏日志归档。

3. **发布 0.2.19.0**（如果上面两项完成或明确降级为“未验证”），保持 0.2.x 版本节奏。

## 2. 非目标（本版不做）

- SiliconHeart 装 BepInEx6 生成 interop：需要用户明确授权（会改游戏目录）。
- KKZ（千戀萬花）真机闭环：需要授权 + 有风险，继续搁置。
- 日文 TTS / OCR 精度提升：仍是“不承诺”区域。
- 可用性测试 Round A 的执行：只出方案（见 docs/63），等用户决定预算与时间。

## 3. 风险与预案

| 风险 | 预案 |
|---|---|
| 用户一直在用电脑，占不到窗口 | 先做只读检查、文档与 GUI 离线项；真机项顺延，不硬抢 |
| DDLC 确认框在无鼠标/触屏路径下难触发 | 用键盘聚焦 Quit 后回车；若仍不行，记录“仅单测”并降级声明 |
| GUI NVDA 复验环境不熟 | 用 `forge doctor` 与现有 UIA 树；必要时请用户人工听一遍 |
| 磁盘紧张（D 盘 6.18GB） | 发布物按 docs/60 保留最近 5 版；实验临时目录用完即删 |
