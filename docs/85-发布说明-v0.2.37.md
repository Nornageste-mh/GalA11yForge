# GalA11y Forge 0.2.37.0 发布说明

- 发布日期：2026-11-16
- 上一版：0.2.36.0
- 发布目录：`releases/v0.2.37/`
- 性质：未知程序能力补强（高级分析可预期性）

## 1. 这版解决什么问题

Ghidra 分析大程序可能要跑几分钟到十几分钟，但用户点下去只看到“在跑”，不知道**到底要等多久**，
超时了也不知道该把 `ghidra.timeoutSeconds` 调到多少。这版把这件事变成可预期：

1. 产物 `analysis-ghidra.json` 与 JSON `data.ghidra` 新增：
   - `executableSizeBytes`：这次分析的可执行文件大小（超时路径以前是 0，现在也会写入）。
   - `estimatedSeconds`：按文件大小粗估的耗时（秒）。
2. 超时/取消/非零退出时，人类输出与 `suggestion` 会追加：
   「按文件大小粗估，分析这枚 exe 大约需要 N 秒/分钟；超时不够时可调 --option ghidra.timeoutSeconds=<更大值>。」
3. 新增 `GhidraDurationEstimator`：`30 秒启动 + 85 秒/MB`，夹在 30–3600 秒之间。
   只用于提示，**不参与任何通过/失败判定**。

## 2. 真机证据（只读）

SenrenBanka（KiriKiri，4,583,168 B exe），Ghidra 12.1.4：

| 版本 | 命令 | 结果 |
|---|---|---|
| 开发版 | `analyze --advanced --option ghidra.timeoutSeconds=8` | `status=timeout`、`size=4583168`、`estimated=402`、`elapsed=30.1s` |
| 发布版 `releases/v0.2.37/app/forge.exe` | 同上 | `status=timeout`、`size=4583168`、`estimated=402` |

人类输出节选：

```
[部分完成] 分析未完成：0 个文本候选（Ghidra 高级分析失败，结果不完整）。
  [高级分析] Ghidra 分析超时（30s），已终止进程树；结果不完整，日志见 work 目录。
  按文件大小粗估，分析这枚 exe 大约需要 402 秒；超时不够时可调 --option ghidra.timeoutSeconds=<更大值>。
```

证据目录：`research/78-ghidra-duration-estimate/`（CLI 输出、两版产物、复现命令）。

## 5. 已验证 / 未验证

已验证：开发版与发布版在同一游戏上的超时路径（size/estimate 写入、人类提示出现）；全量测试；版本冒烟。

未验证：
- 未用“小 exe 完整成功”场景复测（成功路径不产出 estimate，真实耗时已有 `elapsedSeconds`）。
- 粗估公式只是经验值，未在更多引擎/更大样本上校准；不能当承诺。
- GUI 未加 estimate 展示（本版只有 CLI/JSON 层；GUI 已能显示报告，但没专门显示预计耗时）。

## 6. 升级

- 替换 `app/forge.exe` 即可；GUI 与 BepInEx 包未变。工作区、账本、产物格式向后兼容。
- 新字段是增量的：旧工具忽略 `estimatedSeconds` 不受影响。

## 7. 合规

- 本版不含游戏资源、台词、图片、音频；只新增代码与提示。
- Ghidra 不随包；BepInEx 5/6 按 LGPL-2.1 原样随包并附 NOTICE。
