# 0.2.46 发布说明：Ren'Py 无障游戏的真机回归变成一条命令

- 版本：`0.2.46.0`
- 日期：2026-11-16
- 上一版：`0.2.45.0`（自造最小 Ren'Py 样本抓出并修掉三处真问题）
- 本版性质：**质量基础设施版**。产品行为与 0.2.45 完全一致，新增的是「怎么证明它真的能用」的自动化。

## 1. 一句话

以前验一次 Ren'Py 覆盖层，要人肉点开始、点推进、点选项、截图、看日志；现在一条命令跑完并给出 PASS/FAIL 与证据文件。

## 2. 交付内容

新增 `tools/renpy-minimal-e2e.ps1`（仓库内回归脚本，不随发布包分发）：

```
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\renpy-minimal-e2e.ps1
```

它做这些事，全程无人值守：

1. 清掉上一次的覆盖层与工作区，重新 `forge install`（安装覆盖层）；
2. 用 WMI 启动最小 Ren'Py 样本（`_renpy-mini`）；
3. 真实鼠标点击「开始游戏」→ 推进对白 → 等选项屏 → 点「去公园」→ 等确认框；
4. 断言：题干与选项分离、选项编号正确、确认框整屏播报、`[A11y错误]` 计数为 0；
5. `forge verify --rollback --force` 回滚，并断言覆盖层已清干净；
6. 写 `summary.json` + `progressive.log` + `install.json` + `rollback.json` + `a11y_speech.log` + `a11y-lines.txt`。

## 4. 自动化踩到的三个坑（已写进脚本注释）

1. **`Start-Process` 启动 GUI 游戏会继承父进程 stdout 管道**：父命令等不到 EOF，整个命令一直挂着。
   改用 WMI `Win32_Process.Create`。
2. **`PostMessage` 投键盘/鼠标消息对 Ren'Py（SDL）无效**：菜单按钮不响应。
   必须用真实输入 `SetCursorPos` + `mouse_event`，且先用 `AttachThreadInput` 把窗口真正置前台。
3. **点击生效有数秒延迟**：固定「点一下、等固定秒数」会错位（第一句被顺带推进掉）。
   改成状态机：每轮先看当前累计日志是否已满足，不满足才点一下再等。

## 6. 已验证 / 未验证

已验证：

- 开发版与两版发布版 exe 都能一条命令跑完最小 Ren'Py 样本的「安装 → 朗读 → 选项 → 确认框 → 回滚」，PASS 可重复；
- 回滚后 `game/a11y_platform` 被清干净，工作区账本正常。

未验证：

- **没有人耳听辨/ASR**：只证明文本交给了 SAPI 桥、`wscript.exe` 起了进程、日志零错误；
- 确认框只验证整屏播报，**没有验证「点确认按钮真的触发动作」**；
- 只覆盖 Ren'Py 6.99（DDLC 引擎副本）；Ren'Py 8.x 有真实游戏证据但没有这套自造样本；
- 脚本用固定客户区坐标，换窗口尺寸/换样本要改坐标。

## 7. 升级提示

- 产品行为与 0.2.45 一致，已装 0.2.45 的用户**不必升级**；要复跑回归的同学拉本目录仓库即可。
- 脚本只对**实验副本**用，不要指向 `D:\Steam\steamapps\common` 里的真实游戏（它会安装并回滚覆盖层）。
