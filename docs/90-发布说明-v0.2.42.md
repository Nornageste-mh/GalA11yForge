# 0.2.42 发布说明：CLI 的 analyze 对“无适配器引擎”也会自动改用高级分析

- 发布目录：`releases/v0.2.42/`
- 日期：2026-11-16
- 测试：**700 通过 / 0 失败**

## 1. 这版解决什么问题

0.2.41 把“无适配器引擎自动高级分析 + 报告”接进了 GUI 一键；
命令行用户仍然要先知道 `--advanced` 这个开关，否则 `analyze` 会直接报：

```
识别为 kirikiriz，但该引擎的适配器尚未接线（当前已内置：unity_mono、unity_il2cpp、renpy）。
建议：…可先用 analyze --advanced 跑 Ghidra 静态分析…
```

对方是第一次用、又不熟悉工具时，这行提示等于“自己去找开关”。

0.2.42 起，命令行的 `analyze` 遇到下面条件会**自动改走 Ghidra 高级分析**，并在 stderr
用人话说明改道：

- 该引擎没有内置适配器（已识别，或未识别）；
- 游戏根目录确实存在 `.exe`（空目录/无 exe 仍诚实报 `E_ENGINE_UNSUPPORTED`）；
- 本次没显式传 `--advanced`（传了就按原样执行，不会重复提示）。

分析结果的 JSON 里新增 `data.autoAdvanced`，脚本可据此判断这次是否自动降级。

## 2. 改了什么（技术）

- `src/Forge.Cli/PipelineCommands.cs`
  - 适配器解析：`autoAdvanced` 标记 + 放宽“根目录有 exe”条件；
  - `AnalyzeAsync`：`options.Advanced || resolved.AutoAdvanced` 时走 Ghidra 空结果 + 后续合并路径；
  - `RunAnalyzeAsync`：改道时向 stderr 打一行说明；JSON `data.autoAdvanced`。
- 测试：`tests/Forge.Core.Tests/AdapterlessAnalyzeAutoAdvancedTests.cs`
  - 有 `data.xp3`+`game.exe` → `autoAdvanced=true`、`ghidra.status=dry_run`、stderr 含改道说明；
  - 只有 `mystery.exe` 的未知目录 → 同样自动降级；
  - 没有 exe 的目录 → 仍 `E_ENGINE_UNSUPPORTED`（不假装能分析）。
  - Core 101 通过；全量 700。

- 真实游戏 `analyze --advanced` 路径未变：仍是 0.2.34/0.2.35 的 Ghidra 行为（本次只改“自动降级入口”）。

## 6. 升级提示

- 解压覆盖整个 `v0.2.42` 目录。
- 如果你的脚本依赖 `analyze` 在“无适配器引擎”上返回 `E_NOT_IMPLEMENTED`，请改为检查
  `data.autoAdvanced` 或直接读报告；这是有意的行为变化。
- 想关掉自动降级：显式加 `--advanced`（保持原路径）或让工具找不到 Ghidra
  （`GALA11Y_GHIDRA_HOME` 指向不存在路径），此时会自动退回诚实失败/部分结果。
