# 版本库与协作规范（v0）

- 建立时间：2026-11-18
- 目的：把「已经能跑的产品」纳入 Git 管理，后续每轮增量可回退、可对比，避免再出现「脚本把文件写空、没有历史可恢复」这类事故。

## 1. 仓库里有什么、没有什么

工作区根目录还住着其它项目与运行产物，所以仓库**只跟踪本项目**：

| 跟踪 | 不跟踪（.gitignore） |
|---|---|
| `src/`（产品源码、模板、实验工程） | `releases/`（发布包，按 docs/60 保留策略管理） |
| `tests/`（单元/集成测试） | `research/`（证据与快照，体积大、按需归档） |
| `docs/`（方案、发布说明、口径、打回预案） | `**/bin/`、`**/obj/`、`**/TestResults/`（构建产物） |
| `tools/` 下的脚本与文本 | `tools/ghostlock/`、`tools/mtkclient-main/` 等其它项目 |
| `README.md`、`AGENTS.md`、`.gitignore` | `tools/bepinex*/*.zip`（第三方二进制）、`tools/_tmp*`、`tools/mail/_outbox*` |

基线：0.2.82 提交 `95ec572`，999 个文件、约 8.5MB 工作区、`.git` 约 3.5MB。

## 2. 提交规范

- 一个提交只做一件事；标题用中文，句式「区域: 做了什么」，例如 `il2cpp: 插件版本号跟随工具版本`；
- 提交前必须：`dotnet build src/GalA11yForge.sln -c Release` 0 警告、`dotnet test src/GalA11yForge.sln -c Release` 全绿；
- 发布相关改动（版本号、golden、发布说明）单独提交，并在正文写发布版本与校验和；
- 不提交任何游戏资源、台词文本、日志原文（只放 research/ 并按需归档）。

## 3. 分支约定（当前单人开发）

- `main`：始终可构建、可发版；每轮增量直接提交，发版打 tag `v0.2.x`（可选，后续补）；
- 大改（如 IL2CPP 字段兜底、MCP 连接器）用短分支 `feat/xxx`，跑通测试再合回 `main`；
- 回退优先用 `git revert`，不用 `reset --hard` 抹历史。

## 4. 常用命令

```powershell
# 构建
& D:\dotnet\dotnet.exe build src\GalA11yForge.sln -c Release
# 全量测试
& D:\dotnet\dotnet.exe test src\GalA11yForge.sln -c Release
# 重生成 golden/证据（改模板后）
$env:FORGE_UPDATE_GOLDEN='1'; $env:FORGE_WRITE_EVIDENCE='1'
& D:\dotnet\dotnet.exe test tests\Forge.Generators.Tests -c Release
# 发版
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\release.ps1 -Version 0.2.x.0 -SkipTests
```

## 5. 安全边界（不因有 Git 而放松）

- `D:\Steam\steamapps\common\**`：默认只读；需要真机验证时安装→验证→**必须回滚**并检查 `BepInEx`/`doorstop_config.ini`/`winhttp.dll` 残留；
- 不修改工作区以外的文件；不删除工作区根目录；
- 邮箱授权码、NVDA 客户端等敏感/第三方二进制不入库。
