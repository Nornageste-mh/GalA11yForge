# 发布说明 · v0.2.84.0（2026-11-18）

## 1. 一句话

`verify --speech-log` 现在会数日志里的 `[Hook] 已挂载` 与「解析目标时出错」行：**某条钩子没挂上会被判失败**，不再出现「日志里明明写着 Ambiguous match，初检却说通过」。

## 2. 为什么做

0.2.83 修了「同名重载导致整条钩子挂不上」的根因（生成期按证据里的形参类型在运行期挑唯一重载）。但验证侧还有一条缝：

- 真机现场（research/106）：《Mystery Lover》装 0.2.55 后，6 个钩子只挂 5 个，日志里写着 `Ambiguous match found.`。
- 而 `verify --speech-log` 只看「有没有朗读行」——只要兜底轮询还在念，就可能给出「有朗读、通过」的结论，把「少挂一个钩子」藏起来。
- 同类成因不止重载：目标方法被裁剪、类型名写错、插件版本不匹配，都会在日志里出现「解析目标时出错」。这类信号应该被单独报出来。

## 3. 改了什么

| 文件 | 改动 |
|---|---|
| `src/Forge.Verify/SpeechLogInspector.cs` | 摘要新增 `HookMountedLines`（`[Hook] 已挂载` 行数）与 `HookResolveErrorLines`（`AmbiguousMatchException` / `Ambiguous match` / `解析目标时出错` / `无法解析目标`）；两条编译好的正则 |
| `src/Forge.Verify/Internal/SpeechLogChecks.cs` | 新增指标 `speechHookMountedLines`、`speechHookResolveErrorLines`；新增检查 **s-06「钩子没有解析失败」**：没有钩子相关行 → Skip（Ren'Py / 纯兜底）；有解析失败行 → **Fail（P1）**；只有挂载行 → Pass |
| `tests/Forge.Verify.Tests/SpeechLogInspectorTests.cs` | `Counts_hook_mounted_and_resolve_error_lines`：2 条挂载 + 1 条解析失败 + 1 句朗读 → 2/1/1 |
| `tests/Forge.Verify.Tests/InstallVerificationTests.cs` | `Speech_log_with_hook_resolve_error_fails_s06`（s-06 Fail、overall=partial）；`Speech_log_with_only_mounted_hooks_passes_s06`（s-06 Pass、pass_with_skips） |

s-06 的失败文案会把「已挂载几个」一起说出来，并提示去看 0.2.83 起新增的 `[Hook:resolve]` 行——那一行会写明「有几个同名重载、按证据里的参数类型选中的是哪一个」。

## 4. 验证

### 4.1 真实归档日志（Unity Mono《Build》，0.2.51 时期插件产物）

日志：`research/91-watcher-live/LogOutput.log`（10,922 B、180 行，6 条 `[Hook] 已挂载`、钩子命中 0、兜底轮询 53 行）。

在《Build》副本上安装补丁后执行 `verify --speech-log`：

```
overall = pass_with_skips
s-01 pass   10,922 B，180 行，完整读取
s-02 pass   有效朗读 49 行，去重后 44 行，占位噪声 0 行
s-04 skip   钩子命中 0 行、兜底轮询读到 53 行：可能全部来自兜底轮询
s-05 pass   没有发现 [A11y错误] 或 Exception 行
s-06 pass   钩子已挂载 6 个，没有解析失败行
s-03 pass   有效朗读 49 行，去重后 44 行（同一句最多重复 3 次）
metrics: speechHookMountedLines=6, speechHookResolveErrorLines=0
```

### 4.2 合成失败日志（真实日志 + 一行真实错误格式）

追加：`[Hook] Utage.SystemUiDialog1Button 解析目标时出错：Ambiguous match found.`

```
overall = partial
s-06 fail   日志里有 1 行钩子解析失败（Ambiguous match / 解析目标时出错），已挂载 6 个：
            可能有补丁点没挂上、对应文本读不到；0.2.83 起应看 [Hook:resolve] 行确认挑到了哪个重载。
```

这正是 0.2.55 在《Mystery Lover》上出现过、但过去 verify 不报的情况。

副本上 `install` → 两次验证 → `verify --rollback --force` 全部成功；回滚后游戏目录干净、账本 `rolledBack=true`；副本与工作区已删。

已验证：

- 749 全量测试。

未验证（诚实边界）：

- 归档日志来自《Build》副本的旧插件版本，**不是**《Mystery Lover》`hook_002` 的现场日志；合成失败日志是「真实日志 + 一行错误」，不是完整真机复现。
- s-06 只判断「日志里有没有解析失败行」，**不核对「计划里应有几个钩子」**——计划钩子数与日志挂载数的对照留给后续版本。
- 《Mystery Lover 2》的 Utage 正文链仍未拿到用户回发的实机日志（用户侧验证仍未闭环）。
- GUI 本版仅版本号变化，未重跑 GUI 手工验收（Gui 168 单测通过）。

## 8. 升级提示

- 已装旧版补丁的游戏：先 `verify --rollback`，再装本版；回滚后账本标记 rolledBack，可直接重装（无需 `--force`）。
- 装完游戏后跑一次带 `--speech-log` 的验证：能一眼看出「钩子挂了几个、有没有解析失败、朗读到底来自钩子还是兜底」。
- 日志路径建议传**绝对路径**（相对路径先按当前目录、再按游戏目录解析，0.2.82 起）。
