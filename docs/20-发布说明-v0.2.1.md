# GalA11y Forge 0.2.1 发布说明（定稿，2026-11-14）

> 版本：`0.2.1.0`
> 版本纪律：按用户 2026-11-14 邮件要求，后续版本统一在 `0.2.x` 上叠加（0.2.1、0.2.2、…），不使用 0.3/1.0。

## 1. 一句话

0.2.1 是 0.2.0.0 之后的第一个修正+补全版本：把「初检可能假通过」「回滚会留运行期垃圾」「Ren'Py 补丁默认无声」「第二款游戏不能注入却照样生成」四类真问题修掉，并把选项朗读/数字键选择、WinForms GUI、Unity IL2CPP 适配器、加载器兼容性预检并入主线。

## 2. 本版改了什么（相对 0.2.0.0）

### 2.1 初检（verify）变严，不再假通过

- 游戏日志不存在或为空时，b-05/b-06 直接判 **失败**（此前会 skip 成 pass_with_skips）；文案明确「启动一次游戏后重跑；这不等于通过」。
- 识别并报告 BepInEx 预加载器崩溃日志（游戏根目录 `preloader_*.log`），避免「补丁根本没加载」被当成通过。
- 结论文案纪律：通过 / 部分通过 / 有未验证项（不等于通过）/ 未通过 四种说法固定，不再混用。
- 新增「无文本钩子警告」：计划里没有任何带 `System.String` 参数的补丁点时，plan/generate/build/install/report 都会打印警告——生成物只能计数，不会朗读。

### 2.2 回滚（rollback）自动清理运行期残留

- 安装时把 BepInEx 白名单区域（cache/config/patchers/根日志）的既有文件记进账本 `BepInExBaseline`；回滚只删「不在基线、也不是本次新建树」的文件，安装前已有的配置文件与旧日志保留并在 rollback.json 记 `skippedRuntimeArtifacts`。
- 新增安装前基线 `games/<slug>/05-deploy/baseline.json`（路径/存在性/大小/SHA-256）：`verify --rollback` 自动加载并核对 m-07，能证明原文件未被改；缺基线仍 skip，不冒充通过。
- 路径全部过 PathGuard；基线枚举失败宁可只警告不删。

### 2.3 Ren'Py 桥默认无声修复

- 症状：DDLC 上补丁确实调用了 SAPI（126 条），但实际没声音（音频端点峰值 0.000）。
- 原因：`a11y_say.vbs` 用异步 `sapi.Speak text, 3`，wscript 0.77 秒退出，声音被系统取消。
- 修复：改同步 `sapi.Speak text`，A/B 峰值 0.000 → 0.491、wscript 存活 7.79 秒；32/64 位正常。
- 顺带：`uninstall.ps1` 干净卸载时删除 `deploy_plan.json`，不再留垃圾。

### 2.4 选项朗读与选择通道（已真机验证）

- 新识别：补丁点签名含 `ChoiceAsset` 时，生成 `Platform/ChoiceReader.cs` 与专用 hook（`Postfix(object[] __args, object __instance)`）。
- 行为：选项出现时播报「有 N 个选项。选项1：…；…。按数字键选择。」；数字键 1/2/3 通过反射调用 `ButtonN.onClick.Invoke()` 完成选择（该游戏选项界面禁鼠标、只绑手柄，所以补丁自带选择通道）；选完播报确认并恢复剧情朗读。
- 选项回显台词按 hash 抑制，避免二次朗读。
- 真机验证（《五天一夜》，`research/27-choice-e2e/REPORT.md`）：2/2 次选项出现均读到并播报；按 1、2 各一次都真的选中，选项 UI 消失、后续剧情走不同分支；回滚后精确复原 211 文件/21 目录、无 BepInEx 残留。
- 顺带修：选项句末标点不再出现「？。」连写；选项钩子增加 `[Hook:choice]` 命中日志。

### 2.5 WinForms GUI 并入主线

- 新增 `src/Forge.Gui`（界面）+ `src/Forge.Gui.Core`（可测逻辑）+ 138 个 GUI 测试，已进 sln。
- 三区界面、全中文可读名、显式 TabIndex、Alt 助记符、忙碌禁用、安装/回滚二次确认（默认「否」）、失败自动聚焦结果区。
- 尚未用 NVDA 做正式播报验收（见 §4）。

### 2.6 Unity IL2CPP 适配器并入主线

- 新增 `src/Forge.Adapters.Il2Cpp`（47 测试）并接入 CLI：`detect` 识别 unity_il2cpp；有 BepInEx6 interop 时静态分析出候选，`generate` 产出 BepInEx6/net6.0 可编译工程；只有 dump.cs 时写骨架并返回 `E_PARTIAL`（诚实降级，不假装可朗读）。
- 没有 interop/dump.cs 时 `analyze` 返回 `E_DEPENDENCY_MISSING` 并给出两条可行路径（装 BepInEx6 首启生成 interop，或用 Il2CppDumper 的 dump.cs + `--option il2cpp.dumpPath=…`）。
- IL2CPP 的 install/朗读尚未接（明确 `E_NOT_IMPLEMENTED`），真机验证进行中（见 §4）。

### 2.7 第二款 Unity Mono 游戏失败分析与诚实闸门

- 《NEEDY GIRL OVERDOSE》真机 E2E 失败，报告 `research/22-second-game/REPORT.md`：选点层（钩子无字符串参数→只计数）、构建层（该作 InputLegacyModule 裁剪掉 `anyKeyDown`）、加载层（该作 mscorlib 裁剪掉 `Module.GetPEKind`，BepInEx 5 预加载器崩溃且无日志）三层问题。
- 由此加了两个「诚实闸门」：其一，无文本钩子警告（§2.1）；其二，加载失败日志检测（§2.1）。
- 回滚仍然干净（1059 文件 = 1058 基线 + 游戏自建 settings.es3）。

### 2.8 加载器兼容性预检（新）

- 新增 `LoaderCompatProbe`：读 `*_Data/Managed`，检查 mscorlib 是否有 `Module.GetPEKind`、InputLegacyModule 是否有 `Input.anyKeyDown`，给出 `supported/degraded/unsupported/unknown` 四态。
- `detect` 人类输出与 `--json` 都带 `loaderCompat`；`build`/`install` 前对 Unity Mono 强制预检：`unsupported` 直接拒绝（`E_ENGINE_UNSUPPORTED`，附证据与"换 BepInEx6/MelonLoader 也实测不可行"说明），`degraded` 打印警告。
- 真机依据：`research/26-loader-compat/REPORT.md`（NEEDY 判 unsupported 与真机崩溃 100% 一致；《五天一夜》判 supported 与真机正常加载一致）。
- 顺带：部署后哈希校验增加短暂重试（真机首次安装偶发 `.doorstop_version` 被占用导致的瞬时失败，不再误触发自动回滚）。

## 5. 分发与合规

- 结构优先：本版只分发「生成器 + 运行时组件 + 适配脚本」，**不**分发任何游戏的补丁成品、diff、游戏资源或台词。
- 随包第三方：Tolk（LGPL-3.0）、nvdaControllerClient（LGPL-2.1）、BepInEx（LGPL-2.1）等按 `docs/10-合规与保护边界-v0.md` 执行；争渡/SAAPI 等专有组件不随包，检测到用户本机已有才调用。
- 首次启动提示：默认离线单机；检测到在线/反作弊场景停止注入；不绕过 DRM。
- 校验和：见 §7（发布目录内文件的 SHA-256）。

## 6. 升级说明

- 从 0.2.0.0 升级：直接替换程序即可；旧工作区可用 `forge verify` 复检，建议对旧安装执行一次 `forge verify --rollback --force` 后再用新版安装。
- 旧账本没有 `BepInExBaseline`/`baseline.json`：回滚清理与 m-07 会走保守分支（skip/未验证），不会误删；重新安装一次即可获得完整基线。
