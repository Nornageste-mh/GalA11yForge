# 0.2.49.0 发布说明：没有正文入口时，不再“装成功”骗人

日期：2026-11-16 · 版本：0.2.49.0 · 测试：710 通过 / 0 失败

## 1. 一句话

用户反馈「装完补丁没有剧情朗读」之后补的两道防线：分析报告不再掺别款游戏的话；计划里没有已识别的正文入口时，CLI 明确提醒，安装默认挡住（要冒险得自己加 `--force`）。

## 2. 问题是怎么发现的

0.2.48 修完《Mystery Lover 2》（Utage）的正文入口识别后，我回头翻它 0.2.46 装补丁时的旧产物（`%LOCALAPPDATA%\GalA11yForge\games\mystery-lover-2`），发现两处会继续误导用户：

1. `analysis.json` 的 `coverage.manualTodo` 与 `unverified` 里写着「DOText→HandleMessageText→AnimateText」「选项回显延迟运行期实证约 67.7/416.2 秒」——那是早期在《五天一夜》等 Unity 游戏上取证的文案，被硬编码成了通用分析器的话术。用户看报告会以为分析器在说他的游戏。
2. 退一步说，就算计划里一个正文入口都没有（只有系统对话框、工具提示），`forge install` 仍然安装成功、写账本、报「安装完成」。用户装完进游戏才发现一句台词都不读——这比报错更糟。

## 3. 根因

- 分析器把“跨作品通用的取证经验”写成了常量字符串，直接进了每份报告。
- 计划里“有没有正文入口”这件事没有结构化表达：`PlanRoute`、`Risks`、`ManualTodo` 都没有这个概念，CLI 无法据此判断“这份计划大概率读不到剧情”。

## 4. 改了什么

| 改动 | 位置 |
|---|---|
| 人工待办按本次候选动态生成（列出本作识别到的正文入口；没识别到就直说需要人工补） | `src/Forge.Adapters.UnityMono/Internal/UnityMonoAnalyzer.cs` `BuildCoverage` |
| 未验证项去掉别款游戏的方法名与秒数 | 同上 `BuildUnverified` |
| 新增 R-106「没有正文入口」识别器 | `src/Forge.Core/Models/PlanQualityInspector.cs` |
| plan 打 `[注意]`、JSON 增 `noDialogueEntry`、风险摘要列高风险前 3 条 | `src/Forge.Cli/PipelineCommands.cs` `RunPlanAsync` |
| generate / build / install 前提醒 | 同上 `WarnIfNoDialogueEntryAsync`（5 处调用） |
| install 默认挡住（`E_PARTIAL`，退出码 5），`--force` 可越过 | 同上 `RunInstallAsync` |

R-106 的判定依据：计划选中的补丁点里没有任何一个是已知正文入口（`AnimateText` / `DOText` / `HandleMessageText` / `HandleMainText` / `PageTextChange` / `OnTextChanged`）或带文本属性链（Utage 的 `Text.OriginalText`）。

## 5. 验证

### 合成夹具（无正文入口）

夹具：`research/88-no-dialogue-gate/evidence/fixture-*`（`NoDialogueMock.csproj` + `DialogueWindow.cs`），编译成 `Assembly-CSharp.dll` 放进假游戏目录（`MockGame.exe` + `UnityPlayer.dll` + `MockGame_Data/Managed/Assembly-CSharp.dll`）。

| 步骤 | 结果 |
|---|---|
| detect | unity_mono 95% |
| analyze | 2 个候选（`SetMessage` 60 分、`PlaySound` 30 分），人工待办写「本游戏没有识别到已知正文入口」 |
| plan | `[注意] … 正常剧情可能一句都不读。` + `[R-106]` + 风险摘要列高风险 |
| install --dry-run | 通过（不部署） |
| install | **被挡** `E_PARTIAL`（退出码 5），消息与建议如实 |
| install --force | 越过闸门进入生成/构建（夹具无 Unity 程序集，构建按预期失败于 `CS0234`） |

### 真游戏回归（《Mystery Lover 2》，只读）

`plan` 的 JSON：`noDialogueEntry=false`；补丁点第一条仍是 `Assembly-CSharp.dll!/Utage.AdvMessageWindow:PageTextChange`，描述含「文本在实例属性链 Text.OriginalText 上」——**有正文入口的游戏不会被新闸门误挡**。

## 9. 升级

- 从 0.2.48 升级：直接换 `app/forge.exe`（GUI 未变）。
- 已装旧补丁的游戏：先 `forge verify --rollback` 再装新补丁；本版不改变运行期朗读逻辑。
- 遇到 `E_PARTIAL`「这个游戏的计划里没有识别出正文入口」：先看 `plan.json` 的 `manualTodo` 与 R-106；确认要试就加 `--force`，装完核对 `BepInEx\LogOutput.log` 的 `[Speech]` 行。
