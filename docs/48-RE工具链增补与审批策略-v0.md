- 本文件只记录“收到什么、我们准备怎么做、哪些边界不变”。具体工具是否好用，以实机验证报告为准。

## 1. 用户要求（转述，保留原意）

1. 现状认知：项目目前逆向链路“仅内置 Ghidra + UnityPy”，缺 IL2CPP 核心能力，导致 IL2CPP 游戏
   无法像 Mono 那样做“字段兜底朗读”，是当前最大短板（用户说法；实际我方当前只集成 Ghidra，
   UnityPy 尚未接入，本文件第 4 节会纠正）。
2. 要求增补并直接集成四件套：
   - **Il2CppDumper**（核心）：解析 `GameAssembly.dll` + `global-metadata.dat`，输出 C# 符号、
     方法偏移、结构体、Ghidra 导入脚本。
   - **pyghidra**：用 Python 程序化调用 Ghidra（建工程、分析、导入 IL2CPP 符号、重命名、导出伪代码）。
   - **Frida + frida-il2cpp-bridge**：运行时类枚举、内存读取、函数 Hook、运行时字符串 Dump。
   - **dnSpyEx**：旧 Unity Mono 游戏 DLL 反编译备用解析器。
3. 期望收益：IL2CPP 静态符号全自动还原；结构体内存布局自动解析，支撑“原生内存读字段”兜底；
   自动分流 Mono/IL2CPP/加密资源包；自动输出 Hook 模板与结构化 RE 结果对接 Plan。
4. 审批策略（长期生效）：
   - 自动放行：工具下载、源码拉取、环境安装、Python 依赖安装、本地工程配置、脚本调试、
     静态样本分析、无头批量分析、数据导出、结构化文件生成。
   - 仍然拦截：游戏原文件修改/覆盖/删除、游戏目录写入、补丁强注入、系统全局高危变更、
     文件批量删除、KKZ 相关高危脚本、任何可能破坏样本且无法回滚的操作。

## 3. 落地路线（分三步，均可回退）

### 第一步：工具获取与“能跑”验证（0.2.11 候选）

- 在 `tools/re/` 下建立工具目录（不污染游戏目录），每个工具记录：版本、来源 URL、许可证、
  文件哈希、最小验证命令与输出。
- 许可证红线（初判，待逐个核实）：
  - Il2CppDumper：**待核实**（GitHub Perfare/Il2CppDumper），若为 MIT 可随包，否则只做可选下载。
  - pyghidra：Apache-2.0（待核实）。
  - Frida / frida-tools / frida-il2cpp-bridge：Frida 为 LGPL（待核实），npm 包许可证待核实；
    动态工具默认不随发行包，只做“用户本机按需安装”。
  - dnSpyEx：GPLv3（待核实）——**GPL 工具绝不进入发行包**，只能作为可选的“自行下载”指引。
- 产出：`research/49-re-toolchain/REPORT.md` + `evidence/`（版本、哈希、命令输出、许可证摘录）。

### 第二步：IL2CPP 字段兜底朗读（0.2.12 候选，真机目标）

- 用 Il2CppDumper 的输出（`dump.cs` / `script.json` / `il2cpp.h`）找到对话文本字段
  （TMP/UGUI 文本组件的字段）与类结构。
- 运行时路线先走 Il2CppInterop（现有 BepInEx6 工程已有）：钩到对话方法后拿实例，
  按字段名反射/偏移读文本字段；与 Mono 的 `SpeechGate.SayFields` 对齐。
- 如果 interop 路线在目标游戏上不可行，再评估“原生偏移读内存”的方案（需要 Il2CppDumper
  给出的字段偏移 + `il2cpp_field_get_offset` 等导出函数）。
- 验收：至少一款 IL2CPP 游戏真机听到 2 句以上、回滚干净、日志有钩子/字段证据。
- 候选样本（本机，均只读）：`manosaba_game`、`nonand2`、`SiliconHeart`、
  `The NOexistenceN of Lilith`、`The NOexistenceN of you AND me`。

### 第三步：全自动流水线与 Frida 动态验证（0.2.13+）

- `forge tools`（待定名）子命令：检查工具是否就绪、打印版本/许可证、缺什么给安装指引；
  默认不联网、不自动下载 GPL 工具。
- 流水线编排：Il2CppDumper → pyghidra 导入符号 → Ghidra 分析 → 候选方法/字段 → Plan。
- Frida：只做“本机可选动态验证器”（附加进程枚举类/字符串），不进入发行包；验证结果写入报告。
- dnSpyEx：只做指引与可选路径，不捆绑。

## 4. 对用户现状认知的两处纠正（诚实说明）

1. 当前产品**没有**内置 UnityPy；逆向链路只有 Ghidra（`--advanced`）。UnityPy 只是研究阶段用过。
2. 当前 IL2CPP 适配器已有“Il2CppInterop 路线 + dump.cs 路线”，真机能连续读数行；
   缺的是“字段兜底”（钩子无字符串参数时读实例文本字段），不是整个 IL2CPP 都不能用。
   本批工具链的目标是把“缺的那块”补齐，并把分析过程自动化。
