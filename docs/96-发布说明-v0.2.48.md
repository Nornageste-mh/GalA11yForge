# 发布说明 v0.2.48.0（2026-11-16）

## 1. 一句话

用户反馈「新买的《Mystery Lover 2》（Utage 引擎）装了补丁，没有剧情朗读」——这一版把
**Utage 的正文入口**从“分析不到”改成“能识别、能生成补丁”，并新增按实例属性链朗读的补丁写法。

## 2. 问题是怎么来的

- 用户 2026-11-16 反馈：给昨天新下载的某款游戏装了补丁，**没有剧情朗读、也没有导航**，已自行回滚。
- 查默认工作区（`%LOCALAPPDATA%\GalA11yForge\games\mystery-lover-2`）：
  - detect：`unity_mono`，Unity 2019.4.40f1，64 位，置信度 0.95；
  - plan：`automatic_with_confirmation`，6 个补丁点，**全是 `Utage.SystemUiDialog*Button::Open` 这类系统对话框**；
  - verify（回滚模式，工具版本 0.2.46.0）：`pass_with_skips`，23 个新增文件全部删除。
- 用 Mono.Cecil 只读扫 `MysteryLover2_Data\Managed\Assembly-CSharp.dll` 后确认：游戏用 **Utage（宴）** 框架，
  正文链是
  `AdvMessageWindowManager.OnPageTextChange` → `AdvMessageWindow::PageTextChange(AdvPage page)`
  → `IAdvMessageWindow.OnTextChanged(window)` → `AdvUguiMessageWindow.OnTextChanged` 里
  `text.text = window.Text.OriginalText`。
- 这条链上**没有 `System.String` 形参**：文字在 `page.TextData.OriginalText` / `window.Text.OriginalText` 属性链上。
  旧分析器候选条件是「有 string 形参 / 直接写 Unity 文本组件 / 打字机 sink / 语义名 / 选项名」，
  类型级兜底还要求「类型有 Unity 文本组件字段」——Utage 的 `AdvMessageWindow` 都不满足，直接被丢弃，
  于是只剩“有 string 形参”的系统对话框按钮进了计划。

## 3. 根因（两句话）

1. `MonoTextPatterns.KnownFrameworks` 里没有 Utage，`AdvMessageWindow` 拿不到框架分；
2. 候选/生成器只认「string 形参」和「实例文本字段」，不认「实例属性链上的文本」。

## 4. 修了什么

在 `src/Forge.Adapters.UnityMono/Internal/` 与 `src/Forge.Generators/`：

| 位置 | 改动 |
|---|---|
| `MonoTextPatterns.cs` | 已知框架增加 Utage；已知正文类型集合 `UtageMessageWindowTypes`；新增 `IsUtageDialogueType` / `TryUtagePropertyChain`（只对 `AdvMessageWindow::PageTextChange` 返回 `{ "Text", "OriginalText" }`）/ `DescribePropertyChain` |
| `UnityMonoScanner.cs` | `ShouldKeep`：Utage 正文类型的方法一律保留 |
| `UnityMonoScoring.cs` | 规则 S10：该入口 +55 分；证据行「S10+55…」与「文本属性链：Text.OriginalText」；`UnityMonoScore.S10`；`KindFor` 判 Dialogue |
| `UnityMonoPlanner.cs` | 计划描述写成“正文入口没有 string 形参，文本在实例属性链 … 上”；置信度 `PageTextChange` 0.80；新增风险 R-106（没有正文入口时警告“可能只读对话框”） |
| `GeneratorSettings.cs` | `HookSetting.TextPropertyChain`；正则解析 `文本属性链：…`；主朗读钩子优先属性链 |
| `UnityMonoGenerator.cs` | 属性链钩子生成 `Postfix(object __instance)` + `SayPropertyChain` / `NotePropertyChain` |
| `SpeechGateTemplate.cs` | 新增 `SayPropertyChain` / `NotePropertyChain` / `CollectPropertyChain`：只读反射逐段走属性（找不到再走字段），最后必须是 string，异常/空值只写日志 |

## 5. 真机（只读）

用 0.2.48 开发版与发布版对 `D:\Steam\steamapps\common\Mystery Lover 2` 只读分析（未安装）：

- 修复前：6 个补丁点全是系统对话框（`SystemUiDialog1/2/3Button::Open`、`ToolTip::SetTooltip` 等）；
- 修复后：hook-001 = `Utage.AdvMessageWindow:PageTextChange`（得分 85），
  描述里带 `文本属性链：Text.OriginalText`，排序在第一位；
- 生成的 `Hooks/Hook_hook_001.cs`：`private static void Postfix(object __instance)` +
  `SpeechGate.SayPropertyChain(__instance, new[] { "Text", "OriginalText" });`
- `forge build`：`MysteryLover2.A11y.dll` 47,104 字节，exitCode 0（4.0 秒）；
- 游戏目录未被写入（没有 `BepInEx` / `doorstop_config.ini` / `winhttp.dll`）；
- 证据：`research/87-utage-support/`。

## 6. 顺手补的防御

- 计划里如果**没有任何已识别的正文入口**，现在会写一条高风险 `R-106`：
  “可能只在对话框/菜单弹出时朗读，正常剧情一句都不读”，并建议先 manual 复核。
  这直接来自这次用户踩的坑：当时计划明明只有系统对话框，产品却照常报“安装完成”。
