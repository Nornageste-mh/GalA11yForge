# 发布说明 · v0.2.24.0（Ren'Py 旧补丁冲突 hotfix）

日期：2026-11-15｜类型：缺陷修复（hotfix）

## 1. 这一版修了什么

**场景**：玩家电脑里有些 Ren'Py 游戏**本来就装过旧版无障碍补丁**（`game/a11y_game/` +
`game/a11y_platform/`，用户 A11yFramework 体系）。0.2.23 及更早版本在“没检查旧补丁”的情况下
直接把自己的覆盖层写进同一个目录，结果是两套 `A11yHost` 契约不一致，游戏**启动即弹异常屏**：

```
File "game/a11y_game/90_plugin.rpy", line 91
A11yHost.validate()
AttributeError: '_A11yState' object has no attribute 'validate'
```

本版做两件事：

1. **安装前拦截（正路）**：检测到游戏已有 `game/a11y_*` 旧覆盖层时，`install` 直接返回
   `E_ENGINE_UNSUPPORTED`，提示先运行旧补丁的 `uninstall.ps1`（或删除旧目录）再装本补丁；
   确认要叠加时才用 `--force`。**不会再默默装出一个启动就崩的组合。**
2. **契约兼容桥（兜底）**：覆盖层契约里补了 `_A11yLegacyBridge`——旧补丁常调的
   `A11yHost.validate()`、`.rpy.start(...)`、`.keys.install()`、`A11yHost.log(...)` 等
   现在都有人接：空实现 + 记 `[A11y兼容]` 日志，不崩、也不会两套朗读抢麦。
   兼容桥只解决“不崩”，**不支持长期共存**；正路仍是先卸载旧补丁。

## 2. 真机验证（不是只跑单测）

样本：《永恒与星辰与日常》（Ren'Py 8.6.0.26032101 + Python 3.12.7，1.7GB 副本）：

| 步骤 | 结果 |
|---|---|
| 对“带旧补丁”的副本安装 | 被正确拒绝，错误码 `E_ENGINE_UNSUPPORTED`，提示先卸载旧补丁 |
| 把旧目录移出后再安装 | 成功（9 文件，`renpy-20261115-212511-f1ffee13`） |
| 启动游戏 | **正常进主菜单**（此前 0.2.23 启动即崩）；日志：say filter 挂载、5 个热键、`[A11y菜单] 主菜单出现`、`backend=NVDA 主菜单` |
| 回滚 | `pass_with_skips`、10 检查、0 失败 |

证据：`research/65-renpy-legacy-conflict/`（README + 日志 + 截图）。

## 5. 已验证 / 未验证

已验证：
- 带旧补丁的 Ren'Py 游戏安装会被拦截（真机 + 单测）
- 移出旧补丁后，本覆盖层在 Ren'Py 8.6 / Python 3.12 上能启动并播报主菜单
- 回滚干净（10 检查 0 失败）

未验证：
- **Quit 确认屏真机取证**：点击前用户开始使用电脑，立即停止自动化（不抢占用户窗口）；
  等用户空闲或换样本按 `docs/64` 手册补。
- 兼容桥只在一个样本上验证“不崩”；其它旧补丁版本的调用面未穷举。
- GUI 的 NVDA 实际听辨仍需人工（docs/32）。

## 6. 升级建议

- 之前用过 0.2.23 或更早版本、且游戏装过旧无障碍补丁的：先按旧补丁 `uninstall.ps1` 卸载，
  再 `analyze → plan → generate → install`（本版会在冲突时给出明确提示）。
- 没装过旧补丁的游戏：直接升级，无行为变化。
