# 0.2.83.0 发布说明：同名重载不再让整条钩子挂不上

> 发布日期：2026-11-18。上一版：0.2.82.0。测试：**746 通过 0 失败**。

## 1. 一句话

分析阶段早就把「补丁点的完整签名」写进了计划，但生成器只用了里面的参数**名**、没用参数**类型**，于是 Harmony 遇到同名重载就抛 `Ambiguous match found`、整条钩子被跳过；0.2.83 把形参类型交给新增的运行期 `Platform/MethodResolver.cs`，按「参数个数 + 类型全名」挑唯一重载。

## 2. 问题怎么发现的

- 32 个子代理体检时，`research/106-games-mystery-lover-1/REPORT.md` 复核了《Mystery Lover》装 0.2.55 后的真机日志：
  - `Player.log:150` 有 `Hook_hook_002 … Ambiguous match found.`
  - 6 个钩子只挂上 5 个（`[Hook] 已挂载 …` 计数）。
  - 计划里 R-102 已经预言过「同名重载可能导致 AmbiguousMatchException」，但只写了「人工指定」，没有产品级修法。
- 该补丁点：`Assembly-CSharp.dll!/Utage.SystemUiDialog1Button:Open`，完整签名 `Open(System.String text, System.String buttonText1, UnityEngine.Events.UnityAction callbackOnClickButton1)`。

## 3. 根因（两句话）

1. `UnityMonoTargets.BuildHookTarget` 只输出 `类型:方法`（生成器白名单只允许基础类型形参），完整 Cecil 签名只写在补丁点 Description 里。
2. `GeneratorSettings` 从 Description 里只取 string 形参名 / 实例文本字段 / 属性链，`HookTemplate` 于是生成 `AccessTools.Method(Target, null)`；Harmony 对同名重载无法判断 → 抛异常 → `Plugin.PatchHooks` 捕获后打警告、跳过整条钩子。

## 4. 改了什么

| 文件 | 改动 |
|---|---|
| `src/Forge.Generators/Internal/GeneratorSettings.cs` | `HookSetting.ParameterTypes`；`TryFindParameterTypes` 从「完整签名（Cecil）」解析形参类型全名（≤16 个、每个 ≤200 字符，任一非法整体退化）；`SplitTopLevel` 增加 `<>`/`[]` 深度，泛型与多维数组的逗号不再误拆 |
| `src/Forge.Generators/Templates/MethodResolverTemplate.cs`（新） | 生成 `Platform/MethodResolver.cs`：`AccessTools.TypeByName` 找类型（含 `/`→`+`、`Type.GetType`、程序集扫描兜底与缓存）→ 枚举 `Public|NonPublic|Instance|Static` 同名方法 → 先按参数个数 + 类型全名归一化匹配，再退简名匹配 → 唯一则返回；多义抛带候选清单的 `AmbiguousMatchException`；过程记 `[Hook:resolve]` 诊断 |
| `src/Forge.Generators/Templates/HookTemplate.cs` | `Resolve()` 改为一行 `return {{RESOLVE_EXPRESSION}};` |
| `src/Forge.Generators/UnityMonoGenerator.cs` | 新 token `RESOLVE_EXPRESSION`；目标文本自带形参类型 → 保持 `AccessTools.Method(Target, new[] { typeof(...) })`；否则 → `MethodResolver.Resolve(Target, new string[] { … })`；无条件产出 `Platform/MethodResolver.cs` |
| `src/Forge.Adapters.UnityMono/Internal/UnityMonoPlanner.cs` | 计划描述与 R-102 文案改为「生成器会用证据里的完整签名在运行期挑唯一重载；证据缺签名或重载靠泛型/继承区分时仍可能歧义」 |

## 5. 验证

### 5.1 单测 / golden

- 新增 4 条生成器测试：有签名走 resolver、无签名走空列表、目标自带形参类型保留旧路径、非法类型名退回空列表。
- golden 重生成后新增 `Platform/MethodResolver.cs`；`Hook_dialogue_set_text.cs` 变为 `MethodResolver.Resolve(Target, new string[] { "System.String" });`，`Hook_advance_on_click.cs` 保持 `AccessTools.Method(Target, new[] { typeof(string) });`。

### 5.2 真实游戏（只读）编译

发布版 0.2.83 对《Mystery Lover》（Steam，只读）跑 `generate` + `build`：

hook-002 生成文本：


### 5.3 解析逻辑离线验证（7/7）

把发布版生成的 `MethodResolver.cs` 原样编进小控制台程序（Harmony 的 `AccessTools` 与 `A11yHost.Diag` 用最小 stub），用假的同名重载类型跑 7 个场景，全部 PASS：精确挑三形参重载（hook-002 情形）、泛型 `Action`1<…>` 形参（hook-006 情形）、简名兜底、单方法直返、类型缺失返回 null、双重重载抛异常并列出候选、无签名多载也抛异常。
