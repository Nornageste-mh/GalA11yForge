# 发布说明 v0.2.20：把“有没有读出来”变成可自动检查

- 发布日期：2026-11-15
- 版本：0.2.20.0
- 发布目录：`releases/v0.2.20/`
- 测试：652 通过 / 0 失败 / 0 跳过（Core 97、Verify 68、Detection 30、Generators 59、Ren'Py 37、UnityMono 31、Build 79、Gui 141、Il2Cpp 55、Ghidra 55）

## 为什么做这一版

0.2.19 之前，`forge verify` 能确认“文件装对了、BepInEx 加载了”，但回答不了最关键的问题：**补丁到底有没有把台词交给读屏/语音？** 真机测试时我们一直靠人看日志、看截图，既慢又容易漏。用户 2026-11-15 18:01 的决策明确“测试可全用 AI”，因此本版把“朗读证据”做成 verify 的自动检查项。

## 本版改动

1. 新增 `forge verify --speech-log <日志路径>`：
   - 支持 Unity Mono、Unity IL2CPP（`[Speech]` / `[a11y-speech]` / `[朗读]`）与 Ren'Py（`backend=SAPI …`）三类日志。
   - 只统计，不把台词写进报告：有效行、去重行、占位行、最大重复次数、日志大小/是否截断。
   - 新增检查：
     - `s-01 语音日志可读`（P2，通过）
     - `s-02 日志里有有效朗读输出`（P1，有效行 > 0 才通过）
     - `s-03 朗读文本没有明显重复`（P2；样本 <2 记为跳过，去重率 ≤50% 判失败）
   - 没有日志或日志里还没进对白时，只写“未验证”并说明原因，不会把正常安装误判成失败。
2. `VerifyOptions` 新增 `SpeechLogPath`（也支持显式相对游戏目录）与 `SpeechLogMaxBytes`（默认 4MB，避免大日志拖慢）。
3. CLI 解析、帮助文本、`RunVerifyAsync` 全部接好 `--speech-log`；Verify/Core 测试新增 7 条。

## 真机演示

manosaba_game（Unity 6 + IL2CPP + Naninovel，229 文件安装）后用 0.2.14 的真实运行日志做 `--speech-log` 检查：

- `s-01` 通过：16,292 B / 159 行完整读取。
- `s-02` 通过：有效朗读 19 行、去重 18 行、占位 0 行。
- `s-03` 通过：同一句最多重复 2 次。
- 随后 `--rollback`：10 项检查、0 失败，原文件还原；证据在 `research/62-speech-log-verify/`。

## 已验证 / 未验证

- 已验证：发布版安装→语音日志检查→回滚整条链路；Mono 引擎识别；两种 BepInEx 离线包随包可用。
- 未验证：`s-02` 通过不等于用户真的听见（Tolk 缺失时补丁降级为日志输出）；Ren'Py 确认框真机取证仍缺；GUI 的 NVDA 人工验收仍建议用户亲自点一遍。

## 升级提示

- 直接替换 `app/forge.exe` 即可；GUI 无改动。
- 想验证旧补丁是否真的读出来：安装后启动游戏、推进几句，再运行
  `forge verify --game <游戏目录> --speech-log <游戏目录>\BepInEx\LogOutput.log`。
