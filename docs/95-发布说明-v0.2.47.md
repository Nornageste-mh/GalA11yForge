# 0.2.47 发布说明：回滚之后再装一次，不用再学 `--force`

- 版本：`0.2.47.0`
- 日期：2026-11-16
- 上一版：`0.2.46.0`（Ren'Py 真机回归变成一条命令）
- 本版性质：**体验修复版**。改动小、风险低，但影响每一次「装了又卸、卸了又装」的日常使用。

## 1. 一句话

以前卸载干净后想再装一次，会被要求再加一个 `--force`；现在直接 `install` 就行。

## 2. 问题是怎么发现的

这是自造最小 Ren'Py 样本（`_renpy-mini`）反复做「装 → 卸 → 再装」时撞上的：

```
> forge verify --rollback ...     # 回滚成功，游戏目录已干净
> forge install ...               # 再装一次
E_ARTIFACT_INVALID  工作区已有部署账本：…\games\renpy-mini\05-deploy\install-manifest.json
建议：先 verify --rollback 卸载旧覆盖层；确认叠加时加 --force（旧账本会归档到备份目录）。
```

用户明明已经卸载了，却必须再学一个 `--force`；对读屏用户尤其不友好——错误建议本身是“正确但多余的动作”。

## 3. 根因

- 回滚成功后，部署账本（`install-manifest.json`）被**故意保留**，用于追溯“这游戏被我们改过什么”；
- 但账本里没有“已回滚”的状态，安装前的检查只看“文件在不在”，于是把“已卸载”误判成“还装着”；
- 这个检查在 Ren'Py 覆盖层（`OverlayDeployer`）与 Unity/IL2CPP 插件（`PluginDeployer`）里各有一份，
  而且每条路各有两个入口（`Plan` 与真正部署前）。

## 4. 修法

1. 回滚成功后，把账本标记 `rolledBack: true` + `rolledBackAt`（`InstallManifestStore.MarkRolledBack`）；
2. 安装/部署前检查遇到“已回滚”的账本时放行，并给一句“上一批部署已回滚…”的提示；
3. 旧账本仍会在新一轮部署时归档到 `backup/<新批次>/previous-install-manifest.json`（与新装、`--force` 行为一致）；
4. 回滚标记失败时不影响回滚本身，只在报告里加一条警告（下次安装仍可能要求 `--force`）。

改动文件：

- `src/Forge.Build/DeploymentModels.cs`（`InstallManifest` 加 `RolledBack` / `RolledBackAt`）
- `src/Forge.Build/InstallManifestStore.cs`（`MarkRolledBack` / `IsRolledBack`）
- `src/Forge.Build/OverlayDeployer.cs`（回滚标记 + 两处安装前检查放行）
- `src/Forge.Build/PluginDeployer.cs`（同上）

## 6. 顺手修了回归脚本的一个 flaky

用发布版跑 `tools/renpy-minimal-e2e.ps1` 时首跑失败（73.3s，卡在「确认框整屏播报」）：
日志停在 `到了公园。`，之后点了 8 次没有新行。

- 根因：脚本用**真实鼠标事件**（系统级点击），游戏窗口中途被别的窗口挤到后面，点击落到了别的窗口上；
- 修法：每次点击前先确认游戏在前台，不在就先置前台，置不上就跳过这次点击并记警告（宁可不点，也不误点用户别的窗口）；
- 加固后：发布版连跑两次 **PASS（32.2s / 23.7s）**，`[A11y错误]` 0 条，回滚后覆盖层清干净。

## 9. 已验证 / 未验证

已验证：

- Ren'Py 覆盖层「安装 → 回滚 → 再安装 → 再回滚」全链路真机（0.2.47 开发版与发布版各一遍）；
- 0.2.46 同链路第二次安装确实失败（A/B 对照）；
- 回滚后账本带 `rolledBack: true` 与时间戳；
- 新一批备份目录里能看到归档的旧账本；
- 加固后的 Ren'Py 回归脚本用发布版连跑两次 PASS。

未验证（诚实边界）：

- Unity Mono / IL2CPP 插件的「回滚后重装」只在单元测试里验证（`PluginDeployerTests`），没有在真实 Unity 游戏上做第二次安装真机实验；
- 没有验证“两次安装之间游戏被玩家改动”的情形（该场景仍走原有哈希/基线逻辑）；
- 没有用 0.2.46 及更早生成的旧账本文件实测解析（按 C# 默认值等价于旧行为）；
- 用户手工删光补丁文件却没跑 `verify --rollback` 的情况下，仍会要求 `--force`（保守行为，符合预期）。
