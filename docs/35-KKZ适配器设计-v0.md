## 0. 结论摘要

1. 旧版 KKZ（`plugin\*.tpm` 自动加载不生效的那代，如 1.2.0.3）可以用"插件 DLL 代理"稳定注入：
   把原插件改名、放我们的同名 DLL、在 `V2Link` 里转发原 DLL，并用引擎自己给的 TJS exporter
   在主线程定时器里**只读**求值 `global.kag.historyLayer.currentInfo.plaintext`。[实测 task-47]
2. task-49 把这套做法做成**参数化模板**：目标 DLL 名、原 DLL 后缀、轮询间隔、输出路径、可选 TTS
   都可配；状态机/缓冲/去重/落盘/朗读全在原生侧，**不往 TJS 注入任何对象/函数**（这正是 task-47
   崩溃的根因，见 §7）。[实测] 构建产物 102,400 B、x86、三导出齐全、SHA256 见 README。
3. 交付定位：**实验性 extras / 开发者预览**，不进主 CLI 一键路径，不做自动安装，不承诺"装到 Steam"。
4. 对 0.2.4 的建议：**不纳入主线**，最多作为 `extras/kkz-proxy` 的实验资产 + 设计文档一起挂出去，
   并写清"半自动 + 人工确认"。理由见 §8。

## 1. 定位与红线

**是什么**：给"已经知道自己遇到的是旧版 KKZ、且愿意手工确认安装"的人用的技术模板。
它解决的是"文本取不出来"这一件事，不解决"自动识别引擎/自动部署/无障碍朗读全链路"。

**不是什么**：

- 不是给普通玩家的产品功能；默认不进主 CLI、不被自动调度、不写注册表、不装服务、不要管理员权限。
- 不是 DRM 相关工具：不注入授权校验、不绕过任何保护、不修改可执行代码段。
- 不是万能补丁：只对"纯 V2 插件"（如 `getSample.dll`）适用，COM 插件（如 `menu.dll`）未评估。

**红线（硬性）**：

| 红线 | 原因 |
|---|---|
| 不改 `data.xp3`、不改游戏可执行文件、不改脚本资源 | 一旦改动就不再可回滚，且触碰版权与校验边界 |
| 不重分发任何游戏原始文件（含原插件 DLL） | 版权；代理模板只放**我们自己的代码** |
| 不默认指向 `D:\Steam\...`，不做"一键装到 Steam" | 用户机器差异大；脚本必须显式 `-GameDir` |
| 发布说明里必须写"实验性/临时/可能被 Steam 校验还原" | 避免用户误以为是官方支持 |

## 2. 目标识别（怎么判断"这台是旧版 KKZ、且值得代理"）

识别顺序（全部只读，不写盘）：

1. **目录形状**：存在 `<GameDir>\plugin\`，且其中有若干 `*.dll`（典型的 `getSample.dll`、`menu.dll`…）。
   [文件] task-40 提到的 SenrenBanka 安装目录在 `plugin\` 下有 59 个文件。
2. **插件机制探测**：若 `plugin\*.tpm` 可在启动后被引擎自动加载，则**不需要**本适配器（1.4.0.8 属于这类）。[实测 R23]
3. **引擎版本门**：读宿主 exe 的版本资源（`GetFileVersionInfoW` → `FileVersion`/`ProductVersion`），
   与配置里的 `RequireExeVersion` 做前缀匹配（支持 `1.2.*`）。
   注意版本门是**双保险**而不是识别依据：版本资源可能被汉化组改过，也可能与引擎版本不同名。
4. **哈希门**：`RequireOrigSha256` 记录原插件 DLL 的 SHA-256（本机已记录的参考值：
   SenrenBanka 的 `getSample.dll` = `E190AE1B17F82B106FA466E9AB985364E018C8ACD46B39B2B33B895133C2F30C`，
   [实测 task-40/47]）。哈希比版本更可靠：它同时锁定"这是哪个构建的插件"。

> [推断] "1.2.0.3" 这组数字来自前置任务的记录；它对应 exe 的哪个版本字段（FileVersion 还是
> ProductVersion）、以及是否所有本地化版本都保留该字段，**未复核**——task-49 不允许进游戏目录。
> 验证办法：对一台已装机器读一次版本资源，与 `RequireOrigSha256` 一起记进清单。

## 3. 可替换插件白名单

只有"纯 V2 插件 + 无副作用 + 引擎不依赖其导出符号以外的行为"才适合代理。
判定一个插件能否代理，问四个问题：① 是否只导出 `V2Link`/`V2Unlink`/`GetModuleThreadModel`？
② 是否导出 COM 入口（`DllGetClassObject`/`DllRegisterServer`）？③ 被替换后如果转发失败，
游戏是"少一个功能"还是"直接崩"？④ 是否有反作弊/完整性自检？

| 插件 | 结论 | 依据 |
|---|---|---|
| `getSample.dll` | **推荐**（本模板默认目标） | [实测 task-40/47] 代理后游戏正常进局、能取到台词；插件本身接近"示例插件"，被替换影响面最小 |
| `menu.dll` | **需单独评估，暂不推荐** | [推断] 它是引擎/界面相关插件，可能被更早加载、可能带 COM 入口；一旦转发失败用户看到的是"菜单坏了"而非"少个功能"。评估办法：先只读导出表（`dumpbin /exports`）+ 字符串，再在沙箱复制品上试 |
| 其它 `plugin\*.dll` | 默认**不在白名单** | 未逐个分析导出与副作用；宁可拒绝也不要让用户碰上"闪退" |

**白名单落地方式**：`install.ps1` 目前只允许 `-TargetDll` 为显式给出的文件名，且要求
"文件名 == 代理 DLL 自己的文件名"；发布时必须把白名单写进文档，**不要**把 `-TargetDll` 暴露成
"随便填"。建议 v1 起固定为 `getSample.dll`，将来扩展时逐个补评估记录。

## 4. 安装步骤（改名 → 代理占位 → 哈希校验）

全部动作都只在 `<GameDir>\plugin\` 内进行，另外在 `%LOCALAPPDATA%\kkz-adapter\` 写一份清单。

```
0) 前置：游戏已退出；记录原插件哈希（安装前）；确认磁盘有备份空间（原 DLL 一份）
1) 校验：代理 DLL 是 x86 PE 且导出三符号；-ExpectOrigSha256（若给）与实际一致；
         否则拒绝（见 §7）
2) 改名：getSample.dll            -> getSample_orig.dll      （保留原文件，不复制、不删）
3) 占位：kkz-adapter-<ver>-x86.dll -> getSample.dll          （我们的代理）
4) 配置：写 plugin\kkz-adapter.ini（UTF-16LE，含 TargetDll/OrigSuffix/RequireExe/
         RequireOrigSha256/FailMode=degraded/PollMs…）
5) 清单：%LOCALAPPDATA%\kkz-adapter\<GameDir 指纹>.json
         记录 gameDir、gameExe(+版本+哈希)、targetDll、origPath、origSha256、origBytes、
         proxyPath、proxySource、proxySha256、proxyBytes、iniPath、iniSha256、installedAt
6) 复核：装完立刻重算"代理位置"和"原 DLL 备份"的哈希，与清单比对；不一致立即回滚并报错
```

设计要点：

- **改名而不是复制**原 DLL：少占空间、且"目录里出现 `_orig`"本身就是"已安装"的可靠标记，
  `install.ps1` 见到它直接拒绝，避免重复安装把原文件覆盖成代理。
- **先复核再宣布成功**：安装脚本最后一步重算两侧哈希，任何不一致都当成失败处理。
- **清单放游戏目录之外**：把"外来文件"限制在 `plugin\` 里一个 DLL + 一个 ini，减少 Steam
  校验/杀软/用户清理误伤的概率。

`install.ps1` 实测行为（沙箱假目录，非真实游戏）：默认 dry-run 只打印计划；`-Apply` 才写盘；
`-ExpectOrigSha256` 不符 → 拒绝且不写盘；已装过 → 拒绝；装完 `复核: 代理位置哈希一致=True /
原 DLL 备份哈希一致=True`。

## 5. 卸载与回滚

```
0) 前置：游戏已退出；读清单
1) 校验当前 getSample.dll 的哈希 == 清单 proxySha256 ？
   否 => 默认拒绝（说明被 Steam 校验覆盖、或被别人换过），要人工确认才 -Force
2) 校验 getSample_orig.dll 的哈希 == 清单 origSha256 ？
   否 => 默认拒绝（原文件被改过，可能还原本就坏了）
3) 回滚：删除代理 getSample.dll -> 把 _orig 改回原名 -> 删除 kkz-adapter.ini
4) 复核：回滚后插件哈希必须等于 origSha256，否则报警
5) 归档：清单改名为 <指纹>.uninstalled.json；代理副本留在 %LOCALAPPDATA%\kkz-adapter\removed\
```

关键点：**回滚前必须验证"要删的那个 DLL 确实是我们装的"**。否则一旦用户先跑过 Steam
校验（把原插件下载回来覆盖了代理），我们再"回滚"就会把刚下载回来的原文件当成代理删掉，
而把一个过期的 `_orig` 盖回去 —— 这正是最典型的把用户游戏搞坏的方式。

回滚实测（沙箱）：体检 → `-Rollback -Apply` → 回滚后哈希 = 原值、目录只剩原插件、清单归档。

## 6. Steam 文件校验与自动更新的风险

风险是真实存在的，且**无法在客户端侧根除**：

| 场景 | 会发生什么 | 我们的应对 |
|---|---|---|
| 用户点"验证文件完整性" | Steam 发现 `getSample.dll` 的大小/哈希与记录不符 → 重新下载覆盖（我们的代理被冲掉）；`getSample_orig.dll` 是多余文件，一般保留 | 安装前记录全部哈希；文档写清"校验后适配器失效，需要重新安装"；卸载脚本能识别"已被覆盖"并拒绝误删 |
| 游戏自动更新 | 新版 `getSample.dll` 覆盖代理；我们的 `_orig` 仍是旧版 → 版本错配 | 清单里记录 `origSha256`+`gameExeSha256`，重新安装前先比对；不一致就要求用户重新走一遍评估 |
| 用户手动删 `_orig` | 无法回滚，但代理仍能跑（转发失败 → 插件功能缺失） | 安装脚本要求 `-Apply` 明确确认；文档反复强调"不要手动删 `_orig`" |
| 反作弊 / 完整性自检 | 未观察到（KKZ 是单机引擎，本机样本无自检）[推断] | 不做任何隐藏；发布说明明写"改的是 plugin 目录里的一个 DLL" |

应对原则（写给用户的三句话）：

1. **这是临时状态**，不是"装一次永久生效"；Steam 校验/游戏更新都会让适配器失效。
2. **装之前请先记下哈希**（脚本自动记进清单），出问题用清单对账，不要靠记忆。
3. **出问题先回滚**（`uninstall.ps1 -Rollback -Apply`），回滚后哈希必须回到原值，再谈其他。

## 7. 失败安全（宁可"没效果"，不要"游戏崩"）

运行时三道门（不满足 → 不注入，但仍尝试转发原插件让游戏能跑）：

| 门 | 检查 | 失败后果 |
|---|---|---|
| ① 文件名门 | 本模块文件名 == `TargetDll` | `inject=0`；代理被误命名时不至于做出奇怪的事 |
| ② 版本门 | 宿主 exe 名 == `RequireExe`，版本前缀匹配 `RequireExeVersion` | `inject=0`，日志 `gate_exe_version_ok=0` |
| ③ 哈希门 | 原 DLL 存在，且 `RequireOrigSha256` 一致 | `inject=0`，日志 `gate_orig_exists=0` / `gate_orig_hash_ok=0` |

- 默认 `FailMode=degraded`：三闸任一失败都返回成功、只是不注入，**游戏表现与没装适配器一致**。
- `FailMode=strict`：直接让插件加载失败（引擎侧会认为该插件坏了），只建议开发期用。
- 安装期失败安全：缺原 DLL / 版本不符 / 哈希不符 / 游戏在运行 / 已装过 → **脚本拒绝写盘**，
  不留半装状态。装完复核失败 → 提示立刻回滚。
- 运行期异常兜底：TJS 求值全部包在 `try/catch(...)` 里（`/EHa`），异常只记日志不冒泡；
  定时器回调里重入用 `InterlockedExchange` 拦截；变体读取带长度/类型/哨兵校验（`variant_overrun_slot`）。

**已知崩溃坑（task-47 实测，模板已规避）**：

| 坑 | 现象 | 规避 |
|---|---|---|
| TJS `new Object()` / `new Array()` | 进程 `0xC0000409`（`___report_gsfailure`），直接消失 | 模板不向 TJS 注入任何对象，只对属性做只读求值 |
| TJS `typeof(对象)` | 抛异常（`typeof(1)` 正常） | 存在性判定用 `x == void` |
| `wsprintfW(buf, L"前缀=", 值)` | 静默丢值（格式串无转换符） | 全部用 `Append*()` 手工拼接 |
| `V2Link` 内立刻求值 | 太早，KAG 未加载 → 取空 | V2Link 只取函数指针 + 建定时器，求值放到第一个 `WM_TIMER` 之后 |
| `.def` 含中文注释 | `link` 报 `LNK4017`，**静默丢弃全部导出**，产物"构建成功"却完全无效 | `.def` 保持纯 ASCII；构建脚本检测该警告 |

## 8. 与 0.2.4 的关系（建议）

**建议：不纳入 0.2.4 主线；作为 `extras/kkz-proxy` 的"实验性开发者预览"+ 设计文档一起发布。**

理由：

1. 真实目录**一次没跑过**（本任务明确禁止）。沙箱脚本全流程通过 ≠ 真实游戏能跑；
   发布前至少要有一台真实机器上的"安装→取到台词→回滚→哈希复原"完整闭环记录。
2. `docs/33-0.2.4-计划.md` 已明确"不把 KKZ 实验代码放进主 CLI 一键路径"。本模板遵守这条：
   不进 `src/Forge.*`、不注册 CLI 子命令、`install/uninstall` 只接受显式 `-GameDir`。
3. 用户侧心智成本高：需要知道自己在测什么、要看日志、可能被 Steam 校验冲掉。
   这类东西适合"愿意帮忙测的人"，不适合 0.2.4 的普通用户。
4. 但**设计文档必须进主线文档**（本文件）：它把"目标识别、白名单、安装/回滚、Steam 风险、
   失败安全"讲清楚，是将来产品化（自动识别 + 半自动安装）的规格来源。

若 Lead 决定要在 0.2.4 露出，最小的露出方式是：文档里加一节"实验性：旧版 KKZ 代理（开发者预览，
需手工确认，随时可能失效）"+ 附 `dist` 产物 SHA256，不做任何自动安装。
