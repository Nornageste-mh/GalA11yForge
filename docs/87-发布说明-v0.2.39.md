# GalA11y Forge 0.2.39.0 发布说明

- 发布：2026-11-16
- 版本：0.2.39.0
- 测试：全量 686 通过 / 0 失败 / 0 跳过
- 发布目录：`releases/v0.2.39/`

## 1. 这一版解决什么问题

0.2.37 让高级分析（Ghidra）在超时时告诉你“大概要等多久”，但用户还得自己换算该把
`ghidra.timeoutSeconds` 调到多少。0.2.39 把这一步也自动化：**直接给出可复制的建议值**。

对读屏用户和命令行用户都是同一件事：超时 → 结果里出现一个具体数字 → 改参数重跑即可。

## 2. 改动

### 2.1 估算器新增建议值

`src/Forge.Analyzers.Ghidra/GhidraDurationEstimator.cs`：

- `SuggestTimeoutSeconds(long sizeBytes, int currentTimeoutSeconds)`
- 规则：`max(粗估秒数 + 60, 当前值 + 30)`，再夹在 30–3600 秒；
- 没有文件大小时按“只有启动耗时 30 秒”计算（结果 90 秒）。

### 2.2 失败路径带出建议值

- `GhidraAnalysisOutcome` 新增 `int? SuggestedTimeoutSeconds`；
- `BuildRunFailure` 在 Timeout 分支计算建议值并写入失败产物；
- `BuildFailedOutcome` 新增参数 `int? suggestedTimeoutSeconds = null`；
- `GhidraArtifact` 新增 `SuggestedTimeoutSeconds` 并做映射；
- 超时建议文本改为：
  `提高 ghidra.timeoutSeconds（当前 30；按文件大小粗估需要约 402 秒，建议调到 462）后重跑…`

### 2.3 结果 JSON / 人类输出 / GUI 朗读

- `src/Forge.Cli/GhidraAdvanced.cs`：`data.ghidra.suggestedTimeoutSeconds`；
  人类提示改成「可调 `--option ghidra.timeoutSeconds=462`」这样可直接复制的片段。
- `src/Forge.Gui.Core/ForgeDataNarrator.cs`：新增中文标签「建议超时上限（秒）」。

## 3. 真机样例（SenrenBanka，只读）

命令（开发版）：

```
forge analyze --game "D:\Steam\steamapps\common\SenrenBanka" `
  --workspace D:\DSHWorkSpace\_adv-0239 `
  --advanced --option ghidra.timeoutSeconds=8 --json
```

输出要点（人类行）：

```
[部分完成] 分析未完成：0 个文本候选（Ghidra 高级分析失败，结果不完整）。
  [高级分析] Ghidra 分析超时（30s），已终止进程树；结果不完整，日志见 work 目录。
  按文件大小粗估，分析这枚 exe 大约需要 402 秒；超时不够时可调 --option ghidra.timeoutSeconds=462。
```

JSON 片段：

```json
"ghidra": {
  "status": "timeout",
  "executableSizeBytes": 4583168,
  "estimatedSeconds": 402,
  "suggestedTimeoutSeconds": 462
}
```

说明：`ghidra.timeoutSeconds=8` 会被运行器按 30 秒下限执行，这是既有保护逻辑。

证据：`research/79-suggested-timeout/result.txt`、`analysis-ghidra.json`。
