# 发布物保留策略（磁盘紧张时的处理）

## 为什么有这份文档

D 盘空间紧张（2026-11-15 剩余约 2.2GB），`releases/` 每个版本约 206MB（app + gui + bepinex）。
保留全部历史版本会很快吃光磁盘，因此定一个明确的保留规则，避免以后靠猜。

## 规则

1. **保留最近 5 个版本**的完整发布目录（当前保留 `v0.2.13`…`v0.2.17`）。
2. 更早的版本目录可以删除；它们的发布说明（`docs/NN-发布说明-vX.md`）与校验和永久保留在文档里，
   代码可从 git 提交重新构建，所以发布目录本身不是唯一副本。
3. `releases/extras/`（外部读屏器旧包）保留，除非明确不再需要。
4. 删除前先确认目录名匹配 `releases/v0.2.x`，不要碰 `releases/extras`。
