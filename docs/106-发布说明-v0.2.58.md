# GalA11y Forge 0.2.58.0 发布说明

## 一句话
修掉 32 个子代理体检出来的第一个 P0：**--json 输出契约**——7 条流水线命令（analyze/plan/generate/build/install/verify/report）现在 stdout 是纯 JSON，人类可读行全部改走 stderr；解析期错误（未知命令/未知参数）也遵守 --json。

## 为什么做
32 个子代理批量体检（research/101–144）里，C136 实测：nalyze --json 的 stdout 混着人类行，脚本 json.loads 直接失败；解析错误无视 --json，错误对象的 command 恒空。GUI 与自动化都在依赖这个契约。

## 改了什么
- src/Forge.Cli/PipelineCommands.cs：新增外层 RunAsync（json 模式用 StringWriter 缓冲，逐行拆出人类输出→stderr，最后一行 JSON 信封→stdout），原逻辑改名 RunCoreAsync。
- src/Forge.Cli/CliApplication.cs：解析失败分支在原始 args 里检测 --json（此时 options 可能为 null），仍回 JSON 错误信封。
- 测试：	ests/Forge.Core.Tests/CliTests.cs 新增 ParseErrorWithJsonFlag_StillReturnsJsonOnStdout。

## 验证
- 开发版实测：nalyze --json → stdout 86,617B 可 json.loads，人类行 923B 落在 stderr。
- robnicate --json → exit 2，stdout 为 {"ok":false,...,"code":"E_ARG_INVALID"}。
- 全量测试 **715 通过 0 失败**（Core 106、Gui 168、Build 82、Verify 69、Ghidra 72、Generators 60、UnityMono 36、RenPy 37、Il2Cpp 55、Detection 30）。
