# 0.2.16.0 发布说明：Ren'Py 选项上方的题目也会读了

- 发布日期：2026-11-15
- 版本号：`0.2.16.0`（版本纪律：用户 2026-11-14 邮件要求统一在 0.2.x 上叠加）
- 发布目录：`releases/v0.2.16/`
- 上一版：`0.2.15.0`（IL2CPP 字段兜底降噪）

## 1. 这个版本解决什么问题

以前 Ren'Py 游戏出现选项时，补丁只念「选项 1：…；选项 2：…」，**不念选项上方的题目/说明**。
盲人用户听到两个选项，但不知道「现在在选什么」——比如存档冲突时听到「Yes / No」，
却不知道是在问「是否覆盖存档」。

这个版本会先找选项上方的非按钮文字（题目/说明），把它们和选项一起播报：

> 提示：<题目>。选项 2 个：1 …；2 …

没有题目时，退回原来的「选项 N 个：…」格式，不影响旧行为。

## 2. 改了哪里

- `src/Forge.Adapters.Renpy/Templates/platform/03_menu.rpy`
  - 新增 `_a11y_choice_prompt()`：遍历 choice 屏幕的显示树，收集「不是按钮文字」的文本节点，
    最多取 2 条、去重、用「；」连接；拿不到返回空串。
  - `_a11y_menu_tick` 的播报签名加入题目（`prompt + "||" + 选项文本`）：同一屏题目换掉也会重新播报。
- 测试：`Generated_ChoiceMenu_ReadsPromptAboveOptions`（断言模板含探针函数、选项排除、带题目的播报格式、题目进签名）。
- 无接口变更；旧配置与旧补丁工程不受影响。

## 4. 已验证 / 未验证（诚实边界）

已验证：

- 模板生成正确、单元测试全绿；
- DDLC 副本上安装 0.2.15 覆盖层后，真机走到「存档冲突 2 选项」屏，日志里有
  `选项 2 个：1 Yes, delete my existing data.；2 No, continue where I left off.`——
  说明选项通道本身在真机可用（该次是 0.2.15 旧模板，还没带题目行）。

未验证（这一版必须说清楚）：

- **「提示：…」这一段没有在真机上亲眼看到/听到**。原因：当时用户正在用电脑（Steam 前台），
  自动键盘事件投不进未聚焦的游戏窗口，为避免误操作用户窗口，停止了 UI 自动化；
  只做到单测 + 选项通道真机确认。
- 确认框（退出确认/覆盖存档确认）的「屏幕文字」通道仍未真机验证（与上一版相同的缺口）。
- 未做人工听辨/ASR；只以日志与 SAPI 会话归因为证。
