# RE 工具链三路研究与 0.2.11 落地结论

状态：2026-11-15；对应用户 08:24「RE 工具栈增补」工作指令。
版本纪律：用户 2026-11-14 邮件要求统一 0.2.x，因此暂不升 0.3.x，已回信询问。

## 一、这次要回答的三个问题

1. 四件套（Il2CppDumper / pyghidra / Frida / dnSpyEx）能不能在本机跑起来、许可证能不能随产品发？
2. IL2CPP 游戏没有 interop 时，能不能自动补上 dump.cs，少一步人工？
3. IL2CPP 能不能像 Unity Mono 一样，在钩子没有字符串参数时“读实例字段兜底朗读”？

---

## 二、结论（先说人话）

- **Il2CppDumper 能自动跑，而且已经做进产品了**：0.2.11 起，`forge analyze` 遇到既没有 interop 也没有 dump.cs 的 IL2CPP 游戏，会自己调用 Il2CppDumper 生成 dump.cs，再继续分析。本机 SiliconHeart 实测 20 秒出 17.4MB 的 dump.cs、40 个候选，游戏目录一个字节没改。
- **pyghidra 能用**，但它是“高级分析工具”，适合放进高级选项，不适合每次分析都跑。
- **Frida 能附加、能枚举**，但只适合开发机研究，不进产品运行时（体积 23.6MB、要注入、Windows 不是官方测试平台）。
- **dnSpyEx 是 GPLv3**，只能本机手动用，不随产品分发。
- **IL2CPP 字段兜底“能做但要小心”**：反射路线（A）不可行，原生字段 API 路线（B/C）实测可编译；0.2.12 已在 Lilith 真机读到台词并产品化（见下方 2026-11-15 更新）。

## 三、证据与细节

### 3.1 Il2CppDumper（task-56）

- 版本 6.7.46，MIT 许可。
- 只读副本 SiliconHeart → dump.cs 18,195,590 字节 / 530,195 行 / 9,301 类；script.json 93,338 条方法 / 17,745 条字符串字面量；metadata v29。
- 两个必须记住的坑：
  1. 该版本目标 .NET 6，本机只有 .NET 8 → 必须设 `DOTNET_ROLL_FORWARD=LatestMajor`，否则起不来。
  2. 结尾 `Console.ReadKey()` 在重定向 stdin 时会抛异常，退出码变成 `-532462766`，但产物是完整的 → **成功判定必须看产物，不能看退出码**。
- 复现脚本：`tools/re/run_il2cppdumper.ps1`。

### 3.2 pyghidra（task-56）

- 3.2.0，Apache-2.0，与本机 Ghidra 12.1.4 兼容。
- headless 导入 262 个函数、全量分析 385 个函数、反编译 `FUN_140001008` 成功。

### 3.3 Frida + frida-il2cpp-bridge（task-58）

- frida 17.12.0 / frida-tools 14.9.0 / frida-il2cpp-bridge 0.14.0（MIT）。
- SiliconHeart（Unity 2021.3.15f1c1）attach 2 次成功：4 秒枚举 64 程序集 / 13,595 类 / 291 个 Text/TMP 候选类名，只读读出 10 条静态字符串。
- 游戏全程存活；启动前后游戏目录 436 文件逐字节 0 变更。
- 动态拿到 `RevealableUIText.set_Text` RVA `0x9B6DA0`，与静态研究 `research/20` 的值一致（双源校验成立）。
- 结论：研究/开发期验证可用；不随产品（gadget 23.6MB、需注入、Windows 未官方测试、RVA 会随版本漂移）。许可证 MIT/wxWindows 3.1 本身不阻碍分发。

### 3.4 IL2CPP 字段兜底可行性（task-57）

- 路线 A（Il2CppInterop 反射读实例字段）**不可行**：三套 interop 程序集实测只有 `static NativeFieldInfoPtr_*`，`GetField` 恒 null。
- 路线 B/C **可编译**：`il2cpp_object_get_class` + `il2cpp_class_get_field_from_name` + `il2cpp_field_get_value_object`；生成代码不需要写死偏移（TMP_Text.m_text 在 manosaba 是 0xE0、Lilith 是 0xD8）。
- 字段定位示例：manosaba `RevealableTextPrinterPanel.revealableText` 0x150 → `RevealableText.text` 0x838；Lilith `DialogueBubbleUI._dialogueText` 0x28、`DialogueNode.text` 0x38。
- **未验证**：没有在运行中的游戏里真的读到台词；AOT 泛型遍历、async 时序、struct 形参注入都未实测；只验了 2/5 款样本。

## 四、0.2.11 产品落地

### 4.1 自动 dump（已做，真机验证）

- `Il2CppOptions` 新增 `autoDump`（默认开）、`dumperPath`。
- `Il2CppAutoDumper`：校验输入 → 找 dumper（显式路径 / `re.il2cppdumper.path` / 工作区 / 程序旁）→ 输出到 `<工作区>/games/<slug>/il2cpp-dump` → 10 分钟超时 → 按 dump.cs 存在且 ≥100KB 判成功。
- `Il2CppAdapter.AnalyzeAsync`：无 interop、无 dump 时先自动 dump；成功则继续分析并在 unverified 里注明“自动产物未人工核对”；失败则返回带 details 的 `E_DEPENDENCY_MISSING`（三条路：interop / 人工 dump / 指定 dumper）。
- 真机：SiliconHeart 只读目录 → 20.0s 生成 17.4MB dump.cs → 40 个候选，`ok=true`；游戏目录未改。

### 4.2 forge tools（已做）

- `forge tools [--json] [--workspace] [--option re.<id>.path=...]` 检查 5 件工具的“能不能找到 + 版本 + 许可证 + 放置提示”。
- 默认不会去下载 GPL/动态工具，只给下载地址与放置位置。

### 4.3 没做的（诚实标注）

- IL2CPP 字段兜底：0.2.11 只出方案与编译验证；0.2.12 已产品化（Lilith 真机 `[Speech:fields]`/`[a11y-speech]` 读到台词，见 docs/50 §7 与 docs/54）。
- pyghidra 产品化：只作为 `--advanced` 的可选项，不默认跑。
- Frida：只留在研究目录，不进产品。
- dnSpyEx：只写文档，不随包。
