# 发布说明 v0.2.44（读屏结果播报：焦点兜底）

> ⚠️ 本版发布包已被 **0.2.45** 取代（同一小时内又抓到三处 Ren'Py 真机问题）；`releases/v0.2.44` 目录已删除，请以 `releases/v0.2.45` 与 `docs/93` 为准。本页保留为当时的记录。


## 1. 一句话

执行完命令后，GUI 会把焦点放到「结果区」，读屏（NVDA）能直接念出结果；不再依赖 UIA 通知（实测在 NVDA 上不可靠）。

## 2. 背景（为什么做）

0.2.20 起 GUI 有执行结果区，0.2.21 起 `Announcer` 用 WinForms 的 UIA 通知（`RaiseAutomationNotification`）播报「执行完成」。本轮做自动验证时发现：

- 发布包 GUI 执行「环境自检」后，结果区内容正确（`【环境自检】成功` 等），
- 但 NVDA 朗读查看器里**没有出现这条播报**；
- 单独写的探测程序也复现：WinForms 标签的 UIA 通知不会被 NVDA 念出（同一探测程序里，控件获得焦点时的名称会被念）。

结论：UIA 通知不能作为唯一播报通道。这是读屏用户「操作完不知道结果」的真实风险。

## 3. 改动

- `src/Forge.Gui/MainForm.Commands.cs` 的 `PresentOutcome`：
  - 保留 `Announce(headline)`（UIA 通知通道，Narrator 等仍可用）；
  - 执行完成后（无论成功/失败）把焦点移到结果区：`_resultBox.Focus()`，并把光标置到开头；
  - 失败时原本就聚焦结果区，现在成功也一致。
- `src/Forge.Gui/Announcer.cs` 不变（仍保留 UIA 通知，作为兼容通道）。

## 4. 验证情况（诚实）

- ✅ 机器可读：GUI 控件树、Alt 快捷键、结果区内容、焦点落点，均可用 Win32/UIA 取证（`research/84-gui-nvda-live/`）。
- ⚠️ **NVDA 实际播报未在自动化环境里取证成功**：自动化用 `BM_CLICK` 驱动后台窗口时，NVDA 朗读查看器没有记录到结果区内容；原因是窗口未真正前台/焦点事件不可靠。已记录证据与判断过程，见 `research/84-gui-nvda-live/README.md`。
- 建议人工复验：打开 GUI → 选游戏目录 → 按 Alt+V（环境自检）→ NVDA 应念出结果区「【环境自检】成功 …」。
