## 0. 一句话结论

"全自动生成器"这个位置目前是空的：市面上要么是**手工做单作补丁**（用户本人六作、boz 的 Aokana），要么是**通用 OCR/翻译外挂**（NVDA + LunaTranslator，门槛极高）。我们手里有别人没有的三样东西——可复用的三层 Framework、10 作实战踩坑、本机 21 款游戏的实测矩阵——足以把"人工流程"变成"确定性流水线"。

## 2. 九条关键发现

### 2.1 用户侧资产：可复用，但只覆盖 Unity 空骨架（R1）

- 可**逐字节复用**：7 个 L1 文件（只改 namespace）+ `Speech.cs`（整份拷贝，改 `Plugin.`→`A11yHost.`）+ A11yHost 填空 + 16 个模板/4 个构建脚本。
- 硬约束：**UiNav 不得接进新作**（依赖每作 UI 结构）；**非 Unity 路线 C# 一行都用不上**。
- `new_game.py` 现状：能渲染 39 个文件、exit 0，但**全树 46 处 TODO（22 处在 4 个 .cs）**，只生成 Unity 空骨架；krkrz/renpy 直接 exit 2。
- 差距五件事：① 入口与引擎自发现（22 个游戏 18 命中、4 漏判；NEEDY 把 `UnityCrashHandler64.exe` 当入口，真入口是 `Windose.exe`）② 证据→补丁点 ③ 文本 profile + 离线验证 ④ 构建/部署/自检闭环 ⑤ 版本 pin 与一致性（10 作里只有 MeiKong 的 L1 与当前 Framework 10/10 一致；Framework 有 3 个 tag、2 个 Release、0 个 release asset）。
- 结论：**不是从零写，而是把"半自动骨架 + 人工补点"升级为"自动发现 + 打分 + 运行期自检 + 生成缺口报告"**。

### 2.2 "最强王者"生态：可见度 ≠ 可复用能力（R2）

- 硬数据纠正任务卡前提：`Accessibility-mod-template` 作者是 **HappyStarfish**（CC BY 4.0，15★），`prism` 作者是 **ethindp**（MPL-2.0，67★）；boz 对二者全历史 0 实质提交。
- boz 的 60 仓 = 49 fork + 11 自有；自有作品只有 Aokana（3★/4 下载）、GalMasterAccess（1★/1）、HuXiang（0★）；唯一上游硬通货是 **tolk 125 个提交**。
- "更受欢迎"在数据上不成立：用户侧 6 作、GitHub 单版本下载 72+、nvdacn 社区反馈都更高；boz 的可见度来自 fork 策展 + 被误归功的模板/prism。
- Aokana 值得学的：单作可以做很深（14 快捷键、4 语自动检测、CI 出 zip、3 步安装、诚实记录缺口）；但它**没有跨作复用**，每个新作仍靠手写 Handler——正是生成器要补的自动化段。
- 可合法复用：template 规则文字（CC BY，需署名 Happy Starfish）、prism 的能力位/优先级思想（MPL，不引 C++）、tolk（LGPL 动态依赖）、GalMaster/HuXiang（MIT）。**Aokana 无 LICENSE=只读**。

### 2.3 本机 21 款游戏：13 款已装补丁，2 款干净 P0 样本（R3）

- 实测 25 个 acf = 21 游戏 + 3 原声 + 1 运行库；`libraryfolders.vdf` 漏列 5 个已装 app（只按 VDF 枚举会漏）。
- **13/21 已装无障碍补丁**（Unity Mono 6、IL2CPP 3、双引擎 1、Ren'Py 1、NW.js 1、KiriKiri 1），可直接当回归基准。
- 干净首验 P0：`3030980 五天一夜`（Unity Mono 6000.0.49f1，0.55GB/211 文件）、`3012630 硅心`（IL2CPP 2021.3.15f1 + Naninovel，0.67GB/436 文件）。
- P1：`3942480 nonand2`（IL2CPP 与已跑通的 2873080 同版本）、`1451940 NEEDY`（Mono）、`4513880 GalMaster`（大 AssetBundles 压力样本）、`698780 DDLC`（Ren'Py 6.99）、`3715730 mei`（Ren'Py 8.5.2）、`5184600 LoveNest`（NW.js）。
- 引擎分布：Unity Mono 9 / IL2CPP 5 / Ren'Py 3 / KiriKiri 1 / RPG Maker 1 / NW.js 1 / 自有引擎 1。
- **KiriKiri 只有千恋 1 部，且正在 0.2.0.1 收尾 → 没有干净基线**；这是唯一建议买第二部（Riddle Joker ¥88）的理由。可选买《钟塔》¥18（工作区已有 belfry_a11y，可验证"补丁对游戏更新失效"）；免费 Demo 4169180 可先下。

### 2.4 引擎：19 类分级，A 级 3 类可全自动（R4）

- **A 级（可全自动）**：Unity Mono、Ren'Py、RPG Maker MV/MZ。
- **B 级（自动 + 一次人工确认）**：Unity IL2CPP、KiriKiri Z、WebGAL。
- **C 级（仅自动识别）**：其余 13 类（Godot、KK2、RPG Maker XP/VX/Ace、NekoNovel 等）。
- Unity Mono：静态分析能拿"谁在 set_text / 文本字段持有者 / 已知对话框架痕迹 / CJK 字面量方法"，**拿不到台词/选项/菜单的语义**；已给打分规则（S1–S8 正分、N1–N4 负分、70/50/30 阈值、8 项运行期确认）。
- IL2CPP：先装 BepInEx 6 跑一次游戏生成 interop（manosaba 实测 157 dll/88MB），之后可扫；Hook 受 TryCast/委托约束。
- Ren'Py：**零归档改动**（.rpy 叠加 + say filter + tts）；mei 自带 `00accessibility.rpy`，要注意别双朗读。
- KiriKiri（R4b 核验）：`setGameA11y/a11yLayers/announce` 是官方内建，但**仅 krkrz v2.5.0（2026-10-06）起**；本机千恋 1.2.0.3 没有 → 老作品仍走注入；免改 data.xp3 的 `plugin/*.tpm` 自动加载是候选但未实测；适配器按版本分流（新作启用、老作注入，manifest 回滚）。
- RPG Maker MV/MZ：给 JS 插件与精确行号，但**本机无样本**（To the Moon 的 mkxp 是 XP，不是 MV/MZ），属于"有方案未实测"。

### 2.5 工具链：不自研 hook，许可证是硬约束（R5）

- 通用文本捕获不自研：非 Unity 用外置 TextractorCLI（GPL-3.0，UTF-16LE 管道、退出码恒 0）——只能"用户自装"，不可随包；Unity 用我们生成的 BepInEx 插件。
- 可无人值守的分析工具：ilspycmd、Il2CppDumper（MIT，2024-07 停更）、UnityPy、Ghidra headless。AssetRipper（GPL/无 CLI）、AssetStudio（已归档）、Cpp2IL（仅 pre-release）不进主链。
- BepInEx 6 be.788 不在 GitHub releases 列表（tags 只到 v6.0.0-pre.2），URL 可能失效 → 产品内置缓存 + sha256；BepInEx 5.4.23.5 有公开 zip。
- 随包只放 MIT/Apache/BSD + 未修改 LGPL；Tolk 上游混入专有 SAAPI64/dolapi32、ZDSR 闭源 → 只"检测本机已有则调用"，不重分发。
- 新工程建议 .NET 8 核心（自包含 exe，无 Python 硬依赖）+ 可选 Python sidecar（UnityPy）；不用 PyQt6（GPL/商业双许可）。

### 2.6 语音与界面：WinForms/WPF 可读屏，Avalonia/TUI 不可（R6 实测）

- 本机四段语音链全部握手成功：Tolk 自动检测到 NVDA（中文 1.4ms）；NVDA 直连 1.3ms；ZDSR 状态查询 0.14ms；SAPI 有中文 Huihui/英文 Zira 两个音色；Tolk 还检测到盲文通道（hasBraille=1，无硬件未验证输出）。
- SAPI 的坑：同步读 68 字阻塞 17.67 秒、PURGE 打断要等 2.6 秒；中文音色读日语出 3.1 秒"不是日语"的声音，英文音色读日语直接 0 秒空输出。**本机没有任何日语语音**，唯一离线日语合成是 NVDA 自带 eSpeak NG（GPL-3.0，不可随包）。
- 界面四栈实测（UIA 能否暴露 + 焦点扫描）：**WinForms UIA 树完整、12 项焦点可读；WPF 完整且 AutomationId 规整（但标题栏菜单抢焦点）；TUI 无 UIA；Avalonia 11 未取得可靠 UIA 树** → 主界面选 WinForms，WPF 备选。
- 产品默认后端顺序：Tolk → NVDA 直连 → ZDSR → SAPI 兜底 → 静默+诊断日志；切换时念出跳过的后端。
- 阅读规则（L1 Repeat 实证）：选项进重读缓冲；有配音行整句进缓冲但只报角色名；快进/自动模式丢弃中间句而非排队。

### 2.7 中文社区：需求真实但受众极小，六类打回原因（R7）

- 2026 年中文 Gal 无障碍是"两条腿"：官方内建读屏（《想成为Galgame领域大神！！！》Steam 公告被 17173 转载）+ 独立补丁（用户六作）。
- 受众极小：作者 B 站粉丝 2、相关视频播放 350/181、GitHub 单版本下载 1–3；但教学类视频 6500 播放 → 需求在、转化不在。
- 盲人现实主流方案是 NVDA 懒人包 + LunaTranslator + OCR + edgeTTS，门槛极高、每环更新即失效——这正是补丁的价值空间。
- 六类负面反馈：① 安装（杀软误报/SmartScreen/解压层级）② 补丁冲突（解锁/修正补丁）③ 游戏更新失效 ④ 漏读/重复读 ⑤ 图标控件无文本 ⑥ 朗读延迟（"点下去等 5 秒"）。
- 需求分层 7 必须有 / 7 最好有 / 6 锦上添花；15 条风险表（`research/07-cn-community/evidence/risks.csv`）可直接当验收项。
- 渠道：nvdacn 是唯一活跃阵地；Steam 讨论区 0 条无障碍帖 = 空位。

### 2.8 国际标准：30 条验收可直接当规格（R8）

- 双通道范式（Ren'Py 8.6 经 Prism 直连 NVDA/JAWS/VoiceOver/Orca + 盲文、启动自动检测、无读屏回退 TTS）值得照抄。
- XAG 106 是现成叙事规范：顺序 name→role→value→index、焦点到达即读、四类触发时机、可打断可重播、线性菜单循环。
- 30 条可测验收（P0 12/P1 12/P2 6，`evidence/acceptance-criteria.csv`），含判定方法与自动/半自动/人工，可直接映射到第二波测试。
- 竞品：Aokana 功能最全但**无许可**；KSRE（MPL-2.0）工程最稳；DDLC+ mod 以剪贴板为主通道是反模式。五个反模式 + 首次使用脚本已给。
- 有原帖实测的坑：逐行/逐字刷新致截断乱读、读过即失无法回听、焦点被抢、符号 `***`/`⁂` 被静音或念码点。

### 2.9 竞品空白：没人做"全自动生成器"

现有形态对照：手工单作补丁（用户/boz）→ 单作做深但每作重写；通用 OCR 外挂（LunaTranslator）→ 通用但门槛极高；官方内建（少数商业作）→ 只覆盖新作。**没有"输入游戏目录→输出可用补丁+自检报告"的产品**。这就是 GalA11y Forge 的位置。

## 3. 产品机会与差异化

1. **一键化**：识别 → 分析 → 生成 → 构建 → 部署 → 自检，五步内完成。
2. **确定性**：同样的游戏版本得到同样的补丁（版本 pin + profile 指纹），不靠"AI 现场发挥"。
3. **诚实**：机器做不到的（语义、别名、听感）产出"人工待办清单"，不假装成功。
4. **中文优先 + 国产读屏矩阵**：NVDA/争渡/Windows 讲述人/SAPI 全覆盖，日语资源单独处理。
5. **干净**：许可证合规、可卸载回滚、不碰游戏资源、不引 GPL 进主链。

## 5. 对第二波的含义

- 先做**核心骨架**（discover/probe/plan/render/build/verify）+ **Unity Mono 适配器**，用 P0 `3030980` 端到端跑通，再扩 Ren'Py（零归档，风险低）、IL2CPP。
- 测试不是"跑通就行"：R8 的 30 条验收 + R7 的 15 条风险 + R3 的 13 个已装补丁回归，一起构成验收矩阵。
- 图形界面按 R6 结论用 WinForms，先做"向导 + 日志面板 + 自检报告"，不追求好看。
