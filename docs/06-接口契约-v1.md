# GalA11y Forge 接口契约 v1

面向：适配器作者、GUI/CLI 集成者。  
状态：W2-A 骨架（v0.1.0.0）。**引擎命令当前只返回 `E_NOT_IMPLEMENTED`，不得据此宣称可运行。**

## 1. 命名与目录

- 命名空间：`GalA11yForge.Core.*`；适配器建议 `GalA11yForge.Adapters.<Engine>.*`。
- 引擎 id：小写 snake_case。已知：`unity_mono`、`unity_il2cpp`、`renpy`、`kirikiriz`、`rpgmaker_mv_mz`。
- 适配器名：小写 slug（如 `unity-mono`），全注册表唯一（忽略大小写）。
- 工作区默认 `%LOCALAPPDATA%\GalA11yForge`，可用 `--workspace` 覆盖。
- 子目录：`games/<slug>/`、`work/<id>/`、`backup/`、`reports/`、`logs/`、`adapters/`。
- 每个游戏：`profile.json`、`overrides.json`、`00-detect` … `06-verify`、`logs/`。
- 适配器注册表：`<workspace>/adapters/adapter.json`（兼容 `payload/adapters/adapter.json`）。

## 2. 七步接口（全部返回 `ForgeResult<T>`）

```csharp
Task<ForgeResult<EngineDetection>> DetectAsync(GameContext, CancellationToken = default);
Task<ForgeResult<AnalysisReport>>   AnalyzeAsync(GameContext, EngineDetection, CancellationToken = default);
Task<ForgeResult<PatchPlan>>        PlanAsync(GameContext, AnalysisReport, CancellationToken = default);
Task<ForgeResult<GenerationResult>> GenerateAsync(GameContext, PatchPlan, string outputDirectory, CancellationToken = default);
Task<ForgeResult<BuildResult>>      BuildAsync(GameContext, GenerationResult, CancellationToken = default);
Task<ForgeResult<DeployResult>>     DeployAsync(GameContext, BuildResult, CancellationToken = default);
Task<ForgeResult<DeployRollbackResult>> RollbackAsync(GameContext, DeployManifest, CancellationToken = default);
Task<ForgeResult<VerificationReport>>   VerifyAsync(GameContext, DeployResult?, CancellationToken = default);
```

高级后端与万能层占位：

```csharp
string BackendId { get; }
Task<ForgeResult<BackendAnalysisResult>> AnalyzeAsync(AnalyzerBackendRequest, CancellationToken = default);
Task<ForgeResult<UniversalCaptureResult>> CaptureAsync(UniversalCaptureRequest, CancellationToken = default);
```

`GameContext` 提供 `GameDirectory`、`Slug`、`WorkspaceRoot`、`Profile`、`Advanced`、`DryRun`。
适配器不得读全局状态；写盘路径必须落在 `WorkspaceRoot` 内。

## 3. 数据形状

### 3.1 识别

```json
{
  "schemaVersion": 1,
  "family": "unity_mono",
  "version": "2021.3.16f1",
  "bitness": 64,
  "confidence": 0.86,
  "evidence": ["file:Game_Data/Managed/Assembly-CSharp.dll", "file:Game_Data/globalgamemanagers"]
}
```

`confidence` 为 0..1；`bitness` 为 32/64，0 表示未知。无证据就降低置信度并写入未验证项，禁止猜成高置信度。

### 3.2 文本候选

```json
{
  "id": "tc-001",
  "kind": "dialogue",
  "source": "assembly:Assembly-CSharp.dll!/DialogueManager::ShowText",
  "score": 82,
  "evidence": ["method signature (string, string)"]
}
```

`kind`：`dialogue` / `choice` / `menu` / `native_api` / `unknown`；`score` 为 0..100。

原生代码候选（Ghidra 后端）写 `kind=native_api`，`source` 仍用前缀便于外部解析，例如
`native-api:ghidra!0x0041A2F0 FUN_0041A2F0`（地址为 Ghidra 中的原始地址，函数名为分析后的符号）。
该成员在 0.2.4 开发版加入 `TextCandidateKind`；旧消费者遇到未知枚值应按 `unknown` 处理，见 docs/21。

### 3.3 分析报告

```json
{
  "schemaVersion": 1,
  "gamePath": "D:\\Games\\Sample",
  "detection": { "family": "unity_mono", "bitness": 64, "confidence": 0.86, "evidence": [] },
  "candidates": [],
  "coverage": {
    "covered": ["Mono 运行时识别"],
    "notCovered": ["选择支 UI", "存读档菜单"],
    "manualTodo": ["确认 ChoiceManager 是否被实际调用"]
  },
  "risks": [],
  "unverified": ["未在真机运行验证朗读顺序"]
}
```

### 3.4 补丁方案

关键字段：`route`（`automatic` / `automatic_with_confirmation` / `semi_automatic` / `unsupported`）、
`target`（`gamePath` / `engine` / `engineVersion` / `bitness`）、`confidence`、
`patchPoints[]`、`artifacts[]`、`risks[]`、`manualTodo[]`。
补丁点含 `id`、`kind`（`hook` / `config` / `script` / `asset` / `injection` / `other`）、`target`、
`candidateId`、`confidence`、`description`。
机器搞不定的地方写进 `manualTodo`（含 `blocking`），不要用空列表假装完成。

### 3.5 报告

`ReportDocument` 必须带 `coverage` 与 `unverified`；Markdown 固定含 **「## 覆盖声明」** 与 **「## 未验证项」**。
空分类写「（无）」；空未验证写「（无显式未验证项；这不等于全部已验证）」。

### 3.6 Ghidra 高级分析产物（`analysis-ghidra.json`）

`analyze --advanced` 会额外写 `01-analyze/analysis-ghidra.json`，结构如下（只列关键字段）：

```json
{
  "schemaVersion": 1,
  "backend": "ghidra",
  "status": "completed",
  "available": true,
  "engineFamily": "unknown",
  "executablePath": "…\\SenrenBanka.exe",
  "executableSha256": "601b10fa…",
  "executableSizeBytes": 4583168,
  "ghidraVersion": "12.1.4",
  "elapsedSeconds": 148.4,
  "commandLine": "cmd.exe … analyzeHeadless.bat …",
  "candidatesJsonPath": "…\\work\\ghidra\\ghidra-…\\out\\candidates.json",
  "stdoutPath": "…\\stdout.log",
  "stderrPath": "…\\stderr.log",
  "script": { "schema": "gala11y.ghidra.candidates/1", "binary": {}, "candidates": [] },
  "candidates": [],
  "coverage": { "covered": [], "notCovered": [], "manualTodo": [] },
  "unverified": [],
  "risks": [],
  "errorCode": null
}
```

- `status` 取值：`completed` / `not_available` / `disabled` / `no_target` / `timeout` /
  `canceled` / `start_failed` / `non_zero_exit` / `invalid_output`。
- `script` 是 Ghidra 脚本的原始 JSON（schema 见 research/10-ghidra-re），原样嵌入便于追溯。
- `available:false` 且 `status:"not_available"` 时表示本机没找到 Ghidra；此时**不是**失败，
  `analyze` 仍成功退出，但必须把“未启用高级分析”写进 `unverified`。

## 4. profile.json 与 overrides.json

1. 同目录先读 `profile.json`，再读 `overrides.json`。
2. 标量：`overrides` 非空则覆盖；`null` 表示继承。
3. `keymap`：按键合并。
4. `options`：顶层键合并；两边都是对象则递归合并；数组/标量整体替换。
5. 不改输入对象；不写回源文件。
6. `schemaVersion` 必须为 1；`minConfidence` 必须在 0..1；`engine` 必须是合法引擎 id。
7. 配置损坏返回 `E_PROFILE_INVALID`，不得静默忽略。

```json
{
  "schemaVersion": 1,
  "slug": "sample-game",
  "gamePath": "D:\\Games\\Sample",
  "engine": "unity_mono",
  "minConfidence": 0.5,
  "advanced": false,
  "universalCapture": false,
  "voice": "sapi",
  "keymap": { "speak": "Ctrl" },
  "options": { "unityMono": { "hook": "DialogueManager" } }
}
```

## 5. 适配器注册表

```json
{
  "schemaVersion": 1,
  "adapters": [
    {
      "name": "unity-mono",
      "engine": "unity_mono",
      "priority": 100,
      "assembly": "Forge.Adapters.UnityMono.dll",
      "type": "GalA11yForge.Adapters.UnityMono.UnityMonoAdapter",
      "capabilities": ["detect", "analyze", "plan", "generate", "verify"]
    }
  ]
}
```

`priority` 越小越优先；`assembly` 必须是适配器目录内的相对路径；`capabilities` 非空。
已知能力值：`detect`、`analyze`、`plan`、`generate`、`build`、`deploy`、`verify`、`universal`、`analyzer_backend`。
注册表校验失败返回 `E_ADAPTER_INVALID`；找不到引擎适配器返回 `E_ADAPTER_NOT_FOUND`。

## 6. 错误码与 CLI 退出码

| 错误码 | 含义 | 退出码 |
|---|---|---:|
| `E_ARG_INVALID` | 参数非法 | 2 |
| `E_PATH_UNSAFE` | 路径逃逸/非法相对路径 | 2 |
| `E_GAME_WRITE_DENIED` | 试图写游戏目录 | 2 |
| `E_PROFILE_INVALID` | profile/overrides 损坏 | 2 |
| `E_DEPENDENCY_MISSING` | 缺依赖/后端/适配器 | 3 |
| `E_NOT_IMPLEMENTED` | 明确未实现 | 3 |
| `E_ADAPTER_NOT_FOUND` | 无匹配适配器 | 3 |
| `E_ADAPTER_INVALID` | 注册表/程序集非法 | 3 |
| `E_IO` | 读写失败 | 3 |
| `E_ENGINE_UNSUPPORTED` | 引擎不支持（D 路线） | 4 |
| `E_PARTIAL` | 部分成功 | 5 |
| `E_ARTIFACT_MISSING` | 生成物/备份缺失 | 5 |
| `E_ARTIFACT_INVALID` | 生成物/清单非法 | 5 |
| `E_INTERNAL` | 内部错误 | 1 |

CLI：`forge detect|analyze|plan|generate|build|install|verify|report|doctor`。
参数：`--game --out --json --dry-run --verbose --advanced --workspace --bepinex --option --rollback --force`。
`--option key=value`（可重复）覆盖 `profile.options` 的运行时选项（如 `il2cpp.dumpPath`、`ghidra.path`），不落盘。
成功 0；参数错误 2；依赖缺失/未实现 3；引擎不支持 4；部分成功 5。
**未实现时输出 `ok:false` + `E_NOT_IMPLEMENTED`，绝不假成功。**

### 6.1 `analyze --advanced` 与 Ghidra 后端

`--advanced` 时 `analyze` 额外调用 `Forge.Analyzers.Ghidra`（BYO Ghidra，不随包）；`plan`/`generate` 等命令
**不会**触发 Ghidra（避免每次多花 2–4 分钟）。Ghidra 相关选项（均写入 `profile.options`，可用 `--option` 覆盖）：

| 键 | 默认 | 说明 |
|---|---:|---|
| `ghidra.path` | 自动探测 | Ghidra 安装目录（含 `support\analyzeHeadless.bat`），优先级最高 |
| `ghidra.enabled` | `true` | `false` 时跳过并写 unverified |
| `ghidra.timeoutSeconds` | `600` | 子进程墙钟超时，超时杀进程树并清理临时工程 |
| `ghidra.analysisTimeoutSeconds` | `900` | 传给 `-analysisTimeoutPerFile` |
| `ghidra.maxCpu` | `4` | 传给 `-max-cpu` |
| `ghidra.maxMem` | 空 | 设置 `GHIDRA_HEADLESS_MAXMEM`，如 `4G` |
| `ghidra.keepProject` | `false` | 保留 Ghidra 工程目录用于排查 |

退出码语义：
- 未找到 Ghidra / `ghidra.enabled=false`：`ok:true`、退出 0，`data.ghidra.available=false` +
  `unverified` 说明；人类输出为「未启用高级分析（未找到 Ghidra）」。
- 有适配器（Unity Mono / IL2CPP）时 Ghidra 超时/崩溃：适配器结果仍有效，`ok:true` + stderr 警告。
- 无适配器（如 KiriKiri Z）时 Ghidra 超时/崩溃：`ok:false`、`E_PARTIAL`、退出 5。
- Ghidra 完成但 0 候选 / 疑似加壳：`ok:true`、退出 0，但 `unverified` 必须写明“0 候选不等于没有文本”。
- `doctor` 的 ghidra 检查是**可选**项（`optional:true`），未安装不影响 `doctor` 成功。

## 7. 写盘约束（硬性）

- 所有生成物只写工作区内；游戏目录只读（部署动作必须显式备份并记账）。
- 相对路径拒绝：绝对路径、盘符、`..`、`.`、`:` `*` `?` `"` `<` `>` `|`、段尾空格或点。
- 工作区本身不得位于游戏目录内。
- 备份必须位于 `backup/`；回滚按 manifest 逆序执行，先恢复 `Replace/Remove`，再删除 `Add`。
- 日志：`reports/flow.jsonl`，每行一个 JSON 对象（`timestamp`/`level`/`stage`/`message`/`data`）。

## 8. 给适配器作者的一句话

先实现 `detect` 和 `analyze`，把证据、覆盖声明、未验证项写全；`plan` 之后才谈自动生成——
宁可返回 `E_ENGINE_UNSUPPORTED` 或 `manualTodo`，也不要返回一个没有证据的“成功”。
