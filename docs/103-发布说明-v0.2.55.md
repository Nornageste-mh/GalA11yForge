# 0.2.55 发布说明：实例文本字段算“能读”，不再被闸门挡住

## 一句话
《钟塔 Belfry》这类“自定义管理器 + 文本在实例字段”的 Unity 游戏，静态分析能找出字段，但以前被判成“没有正文入口”而拦住安装；本版把这类入口当作可读入口，装上就能靠兜底读出台词。

## 问题怎么发现的
用户反馈用《钟塔》测试“无法秒杀”。只读 analyze 找到 50 个候选，Top 是 DialogueSceneManager::UpdateDialogueInfo（100 分）等，证据里有“类型文本字段：dialogueText/characterNameText/…”，但 plan 报 noDialogueEntry=True → R-106 高风险 → install 闸门拒绝（除非加 --force）。描述还写着“无 string 参数时只能做调用计数”。

## 改了什么（Unity Mono 规划器）
- Describe：无 string 形参但有类型文本字段时，写“实例文本字段（…）：方法没有 string 形参，生成器会按实例字段兜底朗读”；
- BuildRisks：有类型文本字段的入口也算“已识别的正文入口”，不再加 R-106；
- 新增 ExtractTextFields 复用字段解析；单测 Plan_NoStringParameterButInstanceTextFields_IsTreatedAsReadable。

## 真机证据（《钟塔 Belfry》只读副本）
- 副本 191 文件，装 23 文件后启动→新游戏→约 90 秒。
- 日志 577 行：[Speech:watch] 兜底读到 184 条、[Speech] 184 条、[Speech:fields] 0 条、Hook 命中 0、异常 0。
- 台词例：「在梦里，总是会有十二声钟响…」「【 韩冬 】」「笨蛋……暑假才刚刚开始…」「不用，某人曾经对我说过『强扭的瓜不甜』…」。
- 回滚 verify --rollback --force → overall=pass_with_skips；副本已删。
- 诚实边界：这个游戏静态挑的钩子运行期一个都没命中，真正读出台词的是 0.2.51 的文本兜底轮询；标题/主菜单自绘文字仍读不到；New Text 占位会被念；未做人工听辨（本机 Tolk 缺失）。
