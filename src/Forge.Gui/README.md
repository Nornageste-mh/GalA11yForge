# Forge.Gui — 读屏友好的 Gal 无障碍辅助 Demo 快速生成工具界面

这是 Gal 无障碍辅助 Demo 快速生成工具的图形界面（WinForms，.NET 8；Vibe Coding 产物，代码不保证稳定和可用）。它本身不干活，只做三件事：
**收集路径 → 调 `forge.exe` → 把结果讲清楚**。

适合不想背命令行、或者用屏幕阅读器/键盘操作电脑的用户。

---

## 1. 怎么启动

```powershell
# 1) 先构建（在仓库根目录 D:\DSHWorkSpace）
D:\dotnet\dotnet.exe build src\Forge.Gui\Forge.Gui.csproj -c Release

# 2) 启动
.\src\Forge.Gui\bin\Release\net8.0-windows\Forge.Gui.exe
```

可选启动参数（都有对应输入框，不写也行）：

| 参数 | 含义 |
|---|---|
| `--game <目录>` | 预填游戏目录 |
| `--workspace <目录>` | 预填工作区 |
| `--forge <forge.exe>` | 预填命令行工具路径 |
| `--dry-run` | 启动时勾上「演练模式」 |

界面找 `forge.exe` 的顺序（前一个找不到才看下一个）：

1. 界面上「forge.exe」输入框里填的路径；
2. 环境变量 `FORGE_EXE`；
3. 和 GUI 放在同一个目录里的 `forge.exe`；
4. 从 GUI 所在目录往上最多 8 层，找 `src\Forge.Cli\bin\Release\net8.0\forge.exe`（再找 `Debug`）；
5. 从当前工作目录往上找同样的相对路径；
6. 系统 `PATH`。

找不到不会崩，只是所有按钮变灰，并提示你去「forge.exe(&4)」里指定。

## 2. 键盘操作

界面只有三块：**① 输入 → ② 操作 → ③ 结果**，Tab 顺序就是这个顺序。

### 2.1 跳转

| 按键 | 作用 |
|---|---|
| `Tab` / `Shift+Tab` | 按视觉顺序移动焦点 |
| `Alt+1` | 跳到「游戏目录」输入框 |
| `Alt+2` | 跳到「工作区」输入框 |
| `Alt+3` | 跳到「BepInEx 包」输入框 |
| `Alt+4` | 跳到「forge.exe」输入框 |
| `Alt+5` | 勾选/取消「演练模式」 |

### 2.2 执行

| 按键 | 作用 | 是否写游戏目录 |
|---|---|---|
| `Alt+D` | 识别引擎 | 不写 |
| `Alt+A` | 分析文本 | 不写 |
| `Alt+G` | 生成补丁工程 Demo | 不写 |
| `Alt+B` | 构建补丁 | 不写 |
| `Alt+O` | 一键：识别 → 分析 → 生成 → 构建 | 不写 |
| `Alt+I` | 安装补丁 | **写**（有确认框） |
| `Alt+Y` | 安装后自检 | 不写 |
| `Alt+V` | 环境自检（不需要游戏目录） | 不写 |
| `Alt+R` | 回滚补丁 | **写**（有确认框） |
| `Alt+X` / `Esc` | 停止当前命令 | — |
| `Alt+L` | 清空结果区（执行记录保留） | — |
| `F5` | 一键（不用按 Alt，从任何地方都能触发） | 不写 |

### 2.3 读结果

| 按键 | 作用 |
|---|---|
| `Ctrl+Shift+R` | 重新朗读「最近一次结果」+ 结果区开头 |
| `Ctrl+A` / `Ctrl+C` | 在结果区全选 / 复制 |
| `↑` `↓` / `回车` | 在执行记录列表里选择，回车把那次结果调回上方 |
| `Ctrl+L` | 清空结果区 |

命令执行期间：进度条滚动、所有操作按钮变灰（读屏会念出「当前不可用：原因」），
停止按钮保持可用；按 `Esc` 会连同 `forge.exe` 子进程一起结束。

## 3. 读屏预期

- 窗口是标准 WinForms 窗口，走 **UI Automation**：窗口 → 分组（输入区 / 操作区 / 状态区 / 结果区）
  → 文本框、按钮、复选框、列表、只读文本框。每个控件都有可朗读的名称，例如
  「游戏目录」「浏览游戏目录」「环境自检」「执行结果」「执行记录」。
- 名称来自 `Text` 或 `AccessibleName`；**AutomationId 全部为空**（WinForms 的既有行为），
  所以自动化脚本要靠名称定位，不要指望 id。
- 结果区是**只读多行文本框**，读屏可以用「编辑/文本」模式逐行读；失败时焦点会自动移到这里，
  读屏通常会立刻念出第一行结论（例如「【安装补丁】失败」）。
- 每完成一条命令，界面会通过 `RaiseAutomationNotification` 主动播报一句摘要
  （成功/失败 + 退出码）。**这条通道要 NVDA 2019+ / 讲述人才会被念出来**，
  没有装读屏时它什么也不做，不会报错。
- 进度条设置了 `TabStop=false`，Tab 不会停在它上面。
- 忙碌时输入框变为只读，避免边跑边改路径。

## 4. 结果区怎么读

每条结果的第一行永远是一句人话结论，下面是明细：

```
【环境自检】成功
命令：forge doctor --game D:\Games\xxx --workspace D:\_ws --json
退出码：0（成功）
耗时：1.0 秒
消息：环境检查通过。

数据：
  工作区：D:\_ws
  工具版本：0.1.0.0
  检查项（4 项）：
    通过　dotnet-runtime：当前运行时 8.0.11；要求 .NET 8 或更高。
    ...
```

失败时会多出三行，读屏按这三行就能说清问题：

```
错误码：E_ARG_INVALID
消息：游戏目录不存在：D:\Games\不存在的目录
建议：确认 --game 指向游戏安装目录（里面有 .exe）。
```

退出码含义（来自 CLI 的约定）：

| 码 | 含义 | 界面怎么处理 |
|---|---|---|
| 0 | 成功 | 正常显示；若同时 `ok=false` 也算失败 |
| 1 | 内部错误（工具缺陷，不是游戏问题） | 失败 |
| 2 | 参数错误（路径或选项不合法） | 失败 |
| 3 | 依赖或能力缺失（含「未实现」） | 失败 |
| 4 | 引擎不支持 | 失败 |
| 5 | 部分成功（有未完成项） | 按「部分成功」显示，不一刀切当成功 |

## 5. 已知限制

1. **没有用真实屏幕阅读器做过播报验收**：本机 UIA 树、控件名称、焦点顺序都已实测，
   但「NVDA / 讲述人 会不会念出 `RaiseAutomationNotification` 的播报」未实测。
2. 进度条是滚动条样式（Marquee），读屏只能听到「进度」两个字，听不到百分比——
   因为 CLI 不输出进度百分比，界面不编造。
3. 「一键」只做 **识别 → 分析 → 生成 → 构建**，**不包含安装**：安装会改游戏目录，
   必须单独按 `Alt+I` 并在确认框里选「是」。
4. 确认框是系统 `MessageBox`，默认按钮是「否」；它可被读屏朗读，但不是自定义无障碍对话框。
5. 「环境自检」不要求游戏目录，但界面仍会把已填的游戏目录传给 CLI（CLI 会忽略），
   属于无害的多余参数。
6. 执行记录最多保留 50 条，存在内存里，关掉窗口就没了。
7. 界面只做中文；没有英文/日文版本。
8. 没有做补丁工程的预览、日志浏览、差异查看——这些仍然要看工作区里的文件。
9. 停止是「杀整个进程树」，不支持「跑完这一步再停」。

## 6. 开发与测试

```powershell
D:\dotnet\dotnet.exe build src\Forge.Gui\Forge.Gui.csproj -c Release   # 0 警告 0 错误
D:\dotnet\dotnet.exe test  tests\Forge.Gui.Tests                        # 138 个测试
```

代码分工：

| 位置 | 职责 |
|---|---|
| `src/Forge.Gui.Core/` | 纯 .NET 8 逻辑（无 WinForms）：命令表、参数构建、JSON 信封解析、退出码映射、按钮状态机、结果排版、数据朗读、forge.exe 定位 |
| `src/Forge.Gui/` | 只有界面：布局、Tab 顺序、对话框、进程调用 |
| `tests/Forge.Gui.Tests/` | 上面两层的单元测试（xunit） |

**界面不改任何 CLI 内部行为**：它只拼参数、读最后一行的 JSON 信封。
CLI 的输出格式变了，只需要改 `Forge.Gui.Core` 里的解析与排版，界面代码不用动。

崩溃日志：`%TEMP%\GalA11yForge-gui-crash.log`（界面自身出错时写，不含游戏数据）。
